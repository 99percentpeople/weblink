# 桌面开发

`apps/desktop` 中的 Tauri 2 应用嵌入 `apps/web` 现有 SolidJS 应用。首个目标平台为 x64 Windows 10 22H2 / Windows 11，要求 WebView2 120 或更新版本。NSIS 安装器按需安装或更新 Evergreen WebView2 运行时。桌面应用已在 Windows 上手动运行并验证；安装器和各功能验收项见下文，Linux 编译则作为独立开发检查。当前 Linux 宿主可以启动外壳并执行 IPC，但其 WebKit 不提供 `RTCPeerConnection`，因此应用会显示既有的不支持浏览器页面。Linux WebRTC 支持仍是独立的平台任务。

Windows 本地 `tauri dev` 使用 `app_local_data_dir()/profiles/local-dev` 存放 WebView 数据。所有 `tauri build` 产物，包括 CI 开发构建和稳定版，都保留默认 WebView 目录。这样可将本地开发的 localStorage 设置、MCP 凭据、浏览器身份和 IndexedDB 与构建应用隔离，同时不按发布渠道拆分存储。区分依据是 Tauri 开发模式，而非 debug assertions。现有配置数据不会复制到本地开发配置中。

## 自动化与设备权限 {#automation-and-device-permissions}

Windows 桌面可提供 Streamable HTTP MCP 服务，并执行已授权的本地或远程自动化。**设置 → 自动化**将启用 MCP API 与允许工具操作本机分开管理。两个开关默认均关闭；控制端可以仅开放 MCP 转发，而不启用自身的本地输入或 Shell 访问。默认端点为 `http://127.0.0.1:32100/mcp`。

MCP 客户端使用本地签发的令牌认证。来自另一台 Weblink 设备的调用使用该设备的配对身份和权限组，请求通过共享通知流程审批。批准的对端访问持续到当前连接结束，保存的“始终允许/拒绝”策略则始终按设备区分。宿主紧急停止快捷键也会停止自动输入和命令。参见[自动化设置与工具契约](../reference/automation.md#quick-start)和[设备配对](../reference/device-trust.md)。

## 运行与构建 {#run-and-build}

安装 [Tauri 前置依赖](https://v2.tauri.app/start/prerequisites/)：Windows 需要 MSVC 14.44（Visual Studio 2022 17.14）或更新版本、Windows SDK 10.0.26100 或更新版本、Rust 和 WebView2。原生 WebRTC 在首次 Cargo 构建时下载预编译库；根 Cargo 配置选择该库要求的静态 MSVC 运行时。仓库通过 `rust-toolchain.toml` 固定 Rust，通过 `package.json` 固定 Bun。Cargo 还会从 [Weblink fork](https://github.com/99percentpeople/rust-sdks/tree/bf9999f9314ff677830ee342973f495d20a474ff) 获取修补后的 WebRTC 绑定，完整 Git 修订固定在根 `Cargo.toml` 和 `Cargo.lock` 中。该 fork 为私有仓库。本地 Windows x64 构建者需要 Git 读取权限及已认证的 GitHub CLI，以完成首次原生库下载。离线构建可将 `LK_WINDOWS_WEBRTC_ARCHIVE` 设为匹配的 SDK 发布 ZIP；SDK 解压前会验证 SHA-256。普通 Web 构建和 TypeScript 检查不会获取该 SDK。官方桌面 Actions 使用仓库 secret `NATIVE_SDK_READ_KEY`，这是仅对此 SDK 仓库有只读权限的 SSH deploy key。两个原生 crate 必须固定同一个完整提交。Action 通过 Git LFS 获取发布 ZIP，并在 Cargo 读取本地 checkout 前移除认证。轮换 deploy key 时需同时在 SDK 中替换密钥并更新该 secret。

原生 CI 仅用于官方 `public` 分支 push、手动构建及已验证的发布标签。PR 和 fork 仍运行不需 SDK 权限的 Web/TypeScript 检查。公开 Actions 缓存只包含 crates.io 索引和归档；不能缓存私有 Git 源码或原生构建输出，因为 fork PR 可以恢复基础分支缓存。不要上传 Cargo Git 目录、SDK checkout 或原生调试产物。移除原生构建缓存会增加桌面 CI 耗时。SDK 读取失败只导致桌面任务失败，Web 部署仍独立执行。

fork 使用 `main` 保存官方上游历史，`weblink-native-media` 保存已集成的 Weblink 变更。功能开发可在集成前固定已发布的功能提交。将完整 Weblink 补丁序列 rebase 到更新后的 `main`，确保我们的提交始终位于官方提交之后；用 `git range-diff` 验证补丁，验证后更新两个固定依赖文件。初始化 Git 子模块后，在仓库根目录运行：

```sh
bun install
cp .env.example .env
bun run dev:desktop
```

`dev:desktop` 启动本地 Bun 信令服务和 Tauri。Tauri 启动自己的 Vite 服务，地址为 `http://127.0.0.1:1420`；浏览器 Vite 服务保留 5173 端口。根 `.env` 配置信令地址的方式与 `bun dev` 相同。如果信令已在运行，使用 `bun --env-file=.env run desktop`。

```sh
bun run check:desktop
bun run --cwd apps/desktop test
cargo test --workspace --locked
bun run build:desktop --bundles nsis
```

NSIS 命令应在 Windows 上执行。只构建宿主程序而不生成安装器时，使用 `bun run build:desktop --no-bundle`。桌面前端输出至 `apps/desktop/dist`，Rust 二进制和安装器输出至根 `target/`。打包后的桌面页面使用安全源，非 loopback 信令端点必须使用 `wss://`；打包版本仅允许 loopback 端点使用 `ws://`。桌面模式下 Vite 也读取 `apps/web/.env.local`，因此其中的局域网开发端点必须通过构建环境中的 `VITE_WEBSOCKET_URL` 或 `apps/web/.env.desktop.local` 覆盖。构建会在生成可执行文件前拒绝不兼容端点。`bun run dev:desktop` 仍支持普通 WebSocket 开发服务，无需更改打包 WebView 的安全设置。CI 只运行一次共享 Web/桌面 TypeScript 检查和测试；之后 `desktop-dev.yml` 使用相同 release profile 和 `tauri/custom-protocol` feature 运行 Rust 测试及 `--no-bundle` 构建。两个桌面工作流都先构建前端再运行 Rust 测试；`tauri.ci.conf.json` 在打包时跳过重复前端构建。本地普通构建保留前端构建钩子。开发 CI 禁用 LTO，使用 16 个 codegen unit 以减少编译和缓存开销。`weblink-windows-x64` 产物包含 `weblink-desktop.exe`，目标机器需要安装 WebView2。缓存只包含公开注册表依赖。

若选择针对体积优化的 Windows x64 构建，先安装固定版本的 nightly 工具链及标准库源码，再执行体积优化构建命令：

```sh
rustup toolchain install nightly-2026-10-17 --profile minimal --component rust-src
bun run build:desktop:size --no-bundle
# Or generate the NSIS installer:
bun run build:desktop:size --bundles nsis
```

该命令应用 `.cargo/desktop-size.toml`，并使用 [Cargo nightly 的 `build-std`](https://doc.rust-lang.org/cargo/reference/unstable.html#build-std) 重建 `std`。它启用体积优化、完整 LTO、单个 codegen unit 和符号剥离；采集、WebRTC 和远程输入仍使用 `opt-level = 3`。保留 panic 展开和调试格式化：输入清理依赖 `catch_unwind`，以便某个设备操作 panic 后仍释放其他已持有输入。WebRTC 要求的静态 MSVC 运行时也会保留。Nightly 与常规 stable 工具链独立固定，既有开发和发布 CI profile 保持不变。生产采用该预设前应验证流媒体性能；构建成功、文件更小并不能证明延迟符合要求。

命令会转发 Tauri 选项及 `--` 后可选的 Cargo 参数，并用该预设覆盖开发 CI 环境的 release 优化设置。默认输出目录为 `target/desktop-size/x86_64-pc-windows-msvc/release`（安装器在其 `bundle/nsis` 下），显式 `CARGO_TARGET_DIR` 会被尊重。该独立缓存还包含重建后的标准库。

稳定版 `vX.Y.Z` Web 发布标签调用 `desktop-production.yml`，使用工作区完整发布优化。一次 Tauri 构建同时生成可执行文件和 NSIS 安装器，应用版本与 Web 前端一致。工作流还将可执行文件压缩为便携 ZIP：

| Actions 产物                    | Release 附件                       | 内容                                                      |
| ------------------------------- | ---------------------------------- | --------------------------------------------------------- |
| `weblink-windows-x64-installer` | `Weblink-windows-x64-setup.exe`    | NSIS 安装器，按需安装 WebView2。                          |
| `weblink-windows-x64-portable`  | `Weblink-windows-x64-portable.zip` | `weblink-desktop.exe`；需预装 WebView2 120+，解压后运行。 |

官网的单一桌面下载入口打开 `https://github.com/99percentpeople/weblink/releases/latest`。生产工作流还运行 `scripts/generate-release-notes.mjs`，将 `release-notes.md` 保存到 `weblink-release-notes` 产物中。内容由英文下载表和对应版本的 CHANGELOG 组成。新增发布条目应使用英文。下载链接使用该次发布的标签，确保历史说明仍指向自身对应的二进制。

发布时，解压外层 Actions 产物归档，将安装器 `.exe`、其 `.exe.sig`、便携 `.zip` 和 `latest.json` 按原名附加到对应标签的 GitHub Release。以生成的 `release-notes.md` 作为发布说明，并将稳定版标记为 Latest。便携 ZIP 包含应用可执行文件和 `weblink-portable` 标记，必须将两个文件放在一起，且需预装 WebView2 120+。这些工作流仅保存产物，不会发布 GitHub Release。

本地生成相同发布说明时，将示例标签替换为 `apps/web/package.json` 中的版本：

```sh
bun scripts/generate-release-notes.mjs v1.1.0 .tmp/release-notes.md
```

桌面构建使用 Vite 的 `desktop` 模式，默认信令为 `wss://ws.webl.ink`。平台模式与发布渠道彼此独立：`desktop-dev.yml` 设置 `WEBLINK_BUILD_CHANNEL=dev`，`desktop-production.yml` 设置 `stable`。二者复用 Web 前端的构建元数据逻辑。开发版“关于”、复制的版本信息和 `version.json` 显示 `<package-version>-dev.<short-commit>`，稳定版保留包版本。CI 提交由 `GITHUB_SHA` 提供，本地 Git 作为后备。本地桌面开发默认 dev 渠道；打包构建默认 stable，除非设置 `WEBLINK_BUILD_CHANNEL=dev`。CI 从 `Preview`/`production` GitHub Environment 变量读取 `VITE_WEBSOCKET_URL` 和 `WEBLINK_STUN_SERVERS`，与 Web 渠道一致。可选静态/HMAC TURN 配置使用 `VITE_TURN_SERVERS` secret，托管 TURN 凭据由信令后端提供。公共变量也可配置不使用部署 secret 的 PR 构建。部署专用 `VITE_*` / `WEBLINK_*` 值应放在 `apps/web/.env.desktop.local`。`VITE_SHARE_URL` 设置房间链接和二维码使用的公开前端 URL；`Preview` 和 `production` Environment 可覆盖它，桌面工作流分别默认 `https://dev.webl.ink` 和 `https://webl.ink`。本地桌面构建 dev 渠道默认 `https://dev.webl.ink`，stable 默认 `https://webl.ink`。自行托管时将其设为自己的前端 URL，避免邀请使用桌面窗口内部源。根 `WEBLINK_WEBSOCKET_URL` 仅覆盖开发配置，localhost 设置不会成为打包后的信令端点。

## 保存接收文件 {#saving-received-files}

桌面附件、文件库、预览、图库和二维码下载使用平台文件保存器，不通过 WebView blob 链接跳转。手动下载打开原生“另存为”对话框，起始目录为系统下载目录。现有自动下载偏好会将完成的接收保存到系统下载目录；重名时选择带编号的文件名。

前端通过不透明 save ID 发送有界二进制块，不会将任意目标路径传给写入命令。原生代码在选定目标旁暂存文件，只有收到完整声明字节数才提交。取消或失败会删除临时文件；页面重载或应用关闭会清理待完成保存。取消选择器不会报错，写入失败显示本地化错误。浏览器构建继续使用普通下载链接。

## 桌面更新 {#desktop-updates}

设置 → 关于提供手动更新检查和持久化的“自动检查更新”开关，默认启用。启用时，桌面应用在每次启动及运行期间每小时检查一次。自动与手动检查共用进行中的请求，安装期间跳过检查。每个版本在单次应用会话中最多通知一次。发现新稳定版后，通过现有通知服务发送更新意图：前台 toast，或已获权限的后台系统通知。应用隐藏时未送达的提醒保持待处理，在恢复可见时显示 toast，包括检查失败或长时间挂起后。仅原生通知在 24 小时后过期；待显示的应用内提醒沿用最后确认的更新，直到成功检查替换它、开始安装、禁用自动检查或应用作用域释放。已送达的系统通知不会再次作为前台 toast 播放。“应用更新”通知类别、系统权限、仅后台和声音设置均适用于系统通知。点击任一种通知都会打开设置 → 关于；检查不会自动下载或安装。后台失败和已是最新版不会发通知。关闭自动检查立即清除计时器并撤回待处理提醒，手动检查仍可使用。重新启用会启动新的每小时计时器；应用作用域释放也会清除它。

只有稳定版 Windows x64 构建检查 `https://api.github.com/repos/99percentpeople/weblink/releases/latest`。检查将发布 `tag_name` 与已安装语义版本比较，从 API 响应读取说明和附件 URL，不下载 `latest.json`、签名或安装器。不提供草稿、预发布及旧版或相同版本。如果存在匹配的 Windows 包，即使没有 updater manifest，也支持手动下载。开发版和不支持的平台报告应用内更新不可用。共享应用控制器串行处理启动/手动检查和安装，设置关闭后仍保留进度。Rust 服务仅接受安装最近一次检查过的版本。用户确认安装后，从该次具体发布获取 `latest.json`，验证版本和安装器 URL 与已检查发布一致，再用 Tauri updater 插件验证包签名并运行 NSIS。安装会关闭活动会话并重启 Weblink。Windows updater 退出前释放原生采集、远程输入和键盘资源。

相邻的 `uninstall.exe` 用于识别 NSIS 安装。便携 ZIP 中的 `weblink-portable` 标记会覆盖该判断；没有卸载器的单独可执行文件也视为便携版。便携更新链接到对应发布的 ZIP，由用户手动解压替换，不运行安装器。没有公钥的构建只提供手动下载。

首次发布稳定桌面版之前，使用 [Tauri signer](https://v2.tauri.app/plugin/updater/#signing-updates) 生成持久签名密钥：

```sh
bun run --cwd apps/desktop tauri signer generate -w "$HOME/.config/weblink/updater.key"
```

配置 GitHub `production` Environment（或仓库设置）：

| 名称                                 | 类型     | 值                                       |
| ------------------------------------ | -------- | ---------------------------------------- |
| `WEBLINK_UPDATER_PUBLIC_KEY`         | Variable | `updater.key.pub` 文件内容，而不是路径。 |
| `TAURI_SIGNING_PRIVATE_KEY`          | Secret   | 私钥文件内容。                           |
| `TAURI_SIGNING_PRIVATE_KEY_PASSWORD` | Secret   | 签名密钥密码；未加密密钥使用空值。       |

私钥应保存在仓库外，并保留安全备份。未来版本必须使用已安装客户端信任的同一密钥签名。该签名密钥独立于 Windows Authenticode 代码签名。

`desktop-production.yml` 在构建前验证密钥配置，生成只含公钥的临时 Tauri 配置，启用 `createUpdaterArtifacts`，并在重命名产物时保留安装器签名。`weblink-windows-x64-installer` 包含安装器及签名，`weblink-updater-manifest` 包含 `latest.json`。manifest 嵌入签名内容和固定到发布标签的下载 URL。将上述四个附件一起发布，使用生成的发布说明，并将稳定 GitHub Release 标记为 Latest。工作流生成 Actions 产物，不发布 Release。首个版本引入更新检查；实际升级验证需要后续更高版本的已签名发布，在 Windows 上完成。

## 运行时边界 {#runtime-boundaries}

- Rust 外壳按功能组织。`lib.rs` 组装服务及应用生命周期，`capabilities.rs` 查询功能实现是否可用。输入及键盘可用不代表获得系统访问权，开始操作时仍须检查原生环境。能力查询不会创建输入 actor 或 hook。
- `remote_control/` 包含共享 IPC、所有者生命周期、宿主协议/授权、有界传输队列和本地采集绑定，其编排代码可在所有宿主编译。`desktop-input::session::Session` 是原生 actor 边界；Windows 保留串行队列、授权引擎、安全 hook 和输入释放行为。未实现的后端无法创建输入所有者。
- `preview` 和 `keyboard` 提供统一命令签名，并在功能内部选择原生实现。Windows 为 CPU 消费者保留共享缓冲区预览，普通预览使用共享 GPU 呈现服务。通知通过 Windows 后端查询权限、显示和处理操作。只有 Windows 是受支持的桌面目标；其他平台保留不可用实现，用于宿主编译和共享逻辑测试。
- 原生采集与媒体仍共用 `desktop-capture`。其 `media/recording` 核心管理借用的输入端口、编解码器校验、录制生命周期、暂停片段、有界队列和二进制 IPC，不依赖操作系统、WebRTC 或 Tauri。`media/webrtc` 适配 SDK 的发送端音频观察器及采集时钟；Windows 将视频端口绑定到 Media Foundation，并提供 WASAPI PCM 作为后备。核心只消费经后端归一化的单调时钟，绝不关闭原始发送端。生命周期及二进制契约测试使用无需 GPU 或 WebView 的测试输入。D3D 帧、源枚举、设备采集和物理桌面几何仍面向 Windows。
- `apps/web/package.json` 是 Web 与桌面唯一应用版本来源。Vite 将其用于关于、复制版本信息和 `version.json`；Tauri 读取同一文件，生成原生运行时元数据、可执行文件资源和安装器版本。原生构建监听该 manifest 的版本变化。`apps/desktop/package.json` 不维护独立版本。Rust crate 版本仅用于内部依赖元数据，不控制应用发布版本。
- 桌面构建省略 PWA manifest、service worker、share target 和 Web 更新提示。桌面更新通过安装新版桌面包完成；自动更新依赖独立的签名发布渠道。
- 共享 `@weblink/platform` 契约提供浏览器和桌面适配器。`runtime_capabilities` 在可用时报告 Windows 原生采集支持；Windows 远程输入需要明确的本地批准。
- 只有本地主窗口能查询原生能力、控制原生屏幕共享和打开 HTTP(S) 或邮件链接。外部链接在系统浏览器打开。窗口不能跳转到远程页面或创建另一个特权 WebView。不授予通用文件系统、Shell 执行或输入控制 IPC 权限。
- 主窗口使用原生窗口控件。默认关闭时在应用样式的 Web 对话框中询问，可选择隐藏至托盘、退出或取消。“记住我的选择”会在执行前保存隐藏或退出偏好；取消不改变偏好。设置 → 应用可恢复“每次询问”或选择直接退出、隐藏，既有保存选项会保留。托盘可以恢复窗口、撤销本机控制或退出应用。第二个实例也会显示并聚焦现有窗口。托盘创建失败时禁用隐藏，关闭提示只提供退出和取消。
- 文件选择、摄像头和麦克风使用现有 WebView 浏览器 API。远程剪贴板使用下述平台适配器。禁用原生拖放拦截，使应用现有 HTML drop 处理器接收文件。宿主只自动授予本地应用源或配置的开发源摄像头和麦克风访问。Windows 启动时刷新这两个 WebView profile 授权，包括以前保存的拒绝。桌面 AppState 跳过浏览器权限查询和临时权限探测，打开设备菜单绝不开始采集。常规麦克风/摄像头控件启动采集，实际系统拒绝或设备缺失仍更新共享状态。刷新列表会重新检查缺失设备，成功采集会清除之前的系统拒绝。扬声器选择使用已暴露设备，或保留默认输出，不请求麦克风访问。系统隐私设置仍有效。文件选择/下载仍需 WebView2 验收；Windows 屏幕共享使用下述原生路径。
- IndexedDB 和本地存储属于系统应用数据目录中的应用 WebView profile。不会自动导入浏览器历史；开发与打包源使用独立存储。

## 应用窗口行为 {#application-window-behavior}

“批准远程控制后隐藏窗口”默认关闭，作用于被控端，也包括通过记住的客户端权限批准的情况。只有原生授权成功，才隐藏可见且未最小化的窗口。原生授权结束时，仅当该授权曾自动隐藏窗口才恢复；手动显示/隐藏会取消自动恢复。已替换或过期的授权不能恢复其他会话的窗口。这不依赖 WebView 状态轮询。停止被控采集时，在拆除采集之前显式关闭其控制通道并使输入绑定失效；其他已共享显示器仍可用。隐藏或最小化不会释放房间、媒体或宿主输入所有者。控制端键盘采集仍在失去前台焦点时停止。明确离开房间、页面重载、窗口销毁和进程退出保持既有清理行为；托盘“退出”始终退出应用。

呈现消费者共用一个原生可见性订阅，并结合所属文档的可见性。隐藏或最小化会暂停视频/会话诊断采样，释放说话指示器的音频分析；显示时以新统计基线恢复。仅失焦不会停止可见的画中画。观察不会停止借用轨道、远程共享或租约续期；最后一个消费者退出或页面重载会释放订阅。

渲染器订阅原生控制所有者的初始状态及后续授权请求、授权和关闭变更。状态观察不会续期或撤销控制。离开会释放观察器；旧所有者迟到的事件和异步决定不能更新替代房间。订阅建立失败会重试，但不替换原生所有者或重放授权。

主页面订阅原生关闭请求。重复关闭共用一个提示，回复必须同时匹配页面订阅和待处理请求。重载会释放订阅。页面订阅前，或通道拒绝投递时，仍可正常原生关闭。托盘“退出”始终可以独立于渲染器退出。

Windows WebView2 启动时禁用后台计时器/进程节流；桌面渲染器还在其生命周期内持有共享 Web Lock，以抵抗后台冻结。采集租约保持活动，渲染器确实失去响应时仍会过期。这些措施依赖 WebView 运行时行为，因此更改支持的运行时版本时必须检查后台运行。

画中画偏好位于应用设置，并导入原有会议偏好。浏览器保留既有画中画生命周期和权限规则；不支持 document PiP 时禁用自动开关。桌面画中画将主窗口变为可调整大小、始终置顶的窗口，提供自定义拖动栏和紧凑会议控件，保留当前网格或主画面布局。即使没有固定来源或活动视频，也能手动进入，包括多人头像网格。工具栏入口取决于原生窗口支持，而非当前主视图选择；只有自动进入要求活动视频。画中画保留同一渲染器、播放器和控制会话。进入和返回时动画调整窗口边界，并遵循系统减少动态效果偏好。原生帧可取消，最多排队一个；隐藏会使待处理帧失效，但不改变紧凑边界或窗口框架。恢复延迟到下次显示之前，在窗口可见前完成；可见窗口重载则立即恢复。返回按钮恢复之前尺寸、位置和窗口标志。关闭按钮及原生关闭请求沿用主窗口的应用关闭行为：询问、隐藏到托盘或退出。托盘“显示”也恢复主窗口。关闭确认、加入房间等对话框保持在紧凑窗口内。取消关闭保留画中画；关闭到托盘保留紧凑原生边界和标志，直到再次显示主窗口。来源移除、离开房间和页面重载释放原生呈现所有权。

符合条件的视频视图失去前台焦点或最小化时，桌面自动进入画中画。活动对话框、源选择器和明确隐藏到托盘会阻止自动进入。聚焦小窗口可继续操作，使用返回按钮恢复主窗口。明确的被控端控制后自动隐藏仍沿用原行为。

应用设置还包含现有自动加入偏好及桌面登录启动开关。自动加入保留现有 profile 值和房间行为。登录启动读取系统注册信息，不额外保存第二份偏好；只有修改开关或明确修复入口才改变注册。键盘转发和退出快捷键仍位于远程控制设置，与触摸输入偏好放在一起。

Windows 在应用打开时读取启动偏好，并在聚焦时刷新。已有启动项若指向其他可执行文件，或含空格却未加引号、存在歧义的路径，开关保持关闭且禁用，并显示“修复”按钮。修复使用带引号的当前可执行文件路径及 `--autostart` 重新注册，启用登录启动，再回读结果。缺失启动项表现为普通关闭状态，可以正常开启。读取绝不自动重写启动项，修复失败仍可重试。

登录启动使用 `--autostart`。原生配置默认在托盘可用时隐藏，也可改为显示主窗口；手动启动始终显示。托盘不可用或启动配置无法读取时回退到可见窗口。更改启动显示偏好不会启用系统注册。

Windows debug 和 release 可执行文件均使用 GUI 子系统，包括登录启动指向开发构建的情况。登录启动直接注册当前可执行文件及 `--autostart`，无需终端或 Shell 包装器。

Windows 单实例所有权按规范化可执行文件路径划分。手动重复启动同一路径会恢复现有窗口；重复 `--autostart` 启动保持后台。不同路径，包括开发和发布构建，可以同时运行。应用标识符及现有 profile/配置位置不变。

## 系统通知 {#system-notifications}

Web 与桌面 UI 共享通知偏好：消息、控制请求、测速请求和文件传输完成默认启用，且仅在窗口失焦时通知。内容预览和声音可分别关闭。浏览器权限只通过明确的页头或设置操作申请。新消息事件在持久化插入后触发；加载历史、重复投递和 ACK 不通知。传输完成需要在当前会话内观察到状态转换。

应用内 toast 用于更新提醒、控制和测速审批，以及远程剪贴板/文件拖放传输反馈。聊天消息和普通文件完成仅使用系统通知，应用恢复可见时不重放为 toast。具备应用内反馈的事件，如果通知未送达且仍有效，可在返回前台时显示。已通过系统通知送达的事件不会自动再产生 toast。明确点击控制或测速通知正文会将应用带到前台，打开该请求已有的 toast，包括组合操作按钮；普通焦点变化不会触发。移交后仍由同一个通知所有者负责清理、过期及重复操作处理；点击原生批准/拒绝按钮仍直接响应。更新提醒沿用上文桌面更新中的待处理寿命，其他请求和传输保留既有过期及有效性检查。

浏览器权限结合 Notifications 和 Permissions API 校准，在聚焦、可见性变化、页面恢复和权限变更时自动刷新；设置不提供手动权限刷新。未决权限提示不会被视为已授权，也不会反复重试。Android 已安装应用可能需要修改应用自身通知设置；网站权限无法证明系统通知渠道或免打扰状态。

消息预览包含发送者头像和姓名，群组标题还标明房间。UI 后备头像使用共享 SVG，保持渐变、首字母和字形对齐一致；通知将同一 SVG 栅格化为小 PNG。关闭预览会同时隐藏身份和消息内容。头像使用有界 PNG data URL；桌面校验后将其写入本地供系统使用，通知结束时删除。图像无效会回退，但不会抑制消息。Windows 在圆形 app-logo 槽显示头像；浏览器图标呈现由系统决定。Windows 通知源单独在应用身份中注册打包的 Weblink 图标，使发送者头像留在内容区域。该 PNG 在应用本地数据目录中跨单次通知生命周期保留。Web 通知在支持时提供独立单色应用 badge，没有发送者头像时使用应用图标；来源品牌由浏览器控制。

浏览器使用 Web Notifications，可用时通过 Service Worker 提供操作，否则点击打开应用会话。Worker 操作只指向创建页面和订阅，不会操作其他标签页。Windows 使用原生 WinRT Toast，提供消息内联回复和批准/拒绝按钮。Windows 审批通知使用 reminder 场景，横幅保持到响应、手动关闭或请求过期。后台 WebView 被节流时，原生截止清理也会移除已显示提醒；请求取消和订阅拆除会立即撤回。普通消息和回复保留默认横幅行为。Windows 通知状态查询是只读的。新安装的未打包应用在首次通知前，`ToastNotifier.Setting` 可能返回 `ERROR_NOT_FOUND`，映射为 `unknown`，区别于 granted、denied 和 unavailable。首次真实通知仍可无需权限提示直接分发，由 Windows 执行自身设置。只有分发才注册应用身份，不发送临时通知探测状态。其他原生失败仍是错误；设置区分加载、可重试失败和不支持环境。其他桌面系统报告通知不可用。Windows 系统通知设置可能阻止显示或声音。

操作要求活动订阅和未过期通知。批准还会通过既有控制服务重新核对确切待审批请求；取消请求会撤回通知。异步工作前先将操作消费一次。回复走常规消息服务，绝不清空其他草稿；本地接收失败会把回复保留在会话草稿中。接收后的投递失败属于已存储消息及其现有重试流程。测速通知与应用内 toast、面板共用同一个待审批请求，包括原始 20 秒期限。批准/拒绝只结算一次，打开通知会显示现有审批 toast。取消、连接丢失、过期或应用内响应都会撤回通知。迟到操作不能批准同一对端的新请求。测速提醒有独立类别开关，遵循共同权限、焦点、预览和声音偏好；关闭提醒不会禁用应用内审批。从 toast 或系统通知拒绝都会关闭请求，不打开测速面板。重载/关闭会释放回调，并在 Windows 和浏览器撤回通知。这是对活动本地事件的通知，不是应用关闭后的推送。

## 原生屏幕共享 {#native-screen-sharing}

支持的 Windows 系统中，会议屏幕共享按钮打开显示器/窗口选择器。选择器分开屏幕和窗口，单列显示来源及尺寸，并支持窗口搜索。选择来源后才在相邻预览区加载缩略图，不会预先采集所有来源。采集方法在设置中配置，选择器按所选来源类型读取。屏幕可使用 DXGI Desktop Duplication 或 Windows Graphics Capture（WGC），窗口使用 WGC。可用性在当前交互会话探测。DXGI 采集活动时，查询复用正在运行的会话作为支持证据，不能尝试再次 duplication 本进程已占用的输出；停止后重新探测。Auto 对屏幕优先使用 DXGI，启动失败可回退 WGC。窗口默认明确选择 WGC；不可用的显式选项会失败，不会静默改用后端。默认仍为 1080p / 30 fps。设置 → 音视频控制分辨率（最高 2160p）、帧率、码率和降级策略。桌面帧率选项根据已连接显示器当前刷新率生成，包括超过 60 FPS 的高刷新率；仍保留常见低帧率。显示器信息未知及浏览器构建使用 15/24/30/60 FPS。重新打开控件会刷新显示器信息，已保存但不可用的帧率降到最近的可选值。浏览器隐藏原生采集与编码器控件。这些是上限，不保证吞吐。摄像头和浏览器屏幕采集共用分辨率/帧率偏好。更改分辨率、帧率、码率和降级策略会直接更新活动浏览器及原生流，不重建采集或 WebRTC 连接。快速编辑会合并，原生预览轨道绝不被 WebView 约束或重编码。编解码器、编码器和采集后端变更在下次共享生效。保留音频同意及静音状态。无效的实时限制在提交前拒绝；约束和发送参数失败会报告给用户。

软件格式来自 libwebrtc 发送能力。硬件 H.264 和 HEVC 编码器来自可选 NVIDIA NVENC 会话初始化，以及 Media Foundation 硬件 transform 枚举后的激活和输入/输出类型协商，而不是 GPU 型号名称。自动编码通过现有已认证媒体 hello 交换浏览器/WebView 解码 MIME 能力。每条连接将本地编码格式与自己的接收端能力求交集。未知/旧接收端使用 H.264/VP8 和 Opus/PCMU/PCMA 兼容基线，不限制其他接收端。原生选择优先可用硬件，再依次 AV1、HEVC、VP9、H.264、VP8；浏览器使用相同格式顺序。音频优先 Opus，再 G.722、PCMU、PCMA。这是确定性偏好策略，不是设备性能基准；SDP 仍协商 profile/level，实际解码另行监测。交集为空会暂停受影响浏览器发送器或拒绝原生 offer，不结束本地采集。浏览器手动选项保留 WebRTC 后备顺序；原生手动视频格式固定，音频手动选择仍是偏好。二者都不改写用户保存的偏好。

加入或离开不会更改既有对端的格式或重启其流。能力报告改变时，仅重新评估该接收端的选择。浏览器发送器在既有连接上重新协商；原生发送器仅在解析后的格式变化时替换受影响接收端的屏幕发布，保留采集、原始预览和房间连接。每个待处理发布携带自身选定格式，其输入通道重新绑定到替代发布。发送端选择对应硬件或软件编码器，并在观看者间共享采集像素转换。设置将编码器和格式合并为一个选择器，提供 Auto 及探测到的硬件/软件格式组合。保存设置接受全自动编码或具体编码器/格式对；其他组合使用自动默认值。已保存但不可用的具体组合会明确标记，不静默替换。每个远端拥有独立编码帧来源和 RTP 连接，以及独立码率与关键帧反馈。原生 H.264/H.265 观看者起初使用独立硬件工作线程和带宽反馈。当后端、编解码器、尺寸、帧率、色彩、预设及预览模式一致，且分配码率在同一码率区间稳定两秒时，可以共享一条编码比特流。池只用几何 1.5× 区间决定成员归属；编码器遵循活动消费者中最低的正分配值，并受各自设置限制。暂停的观看者跳过帧，在关键帧恢复，不暂停其他观看者。短暂跨区间不会改变当前比特流。当观看者预算相差 1.5 倍或更多且持续两秒时，可移到独立工作线程；预算再次稳定后可重新合并。每个观看者保留自身 RTP 发送器。单个观看者或整组一起改码率时，原地调整活动编码器。硬件帧时间戳跟随采集时间，而非提交到工作线程的时间，因此排队、转换重试和驱动就绪不会改写媒体节奏。静态刷新按帧准备时间推进，跨重试和分组变化仍保持时间戳单调。浏览器与原生软件编码器由 WebRTC 管理，不属于该池。显式选定编解码器会将协商限制在该格式，不兼容接收端会失败，而非静默切换。驱动/会话上限和支持的分辨率/帧率组合仍然适用。Windows 本地预览不创建编码器或 WebRTC 连接，编码器选择和码率仅控制远程发布。摄像头和麦克风仍使用浏览器编解码器偏好；已保存码率及浏览器编解码器偏好保留现有存储键。

NVIDIA 采集设备上的自动硬件编码优先尝试以 D3D11 NV12 纹理驱动的原生 NVENC。发现过程检查已安装驱动的 API、编解码器、输入格式、异步输出和动态码率支持，然后初始化会话。可选驱动 DLL 从 Windows System32 加载，不要求或打包 CUDA/NVIDIA SDK 二进制。固定的 API 12.2 头文件在 `crates/desktop-capture/vendor/nvcodec` 保留 NVIDIA MIT 声明。

原生预设为 `balanced`、`quality` 和 `latency`。NVENC 分别映射为 P3/超低延迟/无 AQ、P4/低延迟/空间 AQ 强度 5、P1/超低延迟/无 AQ。Balanced 和 quality 先以四分之一分辨率分析当前帧，再按完整分辨率编码；单帧 VBV 跟随实时传输码率，使突然场景变化在受限连接上消耗较少比特。Latency 使用单遍编码。三者均为 CBR，并禁用帧重排、B 帧、lookahead 和时间 AQ。对已验证支持预设的后端，设置提供这三种意图，并分别记住每个编码器 ID（包括 auto）的选择；缺失时默认 balanced。更改在下次共享生效，实时分辨率/码率更新和格式协商保留会话预设。编码器分组键包含预设意图，它独立于编解码器、分辨率、帧率和码率上限。Media Foundation 将意图映射为质量/速度值 33、67、0，并请求低延迟及零 B 帧。发现会初始化每种预设，非默认 MF 选项还要求控制回读匹配。原生软件 VP8、VP9、H.264、AV1 通过 SDK 软件预设 API 提供相同意图，balanced 保留上游默认值。共享房间连接上的每个软件屏幕发送器独立持有预设和实时 VFR 目标；更改一个屏幕 FPS 会更新其编码器逐帧码率预算，其他屏幕与摄像头保持设置；重建该发送器编码器时复用其 profile。Quality 选择 VP8 最大复杂度（桌面 speed -3）、VP9 speed 6、OpenH264 高复杂度、AV1 speed 8；latency 选择 VP8 低复杂度（桌面 speed -6）、VP9 speed 9、OpenH264 低复杂度、AV1 speed 11。显式 VP9/AV1 speed 绕过动态速度变化，其他 trials 不变。默认值可能已使用最快设置，因此某些编解码器/分辨率下 latency 与 balanced 未必不同。OpenH264 保留单 slice CBR 及现有线程/丢帧策略。软件预设不改变用户降级偏好或流限制。浏览器 WebRTC 不暴露这些控制。Auto 在选定后端尝试所选意图；预设被拒绝时先重试 balanced，再进入既有同编解码器后端回退。`encodingPreset` 诊断以 0/1/2（balanced/quality/latency）记录请求和实际应用意图及失败状态，它不是驱动回读；其他控制保留各自回读语义。预设表示权衡，不保证质量提升或端到端延迟目标。H.264 使用 Baseline，HEVC 使用 Main 8-bit，保留既有 RTP 和录制包格式。缺失/旧驱动、不支持配置或编码会话耗尽时，回退到同编解码器 MF。活动 NVENC 失败也会重开 MF 并请求 IDR，保留发送器和录制 tap；该接收端不会反复重试 NVENC。MF GPU 输入失败时仍可使用既有内存输入路径。这些是兼容回退，不保证每个驱动支持每种分辨率，也不保证 MF 能从 GPU 设备丢失中恢复。手动 MF 选择保持在 MF；保存的 `nvenc:h264` / `nvenc:h265` 在 NVIDIA 硬件不可用时可使用同格式 MF 后备。

Media Foundation 路径不限定厂商：AMD、Intel 和 NVIDIA 硬件均依赖已安装 GPU 及驱动暴露兼容的 H.264 或 HEVC transform。仅凭 CPU 品牌不能确定硬件编码支持。HEVC 使用 Main 8-bit NV12 输入和 H.265 RTP 编解码器。只有检测到 HEVC 硬件后端的会话才启用 Cargo fork 的 external-HEVC factory；普通/软件 factory 不会声明无法提供的编码器。既有 H.264 编码器 ID 稳定不变，HEVC ID 带编解码器后缀以支持多格式驱动注册。接收端必须协商支持 H.265。视频 answer 被拒绝时立即报告格式失败，不等待 ICE。自动选择随后为该接收端尝试下一个共同格式，具体编码器/格式选择保持固定。尚未实现原生 AV1 硬件发布。

协商成功并不能证明可解码。接收端在视频 RTP 到达时观察解码帧推进。持续停顿先请求新连接和关键帧；连续两次停顿且没有持续解码推进时，自动选择可探测下一个共同视频格式。这只影响该发布/接收端，不是浏览器级格式禁用。没有解码停顿报告的网络失败保留相同格式和有界传输重试。隐藏/冻结页面、采样中断及 RTP 计数器重置会开始新的观察窗口，后台时间不会耗尽视频恢复窗口。明确的编解码器/播放拒绝会立即从受影响接收端的自动选择中排除该格式。替代发布复用现有采集和编码池，其他观看者及录制保持当前工作线程。失败格式在发布/会话重置前不再重试。共同格式耗尽及显式选择仍以终止错误结束，在现有来源卡片显示错误。卡片跨媒体重连保持发布身份。传输重试有界，仅在持续解码推进或格式变化后重置预算。新增的 `receiver-status` 消息报告健康/不支持接收端，`retry.reason=decode` 区分解码停顿与网络中断。旧发送端可以忽略 reason，继续既有有界重试。`stop.retry` 在修复传输期间保留卡片；明确停止也会清除退避或未完成 offer 期间保留的卡片。

浏览器/WebView 解码取决于运行时协商的接收能力，而非发送端 GPU 或 Windows 媒体文件编解码器扩展。运行时必须在 WebRTC 暴露 H.265 才能接收 HEVC，浏览器和 WebView 版本可能不同。WebRTC 没有逐接收端强制 GPU 解码开关。应保持浏览器 GPU 加速启用，并在流统计可用时检查实际解码器实现和解码耗时。Chromium 在仅接收场景可能隐藏实现及硬件效率字段，字段缺失不能证明软件解码。原生屏幕接收已请求零额外音视频抖动缓冲，但仍受浏览器丢包恢复和音画同步要求约束。应用不启用实验编解码器标志。

原生屏幕共享设置逐观看者 RTP 视频上限和用于带宽探测的传输总上限。房间连接的总上限为全部活动输出屏幕、摄像头上限之和，再为每条输出音轨预留预算（默认 128 kbps）。尚未首次设置码率的摄像头使用默认会议视频预算。停止最后一个屏幕会恢复房间传输默认值。专用屏幕路径独立计算自身音视频预算。

应用远端 SDP 时，房间发送端只给输出屏幕视频段设置最高 1 Mbps 的初始估计，并受各观看者视频上限约束；输入视频及摄像头保留协商参数。未设置有限传输上限时，内置引擎将带宽探测默认设为 5 Mbps。原生屏幕 factory 还启用周期 ALR 探测，以便低活动期间继续恢复，使用引擎默认节奏与比例。不强制最低码率，更改上限也不重置初始估计。可用带宽只是该对端路径的估计，不是链路速度，也不承诺按配置上限发送。

硬件编码使选定帧节奏独立于 WebRTC 观察到的输入帧率，以便静态内容后恢复运动。远端保守启动，带宽降低立即生效；上调在 50 ms 内合并，随后直接跟随最新分配，不额外乘法爬升。硬件控制器按 16 kbps 步长向下取整实际预算，同时保留更小的正分配。帧准入遵循当前网络预算。WebRTC 控制拥塞和 pacing，单个关键帧可能超过一帧字节预算。驱动支持时，Media Foundation 在媒体类型协商前按配置码率上限请求单帧 HRD/VBV 预算；部分驱动在初始化时锁定容量并静默忽略后续写入。使用上限而非保守启动估计可为码率恢复留空间。提前请求被拒绝时，类型协商后再尝试。硬件还请求低复杂度质量/速度值（33），优先交互延迟，可能牺牲压缩效率。两项控制均为可选，回读值保留在诊断中。降低上限立即限制传输目标，提高上限则允许目标跟随可用带宽。协商帧率、尺寸或输入设备变化可能需要新媒体类型。码率反馈和上限编辑保留运行中的编码器。NVENC 重新配置既有会话；MF 初始化时协商配置上限，并在同一实例请求传输目标。Intel MFT 在驱动接受时使用无约束 VBR，使平均码率在编码期间跟随 WebRTC 反馈；其他 MFT 使用 CBR。驱动忽略实时写入时保留最后确认码率。慢链路下帧准入可降低交付帧率。统计分别报告已确认编码器设置、传输目标和实际发送码率。

MF 与 NVENC 共用独立于准入预算的驱动更新调度器。它按编码器实例学习阻塞成本，取当前调用耗时与上次估计的一半中较大者。相对最后确认码率变化低于 10% 时，使用成本的二十倍（50 ms 至五秒）；更大幅度上调使用十倍（50 ms 至三秒）；至少 10% 的下调使用两倍（50–500 ms）。存在排队输入或进行中工作，且准入欠账达到一个配置帧间隔，或两个帧间隔未交付输出时，缩短为一次调用估计成本（50–250 ms）。输出空档期限也会唤醒休眠工作线程；没有待处理工作的空闲采集不视为停顿。欠账压力保持到降码率完成、取消或待处理工作排空。驱动更新不会免除准入欠账。因此开销低的驱动保持 50 ms 短合并窗口，不施加按厂商统一的数秒延迟。失败写入五秒后重试，不声称设置已确认。零分配只暂停准入，不写驱动。更改驱动码率前先交付可用输出，计时器确保采集空闲时仍应用待处理更新。重开编码器会重置成本估计和确认码率。采集节奏、帧准入、交付、关闭和唤醒条件继续共用；后端就绪、完成事件和看门狗保留各后端实现。

首个编码帧将来源绑定到发送器后，传输码率反馈不依赖后续帧即可到达来源并唤醒硬件工作线程。通知仅持有弱引用，在所有线程退出路径清除。零分配暂停原始输入，不向 MF 写入无效零码率；正反馈恢复输入并请求新关键帧。已有字节欠账在暂停及恢复中保留。固定编解码器控制在 transform 初始化时回读，不在每次码率更新时读取。

原生屏幕色彩设置在下次共享生效。固定 H.264/H.265/VP9/AV1 时自动转换使用 BT.709 YUV 矩阵；自动格式可能协商 VP8 时使用 BT.601。成员变化期间矩阵保持固定。显式 BT.709 或 full range 会将 VP8 排除出自动选择。显式 BT.601/BT.709 与 limited/full range 在 libyuv 转换、原始预览元数据、MF 输入/输出属性及 RTP 色彩元数据中保持一致。RGB 原色及传递函数仍为 sRGB；选择 BT.709 改变 YUV 矩阵，不改变来源色域或传递曲线。硬件 H.264/H.265 SPS 色彩描述在传输前归一化，因为接受 MF 属性不保证驱动写入匹配的 VUI 标签。此过程只改元数据，保留图像/时序数据，不额外编码。不支持或截断的 SPS 语法会使编码器明确报错，而非发送矛盾色彩描述。VP8 始终为 BT.601 limited range。UI 选中 VP8 时保留其他编解码器色彩偏好，不兼容的直接原生请求被拒绝。具有不兼容显式色彩设置的开放格式 offer 会排除 VP8。

当前采集和传输路径为 8-bit YUV 4:2:0 SDR。Full range 保留 256 个亮度级别，而 limited range 为 220，但不会提供 10-bit 精度，也不能恢复子采样/压缩丢失的色度细节。不声明已启用 HDR 或 4:4:4。HDR 需要浮点/10-bit 采集路径、匹配的编码 profile、协商的解码支持，以及 HDR 呈现或色调映射；单独的 HDR 色彩标签无法实现整条管线。复制的原生统计包含实际色彩描述、位深和色度子采样。

先选择编码器/编解码器，其高级选项显示受支持矩阵和范围。更改色彩偏好不会改变编码器或编解码器。忽略旧 RGB/4:4:4 偏好，所有原生共享使用 YUV 4:2:0。重启共享才能应用色彩或编码变更。

主画面存在视频时，其控件提供**显示流统计**操作。叠层属于该画面临时状态，默认关闭，画面移除或替换时丢弃，不保存到应用偏好。仅显示期间采样，各对端和本地预览分别记录；速率及逐帧耗时通过连续计数差计算，不可用值保持缺失。实际码率是报告间隔内 RTP 载荷字节增长，独立于显示 FPS。发送行分别显示 WebRTC 目标、最后成功应用到编码器的码率及可用时所选传输的出站带宽估计；这些是预算，不是实测流量或保证容量。每个接收端独立拥有编码器和拥塞反馈，应对比同一接收端对应发送行，不能拿另一对端码率比较。接收浏览器的出站带宽估计描述反向路径，不作为入站视频容量显示。原生硬件编码耗时测量从输入准备到输出，包括转换、驱动及工作线程延迟，不是 WebRTC 的编码帧直通耗时。硬件输入等待单独测量。采集到编码耗时从进入应用采集回调开始，排除缓存静态重复帧。包发送队列延迟按包数而非帧数计算。RTT 属于所选 ICE candidate pair。RTT 及这些重叠阶段测量之和都不是端到端画面延迟。Tauri IPC 只传小型计数器；统计不改变采集、传输或借用轨道寿命。复制统计包含各流最近两份原始计数样本。原生 `captureFrames` 统计可供预览的已转换帧，排除静态重复。硬件 `replacedInputs` 统计被新帧替换的待处理输入，`rateLimitedInputs` 统计因编码预算跳过的输入。接收端帧、丢包、NACK、PLI 和冻结计数与播放器丢帧分开。累计解码帧间隔及其平方和还保留平均 FPS 隐藏的时序变化。应在画面运动时比较间隔差值；静态桌面发送帧数低于配置 FPS 是正常情况。

原生采集保留原始 GPU 纹理。H.264 和 H.265 硬件编码器共用 D3D11 纹理输入路径：GPU shader 缩放、旋转、合成 DXGI 光标，并按选定矩阵/范围将 SDR BGRA 转为 NV12。NVENC 在采集设备上注册这些纹理。MF 后端必须声明 D3D11 支持，并通过 `IMFDXGIDeviceManager` 接受该设备；输入用 `MFCreateDXGISurfaceBuffer` 包装 NV12 纹理。原始桌面像素不再次映射或上传，消除 GPU→CPU→GPU 往返，同时保留采集所有权及格式转换需要的 GPU 拷贝。压缩输出仍经过 CPU 内存。

自动编码器选择在打开编码器时解析采集纹理的 DXGI adapter LUID。带 `MFT_ENUM_ADAPTER_LUID` blob 的 `MFTEnum2` 优先选择该适配器上已协商格式的编码器；不可用候选不会遮蔽下一个候选。手动 MF 设置保留既有 ID，仅选择对应 transform，并优先在采集适配器激活。能力发现包含次要适配器，同时避免设置列表出现重复 transform ID。枚举仅在发现或编码器初始化/重配置时运行，绝不逐帧执行。

运行时适配器枚举是可选的。API 缺失、枚举失败或匹配编码器不可用时，保留旧选择方式及 GPU 到内存回退。内存回退记住采集适配器，优先使用之前实际运行的编码器。使用纹理时，替换 GPU 设备会刷新适配器身份，不替换 WebRTC 发送器或录制订阅。这不会增加跨 GPU 纹理共享。管线诊断为每个编码器暴露 `selection`：请求/实际 ID、名称、采集和编码适配器及 LUID、是否匹配，以及使用旧选择的原因。未知的旧适配器保持未设置。

GPU 准入和 CPU 转换使用独立工作线程、通知及有界池。硬件对端共享不可变 BGRA 快照，最多四份。每次采集按输出尺寸及有效色彩矩阵/范围缓存最多八个 NV12 结果，使兼容 H.264/H.265 线程只转换该帧一次。缓存查询和发布按采集串行化，编码及驱动完成绝不在该锁下执行。不同格式和新采集保持隔离；缓存满后仍转换额外格式，但不在采集中保留。每个转换线程的池最多八个 surface。共享租约确保像素在采集和全部消费者释放前不可变，同时不通过引用环保活来源采集或生产线程。被跟踪的 MF sample 在 MFT 释放最后 sample 引用前保留 surface 租约。NVENC 缓存纹理注册，最多四个进行中输入，释放租约前 unmap 每个纹理。专用完成事件等待器只负责唤醒共享线程；共享线程复制压缩输出，先发布到传输，再进入有界录制队列。录制写入绝不在等待器或编码线程执行。NVENC 使用无限 GOP 和按需 IDR，保留单帧 VBV 预算，避免周期性整帧质量脉冲。启动、新消费者、接收端关键帧反馈及录制开始/恢复仍请求带参数集的恢复 IDR。仅码率变化不重置 GOP。即使共享输入来自不同转换池，NVENC 注册缓存仍最多八项，只淘汰最久未用的空闲注册，绝不淘汰待处理输入映射。池满时合并待处理输入，释放时唤醒，不阻塞采集或录制生产者。Shader 命令批持有 D3D 多线程锁，防止预览缩放和编码转换交错修改上下文绑定。静态刷新复用缓存 NV12 surface；尺寸/设备变化替换池，不复用尚未释放租约。GPU 初始化、转换或纹理输入/输出失败时，为该编码器选择内存输入，保留相同 WebRTC 发送器和录制 tap，请求 CPU 回读及新关键帧。回退保持到该对端编码器重新创建。

采集帧可能包含未旋转纹理坐标中的脏矩形，但纹理本身仍完整。元数据缺失表示未知/全帧变化，空列表表示像素未变。DXGI 将移动区域合并到变化边界，WGC 使用可选 ReportOnly 支持；元数据错误继续全帧处理。变化区域在采集 pacing、各接收端输入替换或限速过程中累计，只有成功准入/输入后才确认。独立光标边界、旋转、缩放和 NV12 对齐均保守计入；首帧、失效及编码器关键帧使用全帧变化。GPU AVC/HEVC 输入仅在可选控制被接受时提供 Media Foundation 脏区提示；提示被拒绝会禁用该功能，并重试完整纹理。软件和内存回退保留全帧输入。这不启用局部 GPU 拷贝，也不改变编码后录制 tap。

只有软件发送器、使用内存回退的硬件编码器，或等待下一帧的可见预览会请求 CPU 回读。尚未确认的预览通知会抑制后续仅预览回读，同时保留有界 staging 池和光标合成缓冲供复用。确认后从最新保留来源继续，不会为每个预览帧新分配桌面大小的缓冲。未旋转来源先通过 D3D11 shader 缩放到选定尺寸，再进行 CPU 回读和色彩转换，DXGI 光标坐标与像素同步缩放。不支持 GPU 处理时回退 CPU 缩放，旋转显示器保留现有旋转路径。原始纹理保留细节，使静态屏幕提高实时分辨率时仍可恢复清晰度。采集将新内容合并到一个保留 GPU 来源。CPU 转换线程按选定帧率将拷贝准入到一、二（默认）或三个可复用 staging 槽，槽数由原生采集设置中的 **GPU 回读缓冲区**选择，下次共享生效。更多槽允许工作重叠，但消耗更多显存且可能增加延迟，不增加 PCIe 带宽。GPU 拷贝与 CPU 转换重叠。D3D11 完成事件唤醒工作线程，在采集互斥锁外尝试非阻塞 Map；若仍待完成，则注册下一完成事件，不周期轮询 GPU。通知初始化失败会报告，两秒操作期限检测回读停顿，不提供轮询降级。帧率准入和静态重复保留各自期限。线程处理最新已完成拷贝；所有槽忙时保留最新来源，包括进入静态场景前最后一次更新。回读耗时包含异步 GPU 等待，重叠阶段耗时不能作为吞吐估计。来源尺寸/设备变化保留进行中所有权，停止时释放待处理槽，不发布迟到帧。软件与硬件共用可变帧率调度：所选 FPS 限制新内容，错过期限不会累计突发，空闲后新内容立即启动。硬件输入/输出就绪通过 MF 或 NVENC 完成事件唤醒共享线程，没有第二道编码器 FPS 门控。NVENC 还检测三秒输出停顿，并重试暂时输入背压，不阻塞采集。每个编码器只保留最新待处理输入。重新配置和关闭会释放回调状态，不保活采集会话。在支持 WGC 最小更新间隔的 Windows 版本上，请求 1 ms 最小间隔，由线程执行选定输出帧率；旧版本保留系统默认。线程保留最新待处理帧，避免屏幕转静态时丢失最终更新。GPU 映射/转换在异步执行器之外运行。两条编码路径每秒刷新静态内容两次，同时尊重更低 FPS 上限。硬件关键帧请求还会在下一个允许帧时机调度保留像素，无需等静态刷新期限。加入、传输就绪及解码器请求使用同一路径，需求跨唤醒保留到像素提交。刷新不重复 GPU 回读或共享 BGRA-to-I420 转换。共享 WebRTC 编码适配器在 H.264、VP8、VP9、AV1 稀疏输入期间保留配置 FPS 作为逐帧预算；实时 FPS 更改在下一编码前更新预算，不重置编码器、不提高码率分配，也不禁用传输或编码帧限制。软件 H.264 使用实时码率控制预设。其单流 OpenH264 将丢帧交给 WebRTC，不再在大场景变化后于编解码器内部连续跳帧。OpenH264 仍控制量化，WebRTC 保留丢帧器、码率调整、拥塞控制及 pacing。带宽不足时仍可按选定降级偏好降低帧率或质量。该策略仅作用于原生屏幕 factory 的软件 H.264 后端。硬件直通禁用编码器输入限速丢帧器，因为输入已是压缩参考帧。预编码 RTP 发送器从创建到实时设置更新都禁用原始帧分辨率/FPS 自适应；否则 WebRTC 初始质量缩放器可能在直通编码器启用前丢弃启动 IDR，延迟静态观看者出图。外部编码器 factory 从一开始就使用直通，包括 H.264，不等待发送器后端选择器从软件编码器切换；软件 factory 保留自身启动策略。采集设置和共享编码池负责编码前自适应，传输码率反馈、拥塞控制和 pacing 保持启用。硬件线程将传输码率反馈应用到活动后端，按实际编码字节计账，并提供有界 50 ms 突发额度。驱动超过接受目标时，线程保留最新原始帧及累计变化区域直至预算恢复；即使采集已空闲，也会在该期限唤醒。新输入可替换等待帧。空闲不能积攒无限突发额度，降低码率仍保留既有字节欠账。管线诊断将 `encodedBytes`、`rateLimitedInputs` 与输入替换、播放器丢帧分开。这保证码率限制，不承诺在不足带宽下对任意复杂内容维持所请求 FPS。配置的 `maxBitrate` 是视频码率上限，当前编码预算跟随传输反馈但不超过它。实时设置同时更新 RTP 发送器和硬件线程，没有额外固定 Mbps 上限：50 ms `capture_pipeline_stats` 提供锁等待、GPU 准备、Map、合成、转换、CPU 缩放和发布的有界滚动 mean/P95/max，以及输入/回读尺寸、GPU 回退原因和活动对端/编码器数量。还报告采集等待、逐组硬件输入等待、输入到输出和采集到编码分布、被替换输入数及进行中 sample。每个编码器的 `stages` 分开记录 CPU 准备（不含 `contextLock`）、即时上下文取锁、后端 `input`、`outputWait`（输入返回到观察到输出事件）、`eventDispatch`（观察事件到工作线程处理输出）、`output`（提取/复制/比特流归一化）、`delivery` 及实时 `bitrateUpdate` 调用。每阶段包含累计 `samples`/`totalSeconds` 和滚动 `meanMs`/`p95Ms`/`maxMs`。准备/输入统计已接受输入，输出阶段对 MF/NVENC 都统计匹配完成包。NVENC 在发布 ready 标志前记录完成，并在锁定比特流前开始输出计时；有界逐槽时间戳与输入计时使用同一 Rust 单调时钟。零样本表示未观察或不支持，不是测得零。GPU 准备耗时测量 CPU 命令提交，不是 GPU 执行。`outputWait` 也包含 GPU 依赖和回调调度，不能视为纯硬件编码时间。既有聚合 `encode`/`encodeMs` 保留从转换开始到输出的语义。不同采样窗口阶段不得相加推算端到端延迟。`outputInterval` 测量编码输出交付间隔，包括采集/空闲空档，是节奏诊断，不是额外编码阶段。`hardwareEncoders` 统计独立工作线程；每项带稳定 `groupId` 和当前 `consumers`（peer ID 或 `recording:<id>`），避免成员变化被误认为重启。对端换组时其统计建立新基线，避免不同线程计数导致虚假速率/延迟峰值。逐编码器 `gpuInputs`、`cpuInputs`、`gpuFallback` 区分实际纹理提交与内存输入，并标明回退原因；仅硬件流正常编码时，CPU 管线帧数可以为零。`sourceFrames`、`sourceAgeMs`、`sourceIntervals`、`sourceCopy` 独立于 CPU 回读和预览可见性测量实际系统帧到达及源拷贝路径。源间隔长而编码短提示上游空档，正常源节奏下输入被替换提示编码背压；两者都不能单独证明用户屏幕持续运动。即使非详细模式，自动化也显式采样 `capture.status` 获取新帧数、FPS 和帧年龄。生命周期订阅刻意不发送计数 tick，诊断读取失败报告不可用，不返回过期 FPS。硬件控制包含请求值、setter 结果及驱动回读；setter 接受不代表低延迟/CBR/缓冲请求已落实。不支持的可选控制仅作为诊断，不静默禁用其他方面可用的硬件编码器。准备耗时测量 CPU 提交，GPU 完成等待体现在 Map 中。这些诊断不包含网络传输和呈现延迟。


基准要求可用硬件编码器，输出 `LATENCY_PROBE` JSON。可用 `WEBLINK_PERF_CODEC=video/h265`、`WEBLINK_PERF_FPS=60`（30/60/120）、`WEBLINK_PERF_PRESET=latency` 选择单项运行；默认 H.264、60/120 FPS、MF 和 balanced。`WEBLINK_PERF_ENCODER` 选择准确编码器 ID，例如 `nvenc:h265`。仅编码器模式下，`WEBLINK_PERF_DYNAMIC_BITRATE=1` 以 10 Hz 提供大小幅度目标变化，并输出基线快照用于区间阶段比较。`offeredFps` 将生产者计时/调度不足与编码吞吐分开。`WEBLINK_PERF_TIMER_MS=1` 只为探测进程请求 1 ms 定时器精度，用于受控调度比较。`WEBLINK_PERF_ENCODER_ONLY=1` 绕过 WebRTC 和解码，使用相同合成纹理与硬件线程输出 `ENCODER_STAGE_PROBE`。应串行运行，保持其他 GPU 负载空闲。图案预先计算，每条流预热三秒，RTP/接收计数覆盖随后七秒；管线分布保留最近 120 个样本。比较时使用相同机器、构建 profile 和负载，这些区间及重叠阶段耗时不得相加作为端到端延迟。基准不采集桌面像素，不包含系统采集、真实网络路径、浏览器渲染或显示扫描输出，只检查交付，不断言时序阈值。

DXGI 获取/释放使用专用 D3D 设备。同一适配器上的第二个设备通过可复用的 NT 共享纹理及 keyed 所有权接收帧；sink 在释放借用帧前复制到自身保留来源。只有第二个上下文与异步回读共享，并受多线程保护。这增加一次 GPU 拷贝，但防止等待桌面更新阻塞转换或最终静态帧。桥接不增加帧队列，在宣布采集就绪前验证共享。移交失败或超时会结束采集，不访问无所有权的 surface。`AcquireNextFrame` 等待帧到达，而非每毫秒轮询。50 ms 超时用于静态桌面检查关闭，新帧立即返回；API 无法取消进行中的等待，因此保留此界限。DXGI 处理显示旋转及独立彩色/单色光标。显示模式变化、断开或访问丢失会结束采集，需要重新选择来源。软件及不支持 GPU 的编码器保留 CPU 回读和 libyuv 转换，支持的 H.264/H.265 使用上述共享纹理路径。录制仍在传输发布后订阅已编码包，并使用独立有界队列。本地原生录制通过与流媒体相同的硬件优先格式顺序选择 AVC/HEVC，受包录制器支持格式和用户显式选择限制。它在配置上限的带宽区间持有独立编码租约，有匹配线程则共享，否则创建，即使没有观看者也如此。观看者加入、离开和带宽变化不能结束录制线程。实时录制码率变化原地重配置该线程，比特流配置变化沿用 muxer 校验规则。停止录制只释放自己的租约，最后一个消费者释放线程。录制音频使用同一时钟上的采集 PCM 和 muxer 音频编码器，因此全部观看者离开后仍持续。浏览器屏幕共享和麦克风/摄像头行为不变。

原生源选择器每次新选择默认开启“共享音频”。显示器和窗口共享都采集系统播放，排除 Weblink 进程树，避免将收到的会议音频回传。Windows 进程 loopback 要求 build 20348 或更新版本，关闭音频仍可进行纯视频采集。启动失败会报告，不静默省略已请求音频。PCM 在专用 WASAPI 线程采集，直接发送到原生 WebRTC/Opus，只有本地录制时经 Tauri IPC 传输。屏幕会话结束时结束音频采集。线程等待包就绪及显式停止事件，不周期检查停止；停止也会唤醒静默音频设备。预览音频不经浏览器重发布或本地播放，接收音频归对应屏幕既有静音控件管理。

设置 → 音视频 → 音频采集包含“共享时静音本机”，默认关闭，保存后对下一次带音频屏幕采集生效。Windows 静音采集启动时活动的播放端点，进程 loopback 继续提供输出音频。每个端点最后一个请求采集结束后恢复原静音状态，包括启动失败和取消；保留原本静音状态及用户手动取消静音。麦克风及输出音频静音控件保持独立。浏览器通过 `getDisplayMedia` 请求 `suppressLocalAudioPlayback`，支持情况取决于浏览器和共享来源（通常为浏览器标签页），不支持时禁用设置。

音频采集默认明确为 48 kHz、立体声，旧 null 采样偏好也解析为相同值。浏览器约束将其表达为偏好，设备可能提供邻近格式，不宣称自动协商。原生系统音频格式独立于麦克风和预览轨道发现，后者可能固定 48 kHz。WASAPI 探测 8、16、24、32、44.1、48、88.2、96、176.4、192 kHz 的单声道/立体声，只提供成功的采样率/声道组合。选原生采样率时，支持则保留当前声道数，否则在同一次设置更新中选择兼容声道数。这些是采集格式，不承诺物理设备或编码流格式。WebRTC 重采样到协商格式，本地 PCM 录制为 Opus 重采样到 48 kHz，同时保留采集时间戳。22.05 kHz 等被排除，因为原生 WebRTC 来源要求完整 10 ms 帧。设备选择器使用“系统默认”；采集后端 Auto 仍是真实选择及回退策略，独立于格式协商。

显示器和窗口清单/后端分发分别位于 `crates/desktop-capture/src/backend/windows/{screen,window}.rs`。`CaptureOptions` 独立于 `MediaOptions`。原生消费者可通过 `CaptureService::start_with_sink` 和 `surface::FrameSink` 在没有媒体会话时使用采集：回调借用 GPU 纹理、旋转及可选光标元数据，借用至回调返回。需要保留帧的消费者必须复制，并保持自身队列有界。这是未来远程桌面的采集边界，不授予远程输入能力。服务持有持久 WinRT apartment，防止反复能力查询使 WGC activation factory 失效。

每个远端通过自己的 send-only WebRTC 连接直接接收 Rust 视频。原始本地呈现独立，轨道不加入浏览器发送器。流媒体像素绝不使用 Tauri invoke/event 载荷；只有 WebView2 共享内存映射向本地页面暴露预览像素。选择器另行通过二进制 IPC 请求一张最多 640×360 的 PNG 缩略图。显示器缩略图用单次 GDI 直接传入小位图，独立于流媒体后端，不打开 WGC/DXGI 会话。窗口缩略图使用 WGC 和系统批准的边框抑制，收到一帧或两秒帧超时后释放资源。边框抑制不可用或被拒绝时，窗口预览保持不可用，不启动带边框采集。两条路径都不替换活动共享。预览框保持 16:9，图像保留宽高比。UI 只允许一个进行中请求，丢弃过期结果，选择变化或关闭时释放图像 URL；预览失败不阻止共享。原生连接使用既有 ICE/TURN 凭据加载器和仅中继设置，原始本地预览不使用 ICE/TURN。初次房间绑定、迟加入及采集变化都使用同一发布路径，重连绝不能通过浏览器编码器重新发布本地预览。

Windows 为每个远端成员持有一个原生房间 PeerConnection。已认证媒体 DataChannel 携带屏幕发布 ID、确认、质量请求和接收状态。启用原生屏幕共享前，对端声明 `roomTransport/1`。连接当前 Windows 应用时，双向都要求此能力。旧客户端仍可聊天、传文件及使用普通会议轨道，但必须升级才能交换原生屏幕发布。

每个屏幕的视频和可选音频共用从发布 ID 派生的 WebRTC stream ID，输入通道标签携带同一 ID。增删屏幕会在房间连接上重新协商 transceiver，保留 ICE 传输、数据通道和其他发布。每个屏幕独立持有质量设置、有界重试和统计。原生发布器拥有自身 send-only 音视频段；浏览器反向共享时，如果 `addTrack` 选中了这些输入屏幕段之一，会将本地轨道移到独立媒体段。缺少此能力的对端接收首个活动发布，停止后提升下一个，不替换房间连接。关闭/替换通道会释放其原生发送器和远程接收器。主房间通道仍就绪时，意外关闭的专用通道由协商所有者重新打开。原生输入线程失败会打开新所有者并重建符合条件的媒体绑定，不重放旧输入授权。记住允许的对端不会改变既有传输或授权。ICE 失败重试有界，停止并重启共享会重置。

新增原生共享保留已有屏幕和窗口。每个采集独立拥有原始预览、编码器、远端及心跳，最多 16 个采集。明确停止、来源关闭、应用退出及 60 秒客户端失联租约会释放受影响采集和传输；应用退出释放全部。离开房间释放对端连接，但保留显式运行的本地采集供重新加入。待处理选择不能在替代房间启动，旧会话 ID 不能停止新采集。采集所有者订阅初始状态及生命周期、后端和尺寸变化；仅计数变化不推送，诊断消费者显式读取状态。读取和订阅不续租；独立 10 秒渲染器心跳为每个拥有的采集续期，预览隐藏时也继续。订阅建立或心跳 IPC 失败会重试，不将传输错误视为采集已结束的证据。重载清除页面订阅，停止会话在终止事件后释放订阅。原生终态保留错误和停止原因。逐对端硬件编码器失败只关闭自身传输，并保留有界错误诊断；采集/回读和系统音频失败仍以原生诊断结束受影响采集。

**设置 → 高级 → 原生屏幕采集测试**仍是本地诊断，使用同一采集服务及独立会话，报告采集到达统计，不映射或发送像素。500 ms 统计采样器在窗口或文档隐藏时暂停；状态事件和续租独立于采样器。关闭诊断面板只停止其自身采集。

原生采集服务等待命令及合并的生命周期通知。后端关闭/线程退出、媒体失败和来源尺寸变化直接唤醒所有者，稳定帧到达只更新计数。唯一定时等待为最早活动租约期限，在续期/开始/停止后重新计算。没有活动会话时无限等待命令或关闭。状态读取只采样计数，不另外安排生命周期轮询或续租。回调只通知所有者，停止和 join 资源仍在所有者执行，退役后端的迟到通知不能结束替代后端。

在已解锁的交互式 Windows 会话中运行原生 smoke 测试：

```sh
cargo run -p weblink-desktop-capture --locked --example self_test
```

测试创建并采集自身临时窗口，检查帧交付、调整大小、停止/重启及来源关闭，随后删除窗口，不采集已有窗口或显示器。`media_self_test` 还接受临时交换目录、可选编解码器 MIME（如 `video/vp8`）及可选编码器 ID（默认 `software`，或探测到的 `mf:...` ID）。它以 640×480 / 15 fps / 1 Mbps 限制运行，写出 `offer.sdp`，接受浏览器的 `answer.sdp`，响应 `resize` / `motion` / `done` 标记文件。`motion` 存在时只更新测试窗口，可用于检查接收 FPS。写入 `done` 前，使用浏览器 inbound RTP/解码计数验证视频交付和尺寸变化；两个测试工具都不使用个人桌面内容。`display_self_test` 在交互式 Windows 会话独立测试可用屏幕后端及停止/重启生命周期，只统计借用 GPU 帧，不读取、保存、编码或导出显示像素。Windows 单元测试在可激活硬件 transform 存在时测试合成硬件 H.264/HEVC，这不等于验证所有厂商、驱动版本或持续目标帧率。

`multi_media_self_test` 接受新的交换目录，创建两个测试窗口，为两个浏览器接收端写出 `offer-1.sdp` / `offer-2.sdp`。提供匹配的 `answer-1.sdp` / `answer-2.sdp`，验证二者解码后写入 `stop-first`。出现 `first-stopped` 后，确认第二接收端仍以新尺寸解码，再写入 `done`。它检查独立原始预览、媒体句柄、停止、实时设置及来源关闭，不采集已有窗口。

`thumbnail_self_test` 检查窗口/WGC 和屏幕/GDI PNG 快照、重复请求、已关闭来源及现有采集保留。在交互会话运行 `cargo run -p weblink-desktop-capture --example thumbnail_self_test`。缩略图只在内存中解码，不保存或发送。

DXGI 回读回归必须在已解锁的交互式 Windows 会话显式运行。它将显示器采集到内存，通过同一进程的两个 WebRTC 接收端检查软件及可用硬件编码，并重复停止/启动，不保存截图或向外部对端发送像素。普通测试跳过它，因为 SSH/CI 会话没有交互桌面：

```sh
cargo test -p weblink-desktop-capture --lib dxgi_readback_reaches_preview_and_remote_after_restart -- --ignored --nocapture
```

GPU 输入检查也要求已解锁桌面会话及支持 D3D11/NV12 的硬件编码器，覆盖两种采集后端、色彩/旋转/光标一致性、跟踪 surface 寿命、预览/软件需求、VFR、内存回退及有界消费者下录制暂停/恢复。H.264 使用本地 WebRTC 解码器，H.265 检查编码包。可选 `WEBLINK_GPU_PROBE_DIR` 保存短的采集 elementary stream 供外部解码检查，默认未设置。所有测试都不会向外部对端发送像素。

```sh
cargo test -p weblink-desktop-capture --lib gpu_ -- --include-ignored --nocapture --test-threads=1
```

默认忽略的 `compare_interactive_presets_on_identical_1440p_input` 基准使用合成 NV12 输入和真实 NVENC H.264/H.265 会话。将 `WEBLINK_NVENC_COMPARE_DIR` 设为父目录已存在的新目录，然后运行 `cargo test -p weblink-desktop-capture --release --lib compare_interactive_presets_on_identical_1440p_input -- --ignored --nocapture`。它在两个码率预算下按反向顺序轮次比较三种意图，写出 elementary stream 及精确的八帧循环 NV12 参考，并报告预热后的输入到输出完成耗时。它不采集桌面、不改变活动共享、不测最大流水线吞吐，也不包含采集/转换/呈现延迟。并发 GPU 负载会影响耗时；客观解码图像指标需要外部解码器，不等同于主观画质结论。

默认忽略的 `native_dxgi_final_frame_survives_stop_and_readback_device_is_reusable` 也需要交互桌面，检查有界停止及获取设备关闭后读取保留帧。`native_dxgi_acquire_wait_cost` 在当前桌面对比定时系统等待与原一毫秒轮询；`synthetic_dxgi_transfer_cost` 用合成 1440p 纹理测量额外移交拷贝。二者均不包含浏览器呈现或显示延迟。

## 有人值守的远程控制 {#attended-remote-control}

输入设备共用 `crates/desktop-input/src/devices.rs` 中的平台中立管理器，管理当前原生授权的键盘、鼠标、触摸板、触摸屏和手柄资源。持久输入资源在首次使用时挂载，能力探测不遗留挂载设备。授权撤销、采集结束、对端断开、原生租约过期或有序关机都会释放输入，并尝试卸载所有已拥有设备，即使其他设备清理失败也继续。清理结果不确定会关闭权限。暂停输入使按住状态归零，不撤销记住的同意。键盘和鼠标是逻辑注入资源，不是额外 HID 设备。

共享输入引擎向 `Device` 传递物理桌面像素和已提交 UTF-8 文本。Windows 负责 SendInput 绝对坐标网格、UTF-16 键盘包及部分注入文本的清理。各文本后端在原生提交之间重新检查绑定窗口和期限，并实现 `cancel_text`。既有 PC set-1 键标识及每刻度 120 单位的滚动线格式不变，由原生后端在注入时转换。

`NativeRemoteControl.devices()` 不打开控制所有者即可探测本地能力。原生状态快照包含能力和已挂载设备状态，各后端独立报告 `available`、`unsupported`、`driverRequired` 或 `unavailable`。新平台实现原生后端和能力探测，保留共享授权及生命周期管理器。新增 `ready.inputDevices` 和 `input-capabilities` 消息声明能力，旧对端保留现有键盘/指针协议。

Windows 手柄通过静态链接的 Rust 客户端使用可选 ViGEmBus 驱动。设置 → 远程控制显示驱动可用性、[官方安装指南](https://docs.nefarius.at/projects/ViGEm/How-to-Install/)和重试操作。安装需要管理员批准；应用不安装驱动、不自行提权，启动也不要求驱动。ViGEmBus [已停止维护](https://docs.nefarius.at/projects/ViGEm/End-of-Life/)，适配器与可移植契约隔离，替换驱动无需改变会话。当前驱动支持不保证宿主进程被强制终止后的清理；正常退出及远端失败使用原生清理。

活动远控期间，启用转发的前台浏览器控制端轮询 Gamepad API，无需表面焦点或 pointer lock。最多转发四个 `standard` 映射控制器的完整状态，使用有序控制通道及现有 grant/epoch/sequence 检查。每次连接拥有独立于浏览器索引或玩家槽的新身份。拔出、窗口失焦和释放发送断开，原生租约过期覆盖连接丢失。不变状态每 100 ms 续报，宿主 500 ms 未收到报告后中和控制器。可选后端失败只停止该控制器，不禁用键鼠。不支持非标准映射。设置持久化转发、基础振动、振动强度和摇杆死区，旧布尔转发偏好迁移时值不变。本地设备发现属于 appState，关闭转发时也继续；连接标准手柄时页头显示手柄开关。ViGEm 枚举期间首个报告可能返回 TargetNotReady 或 ERROR_BUSY。在首次报告接受前，后端最多容忍两秒此类错误，使用新浏览器样本重试，不阻塞输入 actor。接受过报告后失败仍触发清理，防止中和失败留下按住按钮。

ViGEm 输出通知通过有序控制通道返回基础双马达振动。原生所有者仅在已授权手柄活动时每 16 ms 非阻塞检查通知。反馈携带 grant、输入 epoch 和逐连接手柄身份。非零输出每 100 ms 续报，播放时长 300 ms，限制传输丢失后的振动。浏览器拒绝格式错误或过期会话反馈，按本地强度偏好缩放，并调用 `vibrationActuator.playEffect("dual-rumble", ...)`。失焦、文档隐藏、拔出、关闭反馈和释放都会重置活动效果。不支持的振动器不影响输入转发。此 Xbox 360 后端不提供 DualSense 自适应扳机或原生高级触觉。

Windows 显示器共享默认只读，直到观看者请求控制，宿主批准本次请求或已为该客户端保存允许规则。浏览器观看者虽然不能托管原生输入，也可请求控制。窗口共享和旧客户端保持只读。浏览器键盘和移动端文本/输入法转发要求原生对端相应能力。确认说明授权为整台计算机的输入权限；显示器矩形只映射指针，不是操作系统安全沙箱。

会议次要视图提供受支持的远控、全屏和画中画操作。激活时先将已有 tile 提升为主视图，再启动所选功能；输入转发仍由主视图拥有，只有一个 tile 时默认即为主视图。控制请求中/活动中，或显示模式正在打开/活动时，切换或取消固定会请求确认；取消也取消新操作。确认会先结束这些模式再换视图，不停止共享轨道。新共享保留忙碌主视图。已批准头像请求跟随匹配屏幕，保持同一控制会话，不相关共享不能替代。来源消失或房间结束仍直接常规清理，不等待确认。

桌面组合层将每条连接绑定到本地拥有的房间、peer generation、客户端、采集会话、发布及当前显示几何。`crates/desktop-capture` 提供 DataChannel 端口，绝不导入独立的 `crates/desktop-input` 授权/输入引擎。全机所有对端及来源共用一个权限中心。远程消息不能注册目标或批准同意。批准是仅暴露给桌面主窗口的可信本地策略决定，不要求前台激活或实体点击证据。传入请求使用持久 toast，提供批准/拒绝；拆分批准按钮还提供批准并加入允许列表、拒绝并加入阻止列表。规则是按现有持久 client ID 保存的本地偏好，不按可编辑显示名，也不是另一个已认证设备身份。被阻止客户端不获托管能力，已有连接规则改变后也如此；原生请求被拒绝，活动控制撤销。移除规则使未来请求恢复手动批准。

设置 → 客户端与房间复用现有客户端/房间偏好记录管理控制和文件权限。连接自动记住，现有本地历史导入一次。各记录有独立设置。忘记可见客户端或活动房间会恢复默认并保留记录；忘记离线记录则移除记录，但不删除会话历史。

具备能力的桌面还在既有原生屏幕信令通道声明 `hello.requestScreen`。头像/摄像头操作可发送 `control-request`、`control-cancel`，接收 `control-result`。批准后复用会议采集所有者，将首个显示器及系统音频共享给整个房间；已有可控显示器则复用。批准前不启动采集。请求随后移交给该发布的普通原生指针。一用授权将客户端、peer generation 和来源绑定 30 秒，避免第二次确认，同时不将同意扩展到其他对端或采集。取消、房间/对端拆除及请求过期使待启动操作失效。手动屏幕选择、控制请求自动共享及 MCP `screen.start` 共用应用所有者，按物理来源串行采集。已有共享保留音频及采集设置。成功的手动控制请求、MCP screen.start 和基于来源的 control.acquire 将采集移交给房间。“结束控制”释放输入；离开或失去控制权限不停止画面。“关闭屏幕”停止整个房间中的该来源。手动远控只提供“结束控制”，关闭画面由共享设备本地操作，包括为远程请求打开的画面。控制端结束控制或重新加入后，可通过保留画面重新获取输入。原生屏幕通道不声明关闭权限，并忽略旧 control-close 消息。成功移交后为房间保留采集并释放临时请求租约，不保留对端关闭授权。待处理取消及批准过期仍释放未完成移交的采集。独立 MCP screen.stop 授权见 [自动化](../reference/automation.md)。

采集关闭会在关闭传输前通知所有原生发送器。接收端在报告连接失败前给房间显式 stop 信号一个短暂传输关闭宽限期。停止和拆除取消该计时器，解码失败及停顿仍立即按原规则处理。

所有显示器共用一个权威原生输入授权。同一已验证设备和连接可请求控制另一个已共享显示器；手动请求也可替换自动化拥有的授权。宿主先批准新请求，再释放旧按住输入并签发新授权。原生 actor 在单次提交替换前检查确切旧授权、目标有效性及共享请求重放预算。准入拒绝、拒绝授权、取消或超时保持旧授权及按住输入不变。原生清理失败会关闭输入，不授予新控制，也不恢复旧自动化租约。其他设备不能替换手动授权。可选 `control.occupancy.takeover` 能力在屏幕 tile 和头像操作启用该请求，旧宿主在控制结束前仍报告忙碌。头像接管复用已控来源，再执行普通原生同意，不创建第二采集或预先撤销当前授权。仅查看另一屏幕不会移动输入授权。

公开占用状态包含可选 `controllerKind`（授权所有者类型）和 `automationActive`（自动化当前是否正在操作），使第三方观察者区分手动控制、独占自动化及借用手动授权的自动化。这些显示字段不授予接管权限。借用保留手动所有者，不允许其他设备替换其授权。

Toast 生命周期绑定原生 consent ID；轮询不会重新创建，取消、过期或所有者拆除会移除。只要同一请求仍为当前请求，响应失败就可以重试。

双方具备能力时，原生媒体 offer 包含 `weblink-control`（有序可靠）和 `weblink-pointer`（无序、无重传）通道。本地 capability hello 先于发布。后续能力变化会重建受影响显示传输，使现有只读共享可获得控制；无关窗口共享保留连接。被取代的能力读取不能覆盖更新权限决定。输入从原生回调直接进入有界原生队列，不逐事件经过 Tauri IPC；IPC 仅用于本地所有者生命周期、确认和状态。通道到达立即唤醒宿主线程，周期等待只在没有消息时服务安全和存活检查。拥塞的原生控制发送器在 DataChannel 缓冲排空通知时恢复排队输出；回调只唤醒所有者，序列化及发送仍在所有者线程，无关周期 tick 不重试阻塞输出。已到期指针样本直接发送，更早样本合并到下一期限。消息最多 4 KiB，可靠队列最多 128 项，发送缓冲最多 16 KiB。指针移动合并为最多每秒 120 次。各输入绑定 grant、连接、几何修订和 activation epoch。按钮/滚轮包含位置；移动有独立序列号和可靠事件屏障，重排移动不能跨越按钮状态转换。

宿主声明新增 `ready.persistentControl`：批准对当前房间/对端/媒体绑定持续有效，直到明确撤销或绑定结束。远程心跳空档两秒或输入过期会释放按住输入，但保留同意。不监测本地键鼠活动，也不会因此暂停或撤销控制。原生序列器挂起旧输入 epoch；新心跳后，如果用户仍意图控制，控制端自动请求新 activation epoch，绝不重放被中断输入。明确结束/撤销不能被迟到心跳或激活确认撤回。输入包必须包含 `activationSequence`，每个新 epoch 递增计数；原生宿主保留高水位并拒绝退役计数，不设固定恢复次数，也不积累重放历史。可靠输入序列出现缺口会释放按住输入并报告 epoch 不活动，使心跳驱动恢复，避免健康心跳维持不可用输入。

暂时 ICE 断开及 DataChannel 背压不关闭控制。可靠发送器拥塞时中断输入、丢弃未发送手势；缓冲排空后以新 epoch 和释放屏障恢复。原生回复队列保留同意/撤销顺序，合并存活观察，确认输入状态转换而非每次移动。入站网络输入突发会清除延迟输入并重置 epoch，但保留通道。控制通道终止失败进入现有媒体重试路径，为同一采集重建对端传输，授权不会带到新对端。

前端状态订阅观察原生状态并应用保存或一次性批准。原生窗口/页面拆除、离开房间、通道/媒体关闭及明确撤销拥有会话生命周期；延迟的 WebView 计时器或失败状态读取不能撤销同意。停止共享或替换房间/对端会结束授权，重新加入不会恢复。页头共享状态和配置的宿主紧急快捷键（默认 Ctrl+Alt+Shift+F10）提供明确本地撤销。原生控制及输入线程由排队命令、通道事件和授权变化唤醒。空闲线程没有周期状态循环，活动会话保留有界桌面/几何检查及精确同意/输入租约期限。键盘交付阻塞等待事件，前台变化唤醒 hook 线程，有界桌面检查继续作为安全后备。

观看 UI 只映射视频实际内容，排除黑边。桌面 tile 操作栏用一个图标按钮表达请求、取消请求和结束控制；移动及粗指针设备通过一个下拉按钮提供带标签操作。全屏时 portal 留在全屏容器内。批准后自动激活输入，没有面向用户的暂停模式。失焦、视图隐藏、拖动捕获丢失和设置变化使用新确认 epoch 释放当前手势，不结束同意。配置的观看者快捷键释放已捕获指针及键盘输入，但不结束同意。现有视频节点、音频路由和统计仍归播放器所有。

### 指针捕获与键盘输入 {#pointer-capture-and-keyboard-input}

本地光标模式下，已批准控制端的鼠标位于视频内容上时，隐藏共享屏幕视频中合成的光标。捕获鼠标拖动期间保持隐藏，直到所有按钮释放，包括拖出视频时；外部坐标钳制到最近边缘。全屏和视口变化在布局后重新检查静止指针，全屏远程 tile 即使未固定也接受输入。不拖动时离开视频、触摸、窗口失焦、捕获模式、输入挂起及结束控制都会恢复光标。该设置作用于共享采集，包括预览和其他观看者，不改变宿主实体光标。窗口拖动时 DXGI 可能将指针嵌入桌面像素。采集后端为 Auto 时，首次隐藏光标请求启动 WGC 显示采集，在首帧前禁用光标采集；移交保留采集 ID、媒体、预览和对端连接，状态报告活动后端 WGC。此后保持 WGC 至共享结束，光标变化只切换采集属性。移交失败保留原采集。显式 DXGI 绝不切换 WGC，只隐藏独立指针，因此已嵌入桌面图像的指针可能仍可见。显式 WGC 保持 WGC，直接使用其光标设置。每次共享启动时保留后端选择，设置更改作用于后续共享。可选 `cursorVisibility` 能力兼容旧宿主；光标更新要求当前 grant、media generation、几何和活动输入 epoch。

Windows 宿主同时声明 `cursorShape` 和光标可见性。指针设置中的**同步远程光标外观**默认开启；关闭时恢复默认本地光标，并改为仅所有权订阅（`appearance: false`），不采集或传输图像资源。本地鼠标模式在鼠标位于活动视频或捕获拖动期间通过 `cursor-watch` 订阅。`cursor-state` 快照携带 grant、输入 epoch、watch ID、递增 sequence、`owner`（`host` 或 `viewer`）及 shape。Windows 光标形状/可见性事件和现有原生移动观察器使快照失效，控制 actor 仅在失效后采样，合并为最多每 32 ms 一次；光标不变时无采样计时器。形状事件即使复用 Windows 光标句柄也使位图缓存失效。Actor 只发送变化，拥塞时以最新快照替换队列中的旧快照。暂停、撤销、断开及离开表面停止订阅；文本焦点订阅独立。

现有原生输入监听器也观察鼠标移动，但不消费事件。只有带本输入会话标记的注入移动算观看者输入；实体鼠标和其他本地应用移动将光标所有权交给宿主，最新原生移动生效。宿主接管时，采集先包含原始光标，再发送一次所有权更新；观看者隐藏 CSS 光标，停止本地动画并取消待解码，不回送可见性请求。后续宿主移动不发送坐标或形状更新。下一次原生观看者移动恢复记住的光标可见性偏好，并复用缓存资源发送观看者所有快照。没有空闲超时、轮询请求、确认或新输入通道。新 watch 忽略历史鼠标活动，结束 watch 恢复采集光标。

标准 Windows 光标句柄映射为观看者原生 CSS 光标角色，包括本地等待/进度动画，无需图像资源。应用私有光标使用资源流：静态图用本地 CSS 光标，动画自定义光标保留步骤顺序、逐步时长和热点，在本地 canvas 播放。Canvas 跟随观看者鼠标事件，不等待宿主位置，位于裁剪视频 tile 之外，必要时移入全屏容器。触摸和 pointer-lock 模式保留视频内光标。网页 DOM/Canvas 光标特效仍属于视频，不作为原生光标资源。

每个 `cursor-watch` 拥有 16 个资源槽。首次使用时宿主按序推送 `cursor-asset` 包，包含 `assetId`、`index`、`count`、`image`、`durationMs`，随后发送带 `shape: { type: "cached", assetId }` 的 `cursor-state`。包携带同一 grant、epoch 和 watch ID。重复帧通过 `image` 引用之前帧索引，不重复发送 PNG。每个资源最多 64 步，每步 16–10000 ms，PNG 数据最多 256 KiB（按 base64 长度限制）。每张图最多 128 × 128 逻辑 CSS 像素及 16 KiB PNG，资源内独立帧源像素合计最多 1,048,576。观看者使用前校验 PNG 头及解码尺寸。索引零替换槽，未完整资源绝不显示；再次出现资源只需槽引用。可靠有序通道上定义先于引用，绝不被合并丢弃。拥塞时延后整个资源批，并为控制消息预留队列空间。动画播放不发送帧更新、确认或缓存缺失请求。新 watch 从空缓存开始。本地光标订阅结束时一并结束播放、待解码及 canvas 所有权。新资源解码期间保持可用本地光标可见，避免每次形状变化都切换视频光标可见性。

Windows 发送原始 PNG 像素、物理尺寸、热点及 `sourceScale`（光标所在显示器缩放百分比，100–500）。逻辑尺寸和热点为源像素乘 `100 / sourceScale`，不取整也不缩小源 PNG，例如 200% 下 64 像素显示为 32 CSS 像素。宿主缩放变化即使光标句柄不变也使形状缓存失效。静态光标通过 CSS `image-set` 声明源密度；不可用时由本地 canvas 按相同逻辑尺寸绘制。动画光标 canvas 使用逻辑 CSS 尺寸，后备存储按观看者当前 `devicePixelRatio` 调整，内存上限为 8。观看者 DPI 或浏览器缩放变化只本地重绘，不重新请求资源，也不改变逻辑大小和热点。标准系统光标仍使用观看者原生样式。宿主到观看者控制消息允许 24 KiB，观看者输入保留 4 KiB 限制。自定义单色反色像素转为黑色加白色轮廓，保留形状及热点，近似 PNG 无法表达的背景反转。未知、超大或不支持的彩色 XOR 光标保留视频光标并隐藏本地光标。原生动画元数据通过动态解析 user32 `GetCursorFrameInfo` 导出获取，使用有界序列校验；离屏 ANI 资源测试验证其 ABI。不支持动画序列、浏览器解码/绘制失败时回退视频光标。资源就绪后本地开始播放，无需远程相位同步往返。两端直接使用该资源流，不设置旧客户端协商分支。

设置 → 远程控制提供两种指针行为。默认**本地光标**将鼠标坐标映射到视频，物理键盘转发使用独立开关，无需聚焦屏幕。**捕获并隐藏本地光标**在点击远程表面后使用 [Pointer Lock](https://w3c.github.io/pointerlock/)，捕获点击在本地消费。之后移动、按钮和滚轮通过现有相对指针通道作用于宿主当前光标位置，不发送冻结的本地坐标。两端均可移动同一原生光标。捕获模式不订阅光标外观或所有权，切入时取消本地模式 watch 并恢复视频光标。不支持或被拒绝的捕获允许再次明确尝试，不改变键盘转发。

两种模式中键盘及手柄转发都独立于指针捕获。共享释放快捷键默认 Ctrl+Alt+Shift+Q，可在键盘设置自定义；它释放指针捕获并关闭键盘转发，即使转发本已关闭也有效。键盘开关恢复转发，快捷键保留已批准控制连接。浏览器 Escape 也可能解除 pointer lock。失焦、文档隐藏、模式变化、失去控制和拆除释放捕获及按住输入；迟到锁定完成立即释放，重新聚焦不自动捕获。宿主有独立可定制紧急撤销快捷键，默认 Ctrl+Alt+Shift+F10。两项设置共用组合键录制器：点击后按组合键，释放主键保存，Escape 或失焦取消，重置恢复默认。快捷键要求 Ctrl、Alt 或 Meta 配合字母、数字、F1–F11 或受支持导航键；拒绝裸修饰键、F12 及保留系统组合。宿主快捷键在房间输入线程存活时使用被动低级键盘观察器，后台也有效，且只作用于当前原生控制授权。包括匹配组合在内的所有事件继续通过系统 hook 链。它不注册全局热键，多进程可观察同一组合，其他应用也可响应。不注册进程级 Raw Input 接收器，忽略注入事件，跟踪实体左右修饰键，每次主键按下只触发一次。紧急通知携带 grant generation，迟到输入不能撤销替代授权。拆除移除观察器；配置更新修改匹配器，监听器已关闭则保留旧偏好。重载和恢复使用保存组合。更新宿主快捷键也会结束控制端键盘捕获，防止保留旧组合。控制端系统键转发仍为显式捕获模式，并继续抑制已转发按键。

键盘转发偏好默认启用。房间页头键盘开关仅在控制支持键盘输入的远程屏幕时出现，托管或仅观看不显示。移动设备上，直到观察到本地编辑器以外的受支持键盘活动才显示；浏览器无法可靠枚举实体键盘，该观察只持续当前页面会话，不限制软键盘入口。开关立即修改同一保存偏好，关闭时释放键盘输入并关闭软键盘，指针控制及同意仍活动。

活动控制、开关开启且页面前台时转发物理键。本地聊天、设置文本框和其他编辑器保持普通输入。浏览器[物理键码](https://www.w3.org/TR/uievents-code/)映射到现有 Windows scan-code 白名单，使用远程键盘布局；接收端通过既有[扫描码输入路径](https://learn.microsoft.com/windows/win32/api/winuser/ns-winuser-keybdinput)注入。浏览器提供事件时支持字母、数字、编辑/导航键、F1–F12、左右修饰键和数字键盘。不支持 Pause、PrintScreen、未支持国际键及系统保留安全序列。本地输入法组合事件不作为物理键转发。

原生 `ready.keyboard: true` 启用包含 `scanCode`、`extended`、`down` 的可靠 `key` 包，共用当前 grant、几何、输入 epoch 及有序序列检查，不走有损指针通道。按住重复产生重复 down，但仅拥有一次 release。失焦、传输中断和拆除清除本地按键所有权，迟到 release/repeat 不重放旧按下。修改键盘偏好立即释放已拥有键，不结束同意。

Windows Tauri 的设置 → 远程控制还提供默认开启的系统快捷键转发。只有所选远程表面活动控制、没有本地编辑器拥有输入、共享键盘开关开启且原生前台窗口匹配时，才使用控制端原生键盘 hook。期间受支持扫描码（包括 Alt/Win 组合）来自原生通道，在到达本地系统或 DOM 前抑制。Hook 放行事件及启动等待旧按键释放期间仍可 DOM 转发。启动在 hook 回调外校准这些键，包括安装 hook 时遗漏的 release。本地编辑器、对话框及软键盘编辑器使用通常路径。关闭系统快捷键恢复浏览器按键处理。

[低级 hook](https://learn.microsoft.com/en-us/windows/win32/winmsg/lowlevelkeyboardproc)在专用消息线程运行，只写有界队列，IPC 另行交付。忽略注入事件以防反馈。捕获前已按住键保留本地，直至释放。前端消费确认每 200 ms 续期 750 ms 原生租约，最多 64 个未确认事件；超过 100 ms 的事件或序列缺口停止转发并重置输入 epoch。Windows Tauri builder 使用 `DeviceEventFilter::Always` 禁用未使用的 Tao Raw Input 设备流；其默认前台 Raw Input 注册可能使本进程低级键盘 hook 在 WebView 聚焦时收不到事件（[wry#1761](https://github.com/tauri-apps/wry/issues/1761)）。键鼠由 DOM 输入及应用原生 hook 处理，未重新验证聚焦窗口快捷键拦截前，不要启用 Tao 设备事件。迟到启动/交付不能附着到另一聚焦屏幕。失焦、窗口拆除和页面导航独立于渲染器停止捕获。停止后 hook 最多两秒只排空此前捕获键的释放，不捕获后台新按下。捕获失败/停止后恢复普通 DOM 键盘转发，不改变共享开关。重置远程输入 epoch 不在同一焦点及偏好区间重试失败捕获，保持 DOM 后备可用。新焦点区间或切换键盘开关会重试原生捕获，不撤销指针控制。明确退出快捷键仍禁用键盘转发。

所选退出组合由原生识别，同时释放 pointer lock 和键盘捕获，最终键不转发。配置的宿主紧急快捷键也会结束控制端输入；如果本应用同时托管控制，还会调用本地主机紧急撤销。这不增加安全桌面或 Ctrl+Alt+Del 支持。真实 Windows 快捷键行为需要手动验收，编译和所有权测试不能证明系统快捷键拦截成功。

任一指针模式中，活动被控屏幕上的键盘操作会同步聚焦该屏幕内的隐形文本编辑器，全屏也适用。此显式软键盘路径不要求 pointer lock。移动浏览器通过该用户手势打开系统键盘，没有自定义输入面板或按键工具栏。编辑器保持可聚焦，不占空间、不拦截指针。触摸设备（包括横屏手机）保持 tile 操作菜单可见。编辑器寿命长于菜单内容，选择键盘会阻止菜单关闭时将焦点归还触发器。隐藏键盘不结束控制。在同一被控屏幕进行指针操作保留编辑器焦点，可同时点击、拖动、滚动和输入；其他编辑器、对话框及明确关闭键盘仍保持正常焦点行为。可配置的**三指轻点**默认在触摸板模式**显示键盘**；直接模式将全部触点作为原生触摸转发。本地手势共用触点、移动和时序检测，要求恰好三个重叠触点、移动最多 20 CSS 像素，600 ms 内完成。第三触点取消待处理触摸板输入。有效三指序列可在原生 `touchend` 或 `touchcancel` 完成，因为 Android 可能取消而非投递释放。其他取消手势、拖动、长按及四指序列不打开键盘，也不回退点击。键盘激活与原生事件同步，只有 pointer 的运行时使用 pointer 完成。重复快捷手势保持键盘打开，或在 Back 后重新请求。直接触摸必须从视频内容内开始，pointer capture 在拖出画面后保持到释放，坐标钳制到显示边缘，不转为滚动或窗口拖动。显式键盘操作在 HTTP 和 HTTPS 都以自动键盘策略聚焦编辑器。可选安全上下文 [VirtualKeyboard API](https://developer.chrome.com/docs/web-platform/virtual-keyboard)只观察几何，不驱动显示/隐藏。编辑器留在全屏容器内，打开键盘不请求退出全屏或改变全局视口行为。键盘几何和 visual viewport 尺寸跟踪系统关闭，包括缺失几何事件时的全屏 Android Back。曾可见键盘持续隐藏 180 ms 后，编辑器释放焦点并更新可见状态，避免触摸屏幕重新打开；瞬时零矩形不结束文本输入。短暂动画空档、缩放和旋转不关闭输入。重新打开会取消待关闭操作，不在中间隐藏。真实 DOM 焦点转移、页面隐藏、控制拆除或明确关闭会释放输入所有权并恢复编辑器策略，不关闭其他输入框键盘。普通和全屏 tile 在其聚焦键盘压缩会议网格时仍保留播放及输入，来源移除和会话拆除仍禁用。Android Back 后重新打开会执行新焦点转换，不结束文本输入会话或打断组合。普通屏幕点击抑制自动重开键盘，包括不改变视口大小的浮动键盘。编辑器在本地暂存 IME 候选，只发送已提交值；处理 `compositionend` 前后最终 input，不发送中间组合字符串，也不重放 `InputEvent.data`，遵循[组合与输入生命周期](https://www.w3.org/TR/input-events-2/)。Backspace、Delete、Enter 使用物理键击，粘贴换行和 Tab 转为 Enter/Tab。编辑器聚焦时物理快捷键继续使用远程键盘布局。本地光标两侧的隐形编辑守卫支持重复 Left/Right 和 Backspace/Delete；只有不在组合中时，IME 仅选择位置变化才转为远程方向键。守卫绝不发送。

远程剪贴板同步独立于自动键盘可见性。`remoteKeyboard.clipboard` 默认 false，只需控制端开启。宿主在既有远控授权下服务请求，自身控制端偏好不限制入站请求。Windows 桌面宿主提供纯文本、HTML/RTF、PNG/常见 DIB 图像及本地文件。文件夹使用现有压缩 worker 转为 ZIP，接收端得到归档，不自动解压。不传输任意应用私有原生格式、虚拟 Shell 文件或文件移动/剪切语义。每次操作使用共享远程文件上限（默认 64 MiB，可配置至 512 MiB），最多 4096 项；文本/图像备选格式独立限制为 64 MiB。

`remoteKeyboard.clipboardFiles` 选择从宿主复制文件的目的地：`clipboard`、`cache`（文件缓存）或 `off`。未设置偏好在初始能力和权限发现完成前保持未设置；可写文件时选剪贴板，否则选文件缓存，再持久化。已保存选择不因后续权限变化被替换。选择器要求发现完成并开启剪贴板同步。Web 控制端标记为“剪贴板（受限）”：文本和图像使用标准浏览器格式。单个 PNG/JPEG 文件被解码后作为 PNG 图像内容写入，不是系统文件列表；PDF、多文件及其他不支持文件产生剪贴板错误。剪贴板和文件缓存是独立目的地，绝不相互重定向。即使 HTTPS，浏览器自定义格式也不能原生文件管理器粘贴，因此不将文件数据写入自定义格式。Windows 桌面控制端可将原文件列表（包括 PDF）写入原生剪贴板。文件缓存在无剪贴板 API 时也可用，复用文件库导入、去重和固定流程。Off 在原生适配器读字节前排除文件及目录，不影响文本、图像或粘贴到宿主的文件，也不重写持久偏好。浏览器读取请求可包含可写非文件 MIME 类型 `formats` 列表，宿主在打包/传输前过滤备选格式；`files: false` 同样在原生文件访问前排除文件和目录。空 `formats` 允许文件缓存接收文件，不传输无法使用的文本/图像。省略列表保留原生及旧客户端行为；旧宿主可能忽略可选列表，因此控制端接收后也过滤不支持格式。

可移植 `remote-clipboard` 请求将一次性 `operationId` 绑定到当前原生 `grantId` 和已认证对端会话。显式复制在发送 Ctrl+C 前采样宿主剪贴板序列，再等待更新序列。复制等待先订阅，再重新检查序列，通过 Windows 剪贴板通知唤醒，只设一个完成期限，不周期读取。等待后及交付内容前重新验证控制授权。上下文菜单复制使用 `watch`/`changed`/`unwatch` 订阅和 Windows 剪贴板变化通知；通知不含剪贴板数据，要求当前 watch 身份，不回显应用自身剪贴板写入。不会仅因控制获批而导入已有剪贴板。

剪贴板 bundle 使用既有文件发送器、接收器、传输注册表、压缩和背压。纯文本（包括 HTML/RTF）不创建任务。含文件或图像的 bundle 仅在打包载荷超过一个 128 KiB 块时在双方创建任务，更小 bundle 不进入任务列表。Offer 声明内容类型，解包后再次校验。传输缓存是临时的，只有明确“文件缓存”目的地将收到文件导入库；剪贴板操作不创建聊天消息或剪贴板历史。选定目的地写入或导入完成后复制才完成。Ctrl+C 已发送或已有剪贴板读取已开始后，Copy 不再依赖输入 epoch，接收/导入时焦点重置不会取消；Ctrl+C 前原 epoch 仍须有效。Paste 仅在完整 bundle 校验并写入宿主剪贴板后确认，随后 Ctrl+V 使用原控制授权和输入 epoch。撤权、关闭控制端设置、改变复制目的地、切换来源、断开和任务取消都会停止待处理工作。原生适配器在访问剪贴板时独立执行活动 grant 及当前采集检查，异步文件准备后也检查。

控制端独立探测读写 API，在浏览器支持时观察剪贴板权限变化。能力检查不读取或替换剪贴板，不根据 URL 协议或安全上下文标志推断支持。应用所有的发现发布 `appState.capabilities.clipboard`，复用现有运行时能力快照，每项剪贴板权限只持有一个观察器。设置和远程输入消费共享状态，挂载视图不重新探测。待处理或不支持的权限查询与拒绝访问保持区分。原生能力由实际后端报告。没有写能力时禁用本地剪贴板写入，文件缓存目的地仍可接收文件并订阅变化；其他情况关闭变化订阅，普通远程 Ctrl+C 仍可用。没有程序化读取能力时，仍支持通过聚焦远程输入表面或软键盘编辑器接收 Ctrl+V/系统粘贴事件。文本和单块复制/粘贴不需进度 toast。浏览器拒绝自动写入时保留已收内容，提供“复制到剪贴板”按钮，点击写入已有字节，不重新传输。取消、撤权、控制表面卸载及操作期限会关闭待处理操作。剪贴板文件任务在前台显示可取消进度 toast，后台使用现有传输通知偏好，包括完成/失败。进度复用同一 toast，后台通知不逐块重复。取消停止现有任务并移除加载提示，不添加操作栏按钮或独立粘贴对话框。失败任务保留可展开诊断错误用于排查。

控制端在本地编辑器之外、键盘转发期间拦截 Ctrl+C/Ctrl+V。浏览器粘贴消费真实 paste 事件，保留换行而非键入 Enter。浏览器复制手势在远端回复前创建带 Promise 的文本 ClipboardItem，跨传输保留文本写入激活，随后自动尝试支持的富文本/图像格式。浏览器粘贴消费真实事件暴露的格式及文件，不为自定义 bundle 探测异步 read API。写入被拒绝不创建独立保存操作，后续复制手势请求新内容。浏览器控制端只写剪贴板 API 支持格式，不读写 Weblink 自定义剪贴板格式。Web 接收复制文件时可选择文件缓存后下载。写权限为 prompt/unknown 时，“剪贴板（受限）”仍可选，用于支持的文本/图像，不请求原生文件列表。明确拒绝或缺失写 API 会禁用该目的地，但不替换保存偏好。Windows 桌面控制端直接写全部支持格式及文件拖放路径。收到文件在被剪贴板引用期间保留于本地临时目录；被替换快照享有 30 分钟宽限，在后续写入时回收。暂存最多 512 MiB / 128 个快照，正常退出清除。真实剪贴板互操作及移动浏览器权限仍需设备验收。

设置 → 传输 → 远程文件与剪贴板集中管理远程文件拖放、剪贴板同步、复制文件目的地及共享远程文件大小上限。这些仍是控制端偏好。

远程文件拖放由 `remotePointer.fileDrop` 控制，默认关闭。只需控制端启用，入站操作要求现有远控授权。Web 和桌面控制端共用 HTML 文件拖放表面，包括没有剪贴板 API 的 HTTP 浏览器。原生宿主在控制通道声明 `fileDrop`，目前只有 Windows 实现。本地文件拖到远程视频位置，排除黑边；目录使用现有 ZIP worker。功能支持复制到远程计算机，不支持从远程窗口拖出文件到控制端系统。

声明 `fileDrop.hover` 的对端在 dragenter/dragover 时还交换 `hover` 请求；离开视频、取消或撤权会取消原生 hover。控制端通过视频看到目标应用拖动反馈，不显示本地 drop 遮罩。另声明 `fileDrop.hoverUpdates` 的对端先确认初始 hover，之后发送无需逐位置回复的 `remote-file-drop-position` 通知，携带 operation ID、grant ID 及递增序列。发送端替换尚未提交传输的位置，宿主在原生工作执行时只保留最新待处理位置，忽略重复/乱序更新。通知不能启动拖动。Prepare 固定最终 drop 位置，丢弃待处理更新，并等待已开始的原生更新完成；迟到通知不能移动已准备、取消或完成操作。启动、prepare 和最终应用仍是需确认请求，原生失败也通过取消传播。仅声明 `fileDrop.hover` 的对端保留需确认 hover 更新，无 hover 的保留 prepare/offer/cancel。位置流保留浏览器提供坐标，不提高 drag 事件频率或精度。Chromium 文件拖动使用整数 CSS 像素，不像 pointer-move 可带小数；缩小远程视频会使细微拖动定位更粗糙。放大视频可减轻影响，插值缺失位置不能恢复原始指针坐标。

`remote-file-drop` 与远程剪贴板文件共用 remote-content bundle、文件通道、发送/接收器、临时缓存、背压及任务反馈。共享远程文件大小设置同时适用于拖放与剪贴板文件，默认 64 MiB，每次可配置 1–512 MiB。控制端在开始时快照上限并发送宿主，两端在目录压缩前后均执行文件总字节限制。Bundle 元数据独立预算 1 MiB，文本/图像备选格式保留 64 MiB 预算，最多 4096 项；只有多块传输创建任务。目录准备显示可取消加载提示。不访问剪贴板 API 或注入 Ctrl+V。宿主暂存真实文件，在专用 STA 使用 Shell IDataObject、IDropSource 和 OLE DoDragDrop。浏览器在 drop 前保护文件名及内容，因此实时 hover 使用有界、基于 MIME 的临时文件提示；预览仅产生 DragEnter/DragOver/DragLeave，绝不 Drop。传输期间保持预览，随后先取消并 join，再由真实暂存文件启动最终 OLE 操作。只允许 DROPEFFECT_COPY。目标决定是否接受文件期间，OLE 循环持续发送本地 hover，包括嵌入式 Web 编辑器的异步决定；只有 hover 反馈允许复制才释放，期限五秒，初始 DROPEFFECT_NONE 不立即结束。事件只发送到 drop 线程的 OLE capture 窗口，不进入系统鼠标输入队列。授权 hover/drop 位置在 OLE 期间控制光标。Hover 更新之间可能到达独立指针输入，拖动会校正光标，而非因位置不符取消。任何位置变化或校正都会清除旧接受状态，要求新的 hover 反馈后才在绑定点释放文件。确认及任务完成要求目标应用接受，但不意味着其后续异步导入/复制已经完成。不接受 OLE 文件拖放的应用会失败，不回退剪贴板粘贴。

准备绑定 grant、采集来源、media ID、几何修订、物理点、应用根窗口身份及边界。子级 drop 遮罩出现不使目标失效。原生应用前及拖动继续期间，宿主重新检查授权和目标。窗口不同或边界变化、撤权、会话断开、关闭控制端设置或取消都会停止待处理工作。仅输入焦点/epoch 重置不使已批准 drop 失效。目标可能在窗口身份不变时改变内部文档/目录，传输待完成时应避免此类更改。已接受路径保留 30 分钟宽限，暂存最多 512 MiB / 128 次 drop，在后续 drop 或正常退出清理。

独立的 `remoteKeyboard.autoShow` 和 `collapseControls` 偏好默认 false。本地视图开启键盘控制且可见时，自动键盘控制订阅 `text-input-watch`，携带当前 `grantId`、`inputEpoch` 和不透明 `watchId`（`null` 取消订阅）。已认证通道及 grant 已绑定采集目标和 generation。Windows 每 200 ms 在专用 MTA 线程采样 UI Automation，仅在 `focus` 改变时发布 `text-input-state`；更新携带订阅身份及递增 `sequence`。Focus 为带不透明字段 ID 的 `editable`、`none` 或 `unknown`。检测失败/不支持表示 unknown，不能证明失焦。不传输字段内容、标签、密码或原生元素 ID。

任一触摸模式的短暂静止单指轻点会允许自动打开，并在有序原生输入处理后刷新订阅获取新快照。可编辑焦点打开键盘，确认非文本焦点只关闭自动打开的键盘。切换字段重置暂存组合，unknown 保留当前键盘。手动打开仍由用户控制；手动关闭后直到下一次轻点前抑制自动重开，包括临时输入 epoch 变化。本地焦点转移取消自动打开准备，隐藏视图取消订阅；暂停、撤销、采集拆除或 epoch 替换停止原生观察。拒绝旧订阅、旧 epoch 和不递增序列。浏览器限制，尤其 iPhone 异步聚焦，仍可能要求键盘按钮。

折叠偏好只有在键盘几何或视口变化确认可见后，才临时覆盖工具栏和屏幕列表显示。关闭、失焦或 tile 释放恢复手动折叠偏好，不写覆盖它们。手动和自动打开键盘共用可见性生命周期。浏览器既不报告浮动键盘几何又不改变视口时，无法确认该键盘可见。

原生 `ready.textInput: true` 与 `keyboard: true` 一起启用可靠 `text` 包。每包最多 64 个 UTF-16 单元，不允许控制字符或孤立代理项。单次编辑器提交在发送任何前缀前限制为 1024 个 UTF-16 单元，更大粘贴被拒绝，包不拆分代理对。文本共用键盘 grant、epoch 和有序序列检查；仍按住物理键或鼠标按钮时原生引擎拒绝文本。传输背压停止提交，未发送后缀绝不自动重试。

关闭编辑器、页面隐藏、更改来源或键盘偏好，以及失去活动输入都会丢弃未完成组合。编辑器独立于视频节点，不重启媒体会话。系统键盘/输入法行为仍需真机验收；逻辑测试不能证明移动键盘显示或候选窗口行为。

### 移动端触摸输入 {#mobile-touch-input}

设置 → 远程控制保存观看端触摸偏好。触摸板模式使用相对单指移动、轻点点击、双指右键/滚动/捏合缩放，以及可配置长按拖动或右键。长按由手机浏览器 `contextmenu` 事件触发，没有应用计时器或延迟偏好；保留单指触摸默认行为供浏览器识别，只作用于静止单指手势。鼠标右键继续走 pointer 事件，直接触摸将长按识别交给 Windows。指针/滚动速度、方向和手势开关均为本地偏好。触摸采样率 30/60/120/240 Hz，默认 120 Hz，在两种模式限制移动、滚动和捏合更新，实际交付还取决于浏览器采样、定时器和背压。Down/up/cancel 状态转换及最终移动刷新绕过该限制。设置变化释放当前手势并立即生效。可用时按顺序处理真实合并 pointer 样本识别手势，绝不发送预测样本。直接移动仍按选定速率合并为最新完整触点帧，不重放所有历史位置。

宿主通过 `ready.relativePointer` 声明原生触摸板手势，使用有序 `trackpad` 事件。移动增量为共享显示器的比例，按钮/滚轮不含缓存绝对坐标。原生输入线程逐事件读取真实物理光标，保留亚像素移动，并限制在共享显示器内。增量按所选速率合并，但走可靠通道，避免丢包丢失位移。旧宿主保留绝对指针模拟移动和点击。双指滚动要求新增 `ready.touchpadPan`，使用有序 `trackpad` pan start/update/end/cancel。更新携带累计 CSS 像素质心位移，按选定速率合并，并应用速度及自然滚动方向。Windows 通过 `CreateSyntheticPointerDevice2` 创建带物理尺寸及 gesture-only 标志的专用 `PT_TOUCHPAD`，由系统识别滚动和惯性。能力检测检查真实 API/设备可用性，该手势不回退滚轮模拟。暂停、撤销、断开或取消结束触点及原生惯性。鼠标滚轮仍使用普通 wheel 输入路径。

捏合缩放使用相同有序 pan 生命周期，在 update 中可选携带累计 `scale`（触点距离除以初始距离，钳制到 0.1–4）。原生设备围绕已平移质心调整两触点跨度，由 Windows 和目标应用识别缩放。纯捏合即使质心静止也发送更新。捏合开始前忽略 8 CSS 像素以内的小跨度变化，滚动速度/方向不改变缩放比。滚动和捏合有独立观看端开关。旧观看端缺失 scale 时为 1，旧宿主忽略新增字段，因此缩放要求更新后的桌面宿主，无需更改协议版本。

直接触摸要求宿主新增 `ready.touchContacts` 能力，通过专用合成 pointer 设备发送真实 Windows `PT_TOUCH` 触点，不模拟鼠标。无此能力的宿主仍可用触摸板模式。每个有序帧包含全部活动触点，最多十个归一化位置，明确 down/update/up/cancel 阶段。移动遵循所选采样率，静止更新保留原生按住识别。手势解释归 Windows 和目标应用。黑边不产生直接触点，位置直接映射到物理显示像素，不额外乘 DPI。

直接模式触摸属性开关默认关闭，开启后转发浏览器报告的压力及接触面积。可选 `pressure` 为 [0, 1]，`width` 和 `height` 必须成对位于 (0, 1]，相对视频实际显示内容归一化。未知触点几何（浏览器默认 1×1）省略。宿主校验字段，将压力映射到 Windows 0–1024，并将物理接触矩形裁剪到共享显示器。注入只设置相应 `TOUCH_MASK_*` 位，缺失属性保留原生默认。静止属性变化仍产生更新，UP 在最终移动后释放压力。这些是新增字段，旧发送端省略、旧宿主忽略。触摸板模式仍在本地识别鼠标/滚动手势，不转发原始触摸板触点或压力。浏览器属性可能是固定后备值，转发并不能证明硬件压力/面积支持。

原生引擎在注入前验证触点所有权及转换。暂停、取消、模式变化、撤销、会话丢失和租约过期释放已拥有触点。取消覆盖整个手势并销毁专用设备，产生取消触摸事件而非完成点击/drop，下一手势创建新设备。触摸不能与按住鼠标按钮或键盘混合。既有 grant、epoch、有界队列和过期输入规则同样适用。合成 pointer 创建失败只禁用直接触摸，不禁用鼠标控制。

`NativeCapture.displayLayout()` / `capture_display_layout` 不打开采集即可读取物理显示边界、虚拟桌面边界、方向及可选系统资源缩放。缩放是元数据，不是坐标乘数。不透明 revision 在观察到布局变化或查询失败时改变，仅在采集服务生命周期内有效。原生 `display_geometry(session_id)` 还要求活动显示器采集，且不续租。该清单不是授权或显示变化订阅；输入集成除查询失败外，还必须在拓扑/会话事件上使所有权失效。控制所有者订阅采集生命周期/尺寸变化，收到通知时重新验证绑定几何，不周期查询采集状态。同一采集的观看者共用订阅，最后对端离开时取消。原生输入环境通知独立处理不改变采集尺寸的拓扑/会话变化。Windows 查询使用 [EnumDisplaySettingsExW](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-enumdisplaysettingsexw) 获取独立于 DPI 虚拟化的物理像素。

Windows 只读清单检查：`cargo run -p weblink-desktop-capture --example display_geometry`。浏览器/Rust 共享线格式 fixture 位于 `test/fixtures/remote-control-signals.json`；Rust 契约/生命周期测试使用 `cargo test -p weblink-desktop-input`，浏览器测试使用 `bun run --cwd apps/web test test/unit/remote-control.test.ts`。这些检查不构成真实远程键鼠验收。

### 原生输入工作线程 {#native-input-worker}

原生所有者注册已验证房间/媒体绑定和物理显示几何。单个线程串行处理同意、授权校验、输入及清理。保存的宿主紧急快捷键（默认 `Ctrl+Alt+Shift+F10`）的被动观察器必须在线程接受授权前启动，观察器或会话通知注册失败会导致启动失败。远程输入绝不选择任意 HWND、白名单外扫描码或系统坐标。所选显示器约束指针映射，不限制系统键盘前台或应用权限。

可靠队列最多 128 个命令，指针移动占一个最新槽，并按本地入队顺序与可靠事件排序。本地撤销丢弃排队工作；溢出、注入或清理失败关闭线程。超过 100 ms 的输入被丢弃并中断当前输入 epoch，保留同意至新激活。中断保留排队本地状态/同意调用，只丢输入。原生线序列器在入队前检查网络序列、epoch 和移动屏障。队列接受和 `SendInput` 成功提交不能证明目标应用已渲染操作。

独立原生线程处理键盘和系统通知，不注入输入或等待输入线程。显示/设置/会话消息及桌面切换 WinEvent 使其环境失效。快捷键重配置和关闭触发可等待事件，因此监听器无需周期枚举桌面。输入线程保留对外部失效标志的有界授权重检，不依赖前端计时器检查两秒心跳期限。宿主不把普通本地输入或空闲时间作为中断信号；使用本机（包括 Weblink 窗口）不会中断远控或阻止本地批准。明确撤销和紧急快捷键结束同意。清理按逆序释放该 grant 记录的按下，忽略没有匹配的远程 key/button release。扫描码区分 extended 键；提交 Unicode 文本有界，不能混入按住远程键。Pause/PrintScreen 不在扫描码白名单。

显示/会话通知、输入桌面不可用或物理显示清单变化会关闭线程。设置通知重新检查真实桌面/布局，不无条件关闭。需要重启并重新同意，解锁绝不恢复 grant。正常退出清理后 join。系统释放失败报告为失败，而非成功撤销；进程强杀及不可用/安全桌面的清理不受进程内所有权保证。`SendInput` 遵循 Windows [UIPI 限制](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-sendinput)，不提供提权或登录屏幕控制。

在交互式 Windows 会话运行 `cargo run -p weblink-desktop-input --example input_self_test`。测试创建自身窗口，要求前台所有权，将指针注入限定在该窗口客户区，并在销毁窗口前关闭原生线程。Windows 拒绝激活时，30 秒内点击测试窗口，探测期间保持键鼠空闲。探测检查真实窗口事件和清理；模拟生命周期/其他来源输入不能替代实体设备、锁屏或崩溃验收。

桌面库默认忽略的 `browser_pointer_attended` 通过 `WEBLINK_CONTROL_TEST_DIR` 与使用生产 `RemotePointer` 接收器的浏览器交换 SDP/ICE 及测试结果。本地测试所有者只批准受守卫保护的测试会话，不要求实体点击证据。测试须显式启用，注入仍限制在自身前台测试窗口。设置 `WEBLINK_CONTROL_TEST_TOUCH=1` 启用原生触摸断言，浏览器驱动必须执行多点触摸、移动、抬起和取消。接收器检查 `WM_POINTER*` 消息及 `PT_TOUCH`，不从鼠标事件推断。

## 原生屏幕接收 {#native-screen-reception}

Windows 桌面可通过原生 libwebrtc 接收一个当前 trickle-ICE 屏幕会话。运行时能力发现添加已安装的 Media Foundation H.265 Main 8-bit 和 H.264 解码器。D3D11 设备暴露匹配 NV12 decode profile 时，VP9/AV1 使用 MF，否则仍可使用内置原生软件解码器。VP8 使用 libvpx。HEVC 取决于已安装 Windows 解码器及驱动，实际探测而非按 GPU 名称推断。该 factory 按需启用，不改变发布端 factory。

应用在回复 SDP 前选择原生接收器，将 RTP、ICE、解码统计及两个已认证控制 DataChannel 保留在原生层。既有 video 元素携带尺寸/生命周期轨道，视频区域由 WebView2 下方原生 D3D11/DirectComposition surface 呈现；HTML 控件、远程输入坐标和布局仍在现有组件树。音频解码为有界立体声 PCM，通过 AudioWorklet MediaStream destination 播放，保留既有静音、音量和播放所有者。浏览器自动播放策略仍生效，用户交互恢复挂起音频。

### 会议媒体 {#meeting-media}

浏览器对端直接向 Windows 房间对端发送普通 WebRTC 轨道。Windows 上 WebView2 采集本地摄像头/麦克风，将帧和 PCM 传给各观看者共享的原生媒体来源。远程轨道使用既有硬件/软件解码器、GPU 渲染器及音频播放路径。关闭摄像头保留连接上的麦克风和其他轨道；撤销接收权限释放受影响远程输出。

### 平台边界 {#platform-boundaries}

`packages/platform` 拥有接收、呈现绑定及录制契约，Web 应用不导入 Tauri/GPU API。其媒体流可携带真实视频像素，或绑定原生 surface 的生命周期轨道。桌面适配器负责该区别、音频播放及页面布局观察。呈现 IPC 边界只传不透明 source ID 和已验证布局。

Tauri 的 `receive` 和 `presentation` 模块按目标配置选择后端。Windows 提供实现，不支持的桌面目标不暴露原生接收编解码器，保留浏览器接收。Windows 解码失败仍留在原生路径。未来平台应在自身解码和呈现路径均可用后才声明格式，保留此区分。

新桌面平台可以先使用 WebView 的 `RTCPeerConnection` 和普通 video 元素接收，复用信令、编解码器协商、控件及录制路径，无需先实现原生解码或合成器。只协商该 WebView 报告的格式，不假设 HEVC 支持。原生发送和接收是独立能力，因此可先实现原生采集/编码，再补原生接收。

当前 `desktop-capture` 的 receive、surface 和 presentation 模块限 Windows。D3D11 纹理租约、DirectComposition target 和录制回读池是后端细节，不是可移植 GPU 接口。添加后端时按平台拆分内部实现，保留 source-ID、生命周期和录制契约。各后端必须保留有界最新帧准入、直到 GPU 完成的帧所有权、明确录制需求及确定性拆除。本地预览和接收视频仍须共用呈现器；其他平台在声明原生能力前需要自己的集成和生命周期测试。

### GPU 呈现与录制 {#gpu-presentation-and-recording}

接收 factory 请求零播放延迟及 MF 低延迟解码。按需 GPU 模式发布带原始 MF sample 租约的不可变 D3D11 纹理。直到合成器 D3D11 完成查询结束前，完整帧而不只是纹理 COM 指针都保持存活。每视图一个 GPU 提交和可替换最新帧使队列有界。调整尺寸、隐藏和移除视图会保留进行中租约直到 GPU 完成，解码器关闭不能使读取者持有的纹理失效。

合成器等待来源/布局通知、GPU 完成事件和 swap chain 的 frame-latency handle，不周期轮询 GPU。每个消费的 swap-chain 信号准入恰好一次提交。低频设备移除看门狗只在 GPU 或 swap-chain 工作待完成时运行，空闲合成器休眠直到通知。隐藏/移除视图取消 swap-chain 等待，但保留进行中 sample 至 GPU 完成。视频处理器输入 view 按纹理和 subresource 缓存，每视图最多 16 项和四个不同纹理分配；缓存持有 COM 资源，不持有解码 sample 租约。创建替代 view 前先淘汰分配，缓存 miss 不临时超限。软件上传获取池化纹理租约后使用同一缓存。输出 view 复用 swap chain 逻辑 back buffer。设备或尺寸变化重建缓存，裁剪/色彩变化仅更新受影响处理参数。重建 swap chain 时保留之前呈现图像，替代链只有首次成功 Present 后才附着，内容、变换和裁剪在同次 composition commit 修改。帧准入或另一视图布局提交不能暴露尚未呈现的替代链。

本地预览和原生接收共用窗口所有的合成器。预览复用编码采集池和 GPU 转换，包括旋转、光标及色彩处理，仅显示预览不请求 CPU 像素。硬件接收直接使用解码纹理；原生软件解码上传输出到同一合成器，不经过浏览器解码。各来源使用自身 D3D11 设备，composition 树包含其 swap chain。软件上传池复用一个 CPU NV12 打包缓冲及最多四个纹理，包含旧尺寸尚未归还租约。NV12 输入避免 I420 转换，其他软件格式使用编码器 SIMD I420-to-NV12 打包例程。纹理只有在最新帧、合成器和录制读取者释放完整所有者后才归还。耗尽时丢弃呈现工作，不排队或阻塞解码；尺寸/设备变化丢弃不兼容空闲资源和迟到归还。硬件解码保留直接纹理路径。Swap chain 将呈现队列限制为一帧。布局 IPC 只含已验证矩形及可见性，像素和原生句柄保持原生。视频区域遮罩页面背景和黑占位，保留 HTML 控件/对话框叠层。页面背景开口覆盖整个 video 元素，包括黑边，只有黑占位使用适配图像的切口，防止浅色背景出现在视频与黑边的小数像素接缝。全屏保持 backdrop 透明并隐藏底层页面，保留全屏元素内控件，原 tile 祖先不再裁剪 surface。原生画中画复用同一 WebView 和合成器；原生视频开孔活动时会议背景必须透明，由共享遮罩页面背景提供周围颜色，不遮挡 GPU 层。圆角裁剪遵循各容器 padding 边缘，包含边框厚度和动画变换；黑边内适配视频的角仍为方形。布局/淡入淡出变化复用活动背景 mask 及原生 clip 对象，每次合成器迭代一起提交最新布局。静态布局时几何观察休眠，resize、滚动、可见性、DOM 布局和明确 WAAPI 启动通知唤醒；只在相关运动未稳定期间逐动画帧测量。保留视频播放状态的成员变化保留原生绑定和 mask。黑色生命周期轨道在挂载、播放恢复和来源 resize 时刷新，独立于原生呈现及录制帧交付。未绑定的活动 surface 仍续原生租约，不周期处理像素。隐藏 surface 在首帧提供尺寸后停止给合成器和尺寸观察器发送帧通知，关闭/错误通知及独立录制需求仍活动；恢复可见立即刷新保留尺寸及最新帧。呈现统计在视图和接收诊断间共享待处理/近期 IPC 结果。隐藏或未绑定视图低频续期，独立接收心跳继续保护接收租约。原生窗口底层是不透明黑色。缩放预览和接收视图显式使用 GPU 线性插值，而非 DirectComposition 默认最近邻，不增加 CPU 回读或帧队列。视频操作菜单对浏览器视频、本地预览和原生接收使用相同半透明渐变；柔和 alpha 边缘及开闭透明度完全由页面渲染，不采样/模糊视频背景、不上传 mask 给合成器，也不触发静态帧原生重绘。呈现仍限偶数尺寸、最高 3840×2160 的 SDR 视频，不声明 HDR/Main10。

共享缓冲接收传输保留给原生 CPU 消费者和对比构建。事件驱动回读将映射 staging 纹理作为不可变 NV12 租出，消除 staging 到 NV12 的中间拷贝。有界池允许跨线程延迟释放，租约归还时恢复最新待处理帧，包括最终静态帧。水平裁剪保留打包兼容路径，因为行切片不得超出映射。两个只读 WebView2 槽流水处理原生打包和呈现，租约归还使用经过源/capability 检查的单向 Tauri 字符串通知。槽忙时合并新帧，不排队像素拷贝。

持久共享缓冲不能出现在 `VideoFrame` 的 `transfer` 列表中。Transfer 可能直接引用映射像素，构造后归还槽会损坏 Chromium 保留的帧。该传输依赖构造器独立像素快照。GPU 呈现避免两次共享缓冲拷贝，但不改变或削弱共享缓冲所有权契约。

每条入站房间视频轨道拥有自身解码输出和渲染 surface。屏幕发布从原生接收支持格式协商。原生屏幕启动、呈现或解码失败，会在当前应用会话排除该屏幕格式，自动发送端可协商另一原生格式；显式固定发送编解码器保留失败语义。MF 解码器连续接受输入但无输出时，先清空压缩状态，在现有连接请求新关键帧，恢复期间最后显示纹理仍有效。持续解码停顿或处理过载时，应用有界恢复策略重建原生接收器。Web 和其他平台保留浏览器接收，允许浏览器后备的平台适配器保留此前重试行为。原生接收在连续前台统计显示区间接收到解码处理延迟超过 250 ms、持续至少三秒时恢复，即使仍在解码帧。计数缺失/重置、采样空档及可见性变化重启观察窗口；浏览器仍仅因停顿恢复。录制明确打开原生 surface 的有界 CPU 回读消费者，各消费者一个进行中读取，每来源最多共用两个可复用 staging 纹理和 GPU 完成事件。完成唤醒异步读取器，映射使用 `DO_NOT_WAIT`，不让即时上下文阻塞等待 GPU。尺寸/设备变化替换不兼容空闲槽。关闭录制释放池所有权；待拷贝在完成前保留完整帧租约，即使取消后也如此。像素直接打包到拥有所有权的 IPC 响应，页面可能持有时不能回收。MediaRecorder 挂载后录制输入重放保留首帧，再用新时间戳稀疏刷新静态像素，不另做 GPU 回读；否则生成轨道会丢失挂载前帧，停止录制时可能得到空输出。每次录制读取等待来源通知及 500 ms 静态刷新期限，不按显示帧率轮询空帧。关闭和来源失败唤醒待读取；先注册再查最新帧，避免竞态发布丢失。活动录制仍最多每秒 60 次读取，并遵守 writer 背压。该池独立于发送端 **GPU 回读缓冲区**设置，后者仅控制需要 GPU→CPU 回读的发送路径，下次共享生效。录制提供真实像素，不录占位轨道，也不改变 GPU 显示路径。该后端不提供接收编码流直通。关闭、页面重载、应用退出及租约过期释放原生接收器、音频 sink 和共享缓冲。

原生入站视频报告包含 `nativeReceive` 诊断。GPU 模式报告解码/呈现帧数、CPU 上传次数、提交时解码帧年龄及原生提交耗时。共享缓冲模式保留线程、打包、租约和渲染器阶段计数及有界耗时摘要。详细自动化诊断只导出已知数值字段。这些是进程内耗时，不是端到端或物理显示延迟。占位视频的 `requestVideoFrameCallback` 不测量原生 GPU 呈现；比较两条路径必须观察相同真实显示边界。

## 接收端视频质量 {#receiver-video-quality}

每个观看者可在设置 → 媒体 → 接收质量降低自身流的分辨率、帧率及码率上限。接收默认值保存在本地，适用于当前及未来入站发布，独立于本地采集设置。每个入站视频显示实际限制，发布端设置仍是总上限。无需输入控制，不改变采集同意、房间可见性、其他观看者或本地录制。默认遵循发布端分辨率及带宽自适应，自动 FPS 还遵循接收显示器稳定前台呈现节奏。后台调度空档及视频内容 FPS 不是显示刷新率测量。浏览器保留当前屏幕几何和缩放下持续确认的最高节奏，不因动画回调变慢降低限制。可见性变化保留校准，屏幕几何/缩放变化开始新校准。此后备方式无法区分暴露相同屏幕属性的显示器，因此仍提供手动 FPS 限制。

质量发现、请求及回复共用已认证 desktop-media 通道。来源声明边界和当前传输身份，请求有界、合并并针对该传输检查。未声明边界的旧对端忽略接收默认值。请求及实际限制属于各发布，重连或开启另一发布复用观看者保存的接收默认值。

浏览器发送端只调整自身 RTP 编码参数。Profile 匹配的原生硬件消费者共享编码器，profile 变化先预热再替换观看者输出，失败保留旧输出。缩放和帧准入按编码组执行，输入控制坐标仍相对来源显示器归一化。帧率限制是最大值，不保证静态内容或受限网络产生对应帧数。

## Windows 验收 {#windows-acceptance}

在 Windows 设备验证安装/启动/重开、关于版本、加入房间、聊天、文件选择/拖放/下载、剪贴板、摄像头/麦克风及受支持屏幕共享。测试媒体权限拒绝、断开/重连、最小化/恢复、媒体使用期间关闭及第二实例启动。确认退出后全部应用进程结束且活动采集停止，外部链接在浏览器打开，Web PWA 更新不会替换桌面资源。

构建、宿主测试和普通 Chromium 运行不能证明 WebView2 媒体、GPU 采集、远程输入或安装器验收通过。
