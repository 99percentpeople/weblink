# 本地文件存储

Weblink 通过 `packages/platform` 中的 `VfsVolume` 契约挂载存储。Web 应用提供 IndexedDB 与浏览器目录 provider；桌面端通过 `PlatformRuntime.filesystem` 提供原生 provider。Tauri 导入和主机路径留在 `apps/desktop`。

## 面向业务的存储契约 {#business-facing-storage-contract}

`libs/domain/file-storage.ts` 定义存储服务契约，具体实现在 `libs/infrastructure/vfs/file-storage.ts`，原来的 application 导入路径作为兼容入口保留。文件与传输使用方通过 `ChunkCache` 完成创建、已提交分块、续传范围、验证、完成与清理，不解析存储 ID，也不解析物理路径。

服务的 `list()` 和 `synchronize()` 将所有 provider 合并为统一目录。同步返回当前 ID 与已确认的移除项。已提交的 IndexedDB 字节以及元数据的发布、删除都会跨连接使目录失效。目录扫描失败时，provider 保留上次成员集合；目录项与部分检查点仍从文件重建，不另存持久目录索引。

释放引用和显式删除来源是不同的生命周期操作。释放时，存储实现保留用户所有的完整文件；显式删除会验证选中的来源版本。确认文件不存在后释放本地文件库保留引用，但聊天、共享引用保留其内容身份。权限丢失或旧数据迁移失败不能作为清理依据。

文件元数据暴露 `capabilities`，包括保存模式、内联保存呈现方式、reveal 能力，以及实际挂载 ID。引用从其底层缓存获取这些值，不受当前默认存储影响。UI 操作基于这些能力调用 `cache.reveal()`，无需接收文件系统句柄或路径。打开、预览仍通过共享的、感知平台能力的文件打开器。只有存储设置负责选择和配置具体 provider。挂载点声明 `canOpen`，通过同一服务的 `storage.openDirectory(id)` 打开根目录。

## 默认位置与既有文件 {#defaults-and-existing-files}

- Web 默认使用浏览器存储。在“设置 → 传输 → 文件存储”中，支持 `showDirectoryPicker` 的浏览器可以挂载目录，并选择它保存新文件。目录选择器要求安全上下文和用户手势。
- 桌面端默认使用 `app_local_data_dir()/files`，也可通过原生选择器挂载其他目录。
- 设置将存储方式与具体目录分开选择。IndexedDB 模式隐藏目录控件；本地目录模式以只读文字显示当前位置，通过目录选择器更换。桌面端使用注册的挂载 ID 在系统文件管理器打开目录；Web 端打开文件缓存。只有不可用的浏览器目录显示重新连接操作。
- 目录文件直接以原文件名保存在挂载根目录下。已有名称会保留，冲突时依次使用 `name (1).ext`、`name (2).ext` 等。未完成接收在完成前使用 `name.ext.part`，列表和传输元数据保留原文件名。应用写入器按挂载点串行分配名称和最终提交，同时预留临时、最终名称，并在完成时再次检查新冲突。
- 只有浏览器挂载目录会对返回 `Name is not allowed` 的文件名编码为 `name.ext.weblink`；普通可接受名称保持不变。列表、下载与传输元数据展示原名称。在此类目录中，`.weblink` 保留为存储后缀，扫描会精确移除一个该后缀，包括外部加入的文件。导入名称原本就以此后缀结尾时，再加一个 `.weblink` 转义，让重新加载时无需文件索引也能还原原名称。原生目录和 IndexedDB 不编码、解码这些名称。
- 更改默认存储会选择新对象的目标和文件缓存中显示的存储。打开的缓存列表跟随选中挂载点，并清除上个挂载点的选择；活动传输、文件库别名与已有文件仍保留原挂载点。
- 旧生产版本的逐文件 IndexedDB 数据库会在启动时自动迁入统一 IndexedDB VFS，保留 ID 与已提交续传分块。应用级提示展示迁移、验证进度。只有新副本通过回读验证并提交元数据后，才删除旧数据库；失败文件保留旧库，等待下次启动重试。恢复和并发规则见[缓存与迁移](cache-assembly.md)。开发中间版本的 VFS 目录索引与格式不迁移。
- 真实目录没有持久文件列表或独立检查点记录。应用设置、目录句柄、聊天引用、内容指纹和显式共享权限仍是应用元数据。清除这些元数据不会删除目录字节或文件内的续传信息，但浏览器目录需要重新挂载、授权。

挂载的真实目录在启动和收到变化通知后递归扫描。已有或外部加入的文件自动出现在文件缓存中，不需要把字节复制到其他目录。编辑、重命名会替换目录项版本；删除会移除其本地保留引用。未变化的目录项无需磁盘索引即可跨重新加载保留 ID。缓存列表先按当前存储限定范围，再对内容引用分组；切回原目录会恢复其列表。共享文件与发送选择器仍可访问跨挂载点保留的文件。
列表是目录读取结果在内存中的投影。文件自己的尾部结构标记未完成传输和目标长度；预分配不能证明进度。完整文件的目录身份由挂载点、相对路径与修订号派生。传输完成时，现有内容引用保留该身份，不持久保存目录文件索引。

桌面文件缓存中的独立“打开目录”按钮在系统文件管理器中打开原生挂载目录；挂载多个根目录时可选择。Web 不显示此操作。两种平台都保留文件缓存对话框及未完成传输列表。显式导入文件会在选中的存储位置创建不可变内容快照。扫描或挂载目录不会自动向 peer 共享文件。用户从文件缓存显式删除时也会删除被索引的源文件；释放附件、去重和后台清理不会删除源文件。

## 接收与恢复文件 {#receiving-and-recovering-files}

接收方先预留逻辑载荷长度，再向 `chunkIndex * chunkSize` 写入分块。IndexedDB 使用固定大小数据页实现稀疏文件；原生文件使用 `set_len`，浏览器文件使用 `truncate` 和定位写入。逻辑长度不保证已预留相同数量的物理磁盘空间。

真实目录中的同一个文件同时保存载荷与尾部结构：

1. 载荷占据正常偏移，包括尚未写入的范围。
2. 固定位置的表记录每个已提交分块及其 BLAKE3 摘要。
3. 两个带校验和的元数据槽保存传输元数据和预期最终路径；更新中断时可回退到上一个有效槽。
4. 带校验和的 footer 标识格式、载荷大小和分块大小。

临时物理文件比目标载荷大，额外开销为 32 KiB、64 字节 footer，以及每个分块 36 字节。不需要旁路文件，也不需要 IndexedDB 文件或检查点行。Web 默认 IndexedDB 后端仍在该后端内部维护事务元数据与分块行。

有界的待写批次先提交，再提交文件内检查点。崩溃后，没有检查点的字节会重新请求。重新打开部分文件或发现外部修订变化时，会按载荷字节重新核对已提交分块摘要，包括合法的全零分块。元数据损坏会让文件不可用，不会把预分配字节当作已完成内容。

所有分块齐备，并且已提供的预期内容指纹验证匹配后，完成过程会移除 `.part` 后缀和尾部结构。例如 `report.pdf.part` 变为 `report.pdf`；被浏览器拒绝的文件名使用 `library.dll.weblink.part`，最终变为 `library.dll.weblink`。传输期间若最终名称被其他文件占用，会保留那个文件并重新分配空闲名称。
原生目录先以不替换已有目标的方式移动文件，再截断尾部结构。浏览器目录将载荷流式写入最终文件、验证已提交字节，然后才删除临时文件；这种回退在完成期间需要同时容纳两个文件。发布失败时，临时文件保留全部检查点。其带校验和的元数据也支持在移动或复制中断后重新打开；已经验证的完整副本会直接复用，不再次复制。目录扫描在等待清理时隐藏已验证的重复副本，并使用 footer 识别部分传输。文件提升为文件库内容之前仍须通过全内容验证。

活动存储服务按挂载点、相对路径和文件修订号共享全内容验证结果。最终提交、文件库发布、恢复扫描及后续引用可复用本地计算结果。原生移动和 Weblink 自己的尾部更新不会改变载荷，因此保留结果；新复制的目标必须单独验证。哈希前后的检查会拒绝版本变化，失败或取消的工作不发布结果。结果仅保存在内存，重启或外部修改后必须重新验证。持久化或 peer 提供的指纹只是比较目标，不能证明本地字节已经验证。

浏览器目录通过关闭 `FileSystemWritableFileStream` 提交写入。保留已有数据重新打开时可能复制整个文件，因此大文件性能与原生随机写入不同。标签页关闭后不能继续接收或监听文件。句柄可以跨重新加载保留，但权限可能要求新的用户手势。上传操作在打开选择器，或等待拖放文件读取、哈希之前，请求所选目录权限。恢复权限后先重新扫描目录状态，再复用内容。拒绝访问会停止导入。现有目录不可用时，不会静默回退并改变文件存储位置。

显式导入相同内容可以恢复不可用的保留副本。先在选定存储中写入并验证新字节，再更新内容的底层位置，保留现有附件 ID 和共享权限；修复不会删除旧目录文件。写入失败或取消会保留旧内容记录与引用，只清理新暂存副本。文件名相同不足以修复旧引用，必须完整内容指纹匹配。

接收去重将不可用的保留副本视为缓存未命中，但保留其引用和共享权限。新传输使用选中存储；验证后的接收字节可直接恢复这些引用，无需另复制载荷。实际接收目标的准备或写入错误仍会使传输失败，只有旧副本不可用则不会阻止接收。

向浏览器目录导入完整本地文件使用一个可写流：预留长度、按有界切片写入、最后只关闭一次。不会在写载荷前提交填零的可执行文件或文件内传输尾部。未完成的网络接收仍使用上述检查点格式。浏览器安全检查依然适用于目录访问和最终提交，失败时上传通知保留文件名、操作阶段和浏览器错误。只有文件名被拒绝才触发存储后缀；权限错误、写入或提交安全检查失败不会触发重试或更换后端。应用不会根据扩展名推断支持情况，也不会静默选用其他后端。

文件缓存导入拥有自己的取消控制器和进度提示。关闭或重新打开缓存对话框不会停止文件读取、文件夹打包、权限完成或存储写入；用户仍可通过提示取消当前和剩余工作，每次单独启动的批次相互独立。紧凑进度条按文件大小加权，跟踪读取、写入和验证字节，为每个阶段预留一轮工作量。复用文件或无需验证阶段的存储，会在导入成功时完成未使用的工作量。等待文件夹打包时显示不确定进度，直到全部文件提交并发布前，批次都保持低于 100%。
失败写入保留原错误详情。导入错误显示文件名、大小、当前阶段、已完成文件数和原始本地错误、cause，包括原生错误字符串与浏览器读取错误。详情可直接从提示复制；运行时主动抛出的 `AbortError` 属于失败，不等同于用户取消。共享文件导入仍采用视图范围的取消行为，防止切换成员后迟到结果发布到错误的共享列表。

已经由文件库引用拥有的目录扫描项会从文件缓存投影中隐藏。未变化的文件快照与 keyed 列表行会复用，避免同步时重建缩略图 URL。目录清单忽略以 `.` 开头的名称及其整棵子树，也忽略 Chromium 的 `.crswap` 事务文件。过滤在打开文件或遍历隐藏目录之前进行，不删除其内容。浏览器交换文件增长期间，录制草稿仍作为一个未完成条目显示。

## 变化通知与文件访问 {#change-notifications-and-file-access}

IndexedDB 使用本地通知和 BroadcastChannel；原生目录使用操作系统通知并定期刷新；浏览器目录优先使用可用的观察器，否则扫描元数据，包括窗口重新获得焦点时。事件只是失效提示，不是权威操作日志。观察器随所属存储服务或页面销毁。

目录协调仅在扫描成功后提交成员集合。扫描失败、根目录断开或权限丢失会保留上次内存列表，并将无法访问的文件标为不可用；重新连接后恢复访问。成功扫描确认不存在的文件会从缓存列表消失，包括由保留聊天引用支撑的项，重新加载后也保持隐藏。权限丢失与确认删除分开处理；仍然存在的未完成文件继续可见，以便续传。

确认删除或替换后，按引用 ID 和底层存储 ID 释放本地文件库保留引用，包括这两个 ID 不同的导入文件。启动时也会协调缺失的目录版本，移除没有任何剩余引用的内容记录，覆盖应用关闭期间发生的删除。聊天与共享引用保留内容身份。扫描失败或挂载不可用不能触发此清理；移除旧索引也不会删除同一路径的新替代文件。

目录文件被编辑或删除时，已发送、共享引用保留原内容身份并变为不可用，不会在旧指纹下提供已变化字节。新目录版本可以立即选择，并在发送、共享时计算指纹。如果重命名或重建文件经验证具有相同字节，可无需复制就恢复现有引用。受管理的传输文件继续使用检查点和不可变内容检查。从磁盘重建目录状态后，必须匹配保留引用的内容哈希，才能在现有内容身份下复用字节。

`StoredFile` 允许有界范围读取和流式读取，无需先物化 JavaScript Blob。原生媒体使用不透明、页面范围的 capability URL 和 HTTP Range 响应。原生读写通过有界二进制 IPC 完成。原生操作只接受相对于已注册根目录的路径，拒绝路径穿越和符号链接逃逸，绝不接受调用者提供的无限制主机路径。

桌面文件打开操作使用系统默认应用。会话图片、视频缩略图在两种平台都使用 PhotoSwipe，音频保留内联播放器，这些媒体气泡不显示重复的打开按钮。原生目录文件气泡也不显示另存为按钮，但右键菜单保留另存为。每条消息最多有两个操作按钮，包含相邻的房间重试按钮；气泡优先展示打开、预览和传输控制，其次才是保存。房间文件详情从右键菜单打开，保留每位接收者的进度与控制，其他文件操作也留在菜单中。
原生文件验证文件能力凭据及修订号后，直接打开原路径。旧 IndexedDB 文件会流式写入临时副本再打开，不显示保存对话框；编辑临时副本不会改变 IndexedDB 内容。Web 文件操作继续使用应用内预览。新选文件发送前仍有独立的发送确认步骤。

文件菜单使用每个文件的实际底层存储，包括共享内容引用，不使用当前默认挂载点。IndexedDB 文件提供“保存到设备”，目录文件提供“另存为”。桌面使用系统保存对话框，支持的浏览器使用保存选择器并流式写入选定目标。取消选择器不改变源文件；浏览器不支持保存选择器时回退为浏览器下载。

批量另存为对整个选择只选一次目标目录，包括混合选择中的 IndexedDB 文件，不挂载该目录，也不改变默认存储。文件依次流式写入。名称冲突时询问覆盖、跳过或通过编号副本保留两者；“应用到全部”只在当前批次记住选择，取消冲突提示会停止剩余文件。目录及其他非普通文件不能覆盖。覆盖失败会保留原文件，只有新内容全部写入后才提交替换。浏览器文件名限制沿用挂载存储的 `.weblink` 回退。单文件菜单操作仍使用文件保存选择器。批次结束或页面重新加载后释放原生导出目录权限，复制失败会丢弃临时文件。

批量另存为使用紧凑进度提示显示当前文件名、写入字节数、已保存数和跳过数。名称冲突由单独确认提示暂停批次；进度仍可见，用户选择后恢复。后台冲突使用已有系统通知服务和传输通知偏好，打开提醒只返回同一应用内确认，不代替用户选择文件操作。已写字节可能尚未最终提交，只有已提交文件计为保存成功。
取消会停止后续文件，并在分块边界中止当前尚未提交的副本，保留此前完成文件及正在被替换的原件。已经开始的提交可能完成，并计入保存数。每个批次拥有自己的文件快照、取消控制器和提示。关闭或重新打开文件管理器不会取消保存，也不会关闭进度、冲突提示；对话框关闭后，已有及后续冲突仍可操作，用户通过任一提示取消。新批次的取消和冲突选择相互独立，不替换旧批次提示。

原生目录项和消息右键菜单还提供“打开文件位置”，包括未完成文件。操作解析当前挂载点相对物理路径，该路径可能含冲突编号或 `.part` 后缀，验证它位于注册根目录内，再要求系统文件管理器显示并选中文件，不打开或导出文件内容。IndexedDB 和浏览器目录不提供这一操作。

## 生成文件与录制 {#generated-files-and-recordings}

`FileStorage.createWritableFile()` 在选定挂载点创建未知长度的顺序输出会话，直到 `finish()` 或 `abort()` 前始终固定该挂载点；之后更改默认目录不会移动其字节。应用通过这一契约写入，无需选择具体 provider。已知大小传输继续使用原检查点及 `.part` 格式。启动生成文件只验证写权限和根目录可用性，不等待完整目录刷新。普通导入仍在复用内容前刷新身份，目录同步独立继续。

录制草稿使用 `.recording.part`，与可续传文件区分。草稿增长时目录身份稳定，空草稿也属于未完成。目录显示预期最终视频名，不显示物理会话 token 或临时后缀，发布前持续标为未完成。草稿不能预览、共享，也没有可续传范围。活动草稿不能通过文件库删除。中止会保留已提交草稿字节，但不保证视频可播放，也不保证崩溃后可恢复。

IndexedDB 通过事务提交有界数据页，并在元数据中发布完成状态；其 `StoredFile` 惰性读取范围并检查捕获的修订号。原生目录保留页面范围的文件句柄，通过有界二进制 IPC 追加，关闭时同步，并在不替换已有文件的前提下重命名。浏览器目录保持一个可写流直到关闭；关闭前写入可能不可持久保存或不可见，所以中止可能留下空草稿。
尚未提交的流数据块不会重新 stat 或发布未变化的草稿；录制进度来自写入器，目录更新只反映已提交变化。浏览器发布最终文件名需要有界流式复制，长时间录制可能有明显保存阶段。名称冲突通过编号后缀保留两个文件。

完成过程验证并注册现有存储对象，不重新导入字节。同一文件版本复用验证结果；原生重命名沿用该结果，浏览器复制则先验证新目标，再删除草稿。

`finish(patches)` 可以在关闭和验证前更新已有元数据字节。更新不能延长文件，最多 16 个范围、合计 64 KiB。浏览器目录对已打开的流应用更新，原生目录在保留句柄上定位写入，IndexedDB 提交受影响数据页。

## 单来源录制 {#single-source-recording}

录制属于应用生命周期，独立于视频块、菜单和文件缓存对话框。同一时间只能录制一个本地或接收来源。所选音轨混合为一条录制音轨，不加入其他参与者，也不产生额外可听播放。独立的私有静音音频使用方还会激活远端解码，不依赖会议音频播放器。

暂停、恢复保留同一个 MediaRecorder、来源连接，以及原挂载点上的 VFS 写会话。暂停只停止媒体收集，不停止共享来源轨道，也不提交输出。已接受的写入可在暂停时继续排空，目录中仍是一个未完成视频。经过时间与保存时长都不包含暂停区间。停止、来源结束或替换、离开会话也会保存暂停中的录制，包括最后一个 data 事件。暂停不会让草稿在重新加载或崩溃后变得可恢复。

`RecordingService` 优先选择支持的 WebM 格式，以 MP4 为回退，并按 recorder 实际 MIME 类型选择扩展名。MediaRecorder 事件进入有序写队列，待处理数据上限 32 MiB。编码器、存储错误或队列超限会停止会话，只保留已提交草稿。正常停止会等待最后一个 data 事件与所有已接受写入后发布。来源结束、替换和离开会话都会停止并保存；清理只释放录制拥有的资源，原始轨道继续运行。

MediaRecorder 的实时 WebM 输出可能缺少时长与 seek 索引。录制器在有界头部预留 Duration 和 SeekHead 空间；写入时检查块头，记录视频关键帧位置，不保留编码帧。正常停止会追加 Cues、填充 SeekHead，并按 TimestampScale 写入经过时长。Segment 保持未知大小标记，因为 recorder 的 Cluster 元素也可能使用未知大小。
索引少于 8192 项；超长录制会逐步稀疏化索引，同时在整个录制范围保留定位点。不重新编码媒体，不重扫完整文件，也不缓存整个录制。已有有限时长和带索引容器会保留，MP4 原样通过，不重写以前的录制。

本地原生屏幕录制会打开一个单独的只接收 WebRTC peer，附加到已有采集会话。它消费真实原生音视频，不依赖 UI 原始预览、静音占位轨道或可见性变化。关闭录制 peer 不会停止采集或其他共享 peer。

会议标题栏状态显示经过时间、已接受字节数、暂停、恢复和停止，沿用共享、控制状态的呈现方式；选中视频标签显示录制或暂停图标。写入、验证和发布期间持续显示保存状态。视图关闭不拥有也不停止录制会话。只有正常完成的录制才承诺是连续可播放文件；单个 MediaRecorder 分块及中断草稿不能视为独立可播放录制。
