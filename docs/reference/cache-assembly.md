# IndexedDB 文件缓存与迁移

文件传输在目录与 IndexedDB 两种后端上都使用 `VfsChunkCache`。IndexedDB 存储卷在 `weblink-vfs-v1` 中保存逻辑文件节点和稀疏的 256 KiB 数据页。文件元数据与已提交分块的哈希存于 `files`、`checkpoints`，文件内容存于 `nodes`、`pages`。

## 接收与完成文件 {#receiving-and-completing-files}

预留文件只记录逻辑大小，不写入填零数据页。只有已提交分块的检查点才计入进度和缺失范围请求。待写入数据有数量上限，并会建立快照，重复或乱序分块也遵循这一规则。数据页事务完成后，检查点才会推进。

完成时从已提交数据页重建供使用方读取的 File，不会再向 IndexedDB 写入第二份完整文件，也不会启动已经移除的组装 worker。P2P 协议、传输 ID 与缺失范围契约保持不变。目录存储与内容验证见[本地文件存储](file-storage.md)。

## 自动迁移 {#automatic-migration}

文件库打开前，存储初始化会发现旧 `file-*` 数据库并迁移至 IndexedDB VFS，不受新文件默认挂载点选择的影响。旧运行时缓存与组装 worker 已移除，只有迁移读取器仍理解旧格式。

每个文件保留存储 ID、文件名、元数据与已提交分块的索引，因此聊天附件、共享引用和文件库内容记录可以继续使用原有 ID。迁移支持完整 Blob/File 数据，以及包含 Blob 或 ArrayBuffer 分块的部分缓存，包括空洞和不足标准长度的末尾分块。

迁移按数据库逐个进行：

1. 升级旧数据库，在版本事务内重命名对象存储。此操作等待旧连接关闭，防止验证完成后旧客户端继续通过废弃的存储名称写入。迁移中断后，下次启动会识别已重命名的存储；源字节保持完整。
2. 使用上限为 4 MiB 的缓冲区复制到尚未发布的 VFS 数据页。旧 ArrayBuffer 分块仍需读取完整的 IndexedDB 记录。部分文件会预留逻辑大小，但只复制已提交分块。
3. 回读目标并比较 BLAKE3 摘要。完整文件如果已有指纹，也会验证该指纹，同时检查分块长度、断点检查点、文件长度及目标修订号。
4. 在一个事务内发布元数据和检查点，并再次检查已验证节点的修订号。文件仅在事务提交后可见。
5. 关闭源数据库并删除。只有删除完成才计为成功；如果最初被其他连接阻塞，也必须等待真正删除。

复制、校验或发布失败时，保留旧数据库并丢弃未发布的暂存数据。发布后的重试会验证并复用新副本，保留发布后额外接收到的分块。不会覆盖存储 ID 碰撞的无关文件。废弃暂存页会被回收，但不会删除已发布文件。

应用级提示显示当前文件名、复制与校验进度和文件数量。连接阻塞时会提示关闭其他 Weblink 页面。失败会保留错误详情，并在下次启动时自动重试。关闭文件缓存对话框不影响迁移。迁移期间暂时需要同时容纳旧数据和新副本；配额不足会保留原始数据。IndexedDB 事务完成代表存储操作成功，但不保证能抵御所有操作系统或硬件故障。

## 检查与基准测试 {#checks-and-benchmark}

`test:e2e:cache` 在 Chromium 中覆盖真实 IndexedDB 事务、封存源数据、连接阻塞、回滚、回读和重试。针对性单元测试注入配额错误、数据损坏、中断和目标冲突。传输冒烟环境使用 VFS 缓存执行真实 WebRTC 传输。

`bench:browser:cache` 分别测量分块写入、文件重建和已提交内容回读，计时不包括 WebRTC 与校验计算。它用独立计算的 SHA-256 检查导出字节，并报告剩余的断点检查点，VFS 会有意保留这些检查点。此基准不测量迁移，也不预测其他浏览器或设备上的耗时。命令与测试边界见[测试与验证](../development/testing.md)。
