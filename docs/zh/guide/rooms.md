# 房间与聊天

两端使用相同的房间 ID 和密码，选择便于辨认的显示名称即可。

## 加入房间 {#join}

1. 点击**加入房间**，填写名称与房间信息，再点击**连接**。
2. 另一台设备填写相同房间信息，或通过邀请加入。
3. 打开**成员**，等待对方连接，然后发送一条消息。

对方收到消息后就可以开始协作；未能收到时，按[连接检查](faq.md#connection)排查。

::: details 再次加入旧房间，或使用自建服务器

### 连接细节 {#before-you-start}

在**历史房间**中选中旧房间，再点击**连接**；需要修改保存的信息时，使用**编辑房间信息**。

使用自建服务时，在每台设备的[连接设置](connection.md#signaling)中填写相同 WebSocket URL。房间邀请不会携带自定义 WebSocket URL。

可选的**分享服务器给其他人**涉及 STUN/TURN 条目及其凭据，说明见[分享连接配置](connection.md#share-settings)。
:::

## 邀请别人 {#invite}

点击头像，选择**用户菜单 → 分享链接**，或打开**房间二维码**让另一台设备扫描。对方打开邀请后加入房间。

设有密码时，链接会包含房间密码，应发给希望加入的人。加入房间不会授予远程控制等[设备权限](device-trust.md#permissions)。

## 群聊或私聊 {#chat}

在**成员**中选择当前房间一行进入群聊，选择成员名称进入私聊。核对会话标题，输入文字并点击**发送**。

房间消息发给已连接的在线成员。后来加入的设备不会收到旧消息或附件信息，需要时重新发送。

### 发送文件 {#attachments}

在会话中选择**发送文件**。接收方通常还需要点击附件的传输操作，发送方应保持在线。进度与保存步骤见[文件传输](files.md#send-and-receive)。

## 离开与重新加入 {#reconnect}

完成传输并保存录像后，点击**离开房间**；返回时重新选择房间并连接。本地历史和保存的权限会保留，权限生效前仍需再次验证设备身份。

::: details 本地历史与多个页面的使用

### 哪些内容留在本机？ {#history}

历史属于当前浏览器或桌面配置，没有账号同步或服务器备份。

- 移除**历史房间**条目会清除入口和保存的密码，但保留聊天与权限。
- **清空聊天记录**移除本地会话记录；[删除文件](storage.md#cleanup)是另一项操作。
- 清除站点数据可能移除浏览器文件、历史、身份和设置。
- **历史成员**是本地仍保留私聊的旧成员，不代表当前在线。

同一浏览器配置、同一站点内，一个身份一次只能在一个页面连接同一房间。**切换到此页面**会结束旧页面的会议与传输。需要测试两个独立客户端时，使用不同设备或浏览器配置。

设备身份变化时，应按[重新配对](device-trust.md#repair)确认，名称相同不能单独证明身份。
:::

## 接下来想了解什么？ {#troubleshooting}

- **想传文件或让别人浏览选定文件**：使用[文件传输与共享](files.md)。
- **想通话或展示屏幕**：按[屏幕共享与通话](media.md)操作。
- **想决定另一台设备可以访问什么**：调整[设备权限](device-trust.md#permissions)。
