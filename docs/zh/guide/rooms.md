# 房间与聊天

通过房间连接在线设备，再选择与所有成员或某一台设备交流。本篇从加入房间开始，带你确认第一条消息送达。

## 加入前准备 {#before-you-start}

- 在每台设备打开 [Weblink](https://webl.ink) 或桌面端。
- 两端使用相同的 **WebSocket URL、房间 ID 和房间密码**。显示名称用于在界面中辨认设备，无需相同。
- 使用自建信令时，先在每台设备的[连接设置](connection.md#signaling)中填写地址。不同信令服务器上的相同房间 ID 不会让设备连接到一起。

房间没有密码时可以留空；设置了密码时，每位参与者都需要填写相同密码。

## 加入房间并确认连接 {#join}

1. **第一台设备**点击**加入房间**，在设置对话框中填写便于辨认的名称，继续到房间信息，填写房间 ID 和可选密码。
2. 点击**连接**。修改字段会保存配置，但需要连接后才会加入房间。
3. **另一台设备**填写相同的房间信息，或[打开邀请](#invite)。为这台设备选择便于区分的名称。
4. 两端打开**成员**，找到对方，等待连接和[配对](device-trust.md#pairing)完成。
5. [打开聊天](#chat)，发送一条简短消息，请接收方确认收到。

再次进入以前的房间时，在**历史房间**中选中它，再点击**连接**。需要修改已保存的信息时，使用**编辑房间信息**。

**成功的标志**：两端互相可见，接收方也收到了测试消息。出现成员只是第一步；消息仍无法送达时，按[连接常见问题](faq.md#connection)排查。

## 邀请其他人或设备 {#invite}

1. **已在房间中的设备**点击头像，打开**用户菜单**。
2. 点击**分享链接**复制邀请，或打开**房间二维码**供另一台设备扫描；二维码对话框中也可以**复制链接**。
3. **受邀设备**打开链接，核对房间信息并加入，再从原设备确认新成员名称已出现。

邀请包含房间 ID，以及已设置的房间密码，应发给希望加入的人。它**不会携带自定义 WebSocket URL**，使用自建服务时仍需让对方自行选用同一服务器。

连接设置中的**分享服务器给其他人**只涉及 STUN/TURN 条目，也可能将对应凭据放入链接，开启前请阅读[分享连接配置](connection.md#share-settings)。邀请本身不会授予远程控制等设备权限。

## 选择房间群聊或私聊 {#chat}

1. 在会议界面打开**成员**。
2. 群聊选择当前房间一行（**打开当前房间群聊**）；私聊选择对方名称（**与……私聊**）。
3. 输入消息前先核对会话标题。
4. 输入文字并点击**发送**；接收端打开对应会话，确认消息到达。

| 会话     | 谁会收到新消息？           | 常见用途                   |
| -------- | -------------------------- | -------------------------- |
| 房间群聊 | 当前房间中已连接的在线成员 | 与参与的所有设备一起交流   |
| 私聊     | 选中的那台设备             | 给单个接收方发送消息或文件 |

房间消息不提供离线队列。后来加入的设备不会自动收到之前的消息或附件信息，需要在其连接后重新发送。

## 发送附件并检查投递 {#attachments}

在会话中选择**发送文件**、**发送文件夹**或**从文件列表选择**，也可以将文件拖入聊天。发送确认时核对目标会话，再继续操作。

房间附件卡片表示文件信息已发布，接收方通常还需要发起传输。发送方应保持在线，并保留可读取的原文件。在房间文件的**查看详情**中检查各接收者进度，或打开**用户菜单 → 任务列表**。

**消息送达不等于文件传输完成。**继续按[发送端与接收端步骤](files.md#send-and-receive)下载、确认并保存文件。

## 哪些历史会被保留？ {#history}

聊天历史属于当前浏览器或桌面配置，不是服务器备份，也不会自动跟随你到其他浏览器或电脑。

- 离开房间会保留本地历史与设备权限。
- 从**历史房间**移除房间，会清除该入口和保存的密码，但保留聊天与权限。
- **清空聊天记录**会移除本地会话记录；清理文件是另一项操作，见[文件删除与存储](storage.md#cleanup)。
- 清除浏览器站点数据可能移除历史、设备身份、设置和浏览器存储中的文件。

房间的**历史成员**只列出曾加入房间、且本地仍保留其私聊会话的设备，不代表这些设备当前在线。

## 离开、重连或切换页面 {#reconnect}

1. 先完成需要保留的传输与录像，再点击**离开房间**。
2. 返回时选择已保存的房间并重新连接；设备验证身份后才会使用已保存权限。
3. 发送一条消息确认新连接。名称相同不能证明是同一设备，身份变化时按[重新配对](device-trust.md#repair)处理。

同一浏览器配置、同一站点内，一个身份一次只能在一个页面连接同一房间。另开页面时，**切换到此页面**会把连接转移到新页面，并结束旧页面的会议与传输。需要模拟两台独立设备时，使用两台设备或不同浏览器配置。

## 接下来想了解什么？ {#troubleshooting}

- **想发送文件并确认对方完整接收**：按[文件传输与共享](files.md)操作。
- **想与房间成员通话或展示屏幕**：使用[屏幕共享与通话](media.md)。
- **想决定哪些设备能访问文件或控制电脑**：调整[设备权限](device-trust.md#permissions)。
- **成员不出现，或消息无法送达**：按[连接检查](faq.md#connection)排查。
