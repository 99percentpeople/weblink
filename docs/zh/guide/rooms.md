# 房间与聊天

房间用于让在线设备发现彼此。设备使用相同的信令服务、房间 ID 和密码，才能在同一个房间协作。

## 加入房间与邀请设备 {#join}

1. 打开 Weblink，设置便于辨认的显示名称。
2. 填写房间 ID；需要限制进入时设置房间密码。
3. 在另一台设备填写相同信息，或使用房间邀请链接、二维码。
4. 等待成员出现并完成设备配对，再发送一条消息确认连接。

自建信令的用户先在**设置 → 连接**选择同一服务器。相同房间 ID 在不同信令服务器上不会把设备连接到一起。

只把邀请信息交给希望加入的人。邀请链接和显示名称不代替设备权限；进入房间也不会自动授权远程控制。

## 房间聊天与私聊 {#chat}

| 入口     | 接收对象           | 适用情况                   |
| -------- | ------------------ | -------------------------- |
| 房间聊天 | 当前在线的房间成员 | 多设备交流、分享消息和附件 |
| 成员私聊 | 选定的对方设备     | 单独交流、点对点传文件     |

房间消息面向在线成员，不提供离线消息队列。后来加入的设备不会自动同步旧消息或附件；需要时重新发送给当前成员。

历史记录保存在当前浏览器或桌面配置中。换浏览器、换电脑或清除站点数据后，不会从服务器自动恢复历史。

## 发送文件与查看进度 {#attachments}

在会话中选择或拖入文件，确认后发送。房间附件默认需要接收方点击下载；聊天中出现附件卡片，不代表文件已接收完成。

通过传输任务查看进度。房间文件可从菜单打开详情，分别检查各接收设备的状态。某个设备失败时，按该设备的任务状态重试。详见[文件传输与共享](files.md)。

## 离开、重连与多个窗口 {#reconnect}

离开房间会结束当前设备连接。重新加入后，设备仍需完成身份验证，再应用保存的权限。普通断开不会自动清除本地聊天和设备权限。

成员名称相同不代表同一设备。出现身份变化或不受信任提示时，按[设备配对与权限](device-trust.md#repair)确认并重新配对。

## 接下来想了解什么？ {#troubleshooting}

- **房间已经连通，想开始发送或共享文件**：继续了解[文件传输与共享](files.md)。
- **想决定每台设备可以访问哪些功能**：继续配置[设备配对与权限](device-trust.md)。
- **想理解投递应答和重复消息如何处理**：深入了解 [P2P 控制协议](../architecture/p2p-protocol.md)。
- **看不到成员，或消息发不出去**：前往[房间与连接常见问题](faq.md#connection)查找对应现象。
