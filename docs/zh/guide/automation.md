# MCP 与自动化

通过 MCP 客户端，可以发现 Weblink 设备、查看诊断信息，并在授权后操作本机或远程桌面。Windows 桌面端提供 HTTP MCP 服务；支持 WebMCP 的浏览器可将工具提供给浏览器内的客户端。

## 理解两个开关 {#switches}

在桌面端的**设置 → 自动化**中，有两个独立开关，默认均关闭：

| 开关       | 开启后的作用                                                      |
| ---------- | ----------------------------------------------------------------- |
| 启用 MCP   | 启动 MCP 接口，让持有本机令牌的客户端连接；不自动允许操作本机系统 |
| 启用自动化 | 允许经过授权的工具操作本机系统；不自动启动 MCP 接口               |

只想把本机作为入口连接其他设备，可以仅开启 MCP。设备发现、本机诊断和转发不要求开启本机自动化；本机截图、输入和命令等操作系统工具需要自动化开关。

## 连接桌面 MCP 客户端 {#quick-start}

1. 在 Windows 桌面端打开**设置 → 自动化**，启用 MCP。
2. 在“本地 MCP 令牌”中为客户端创建一个有名称的令牌，选择有效期。
3. 从创建结果复制连接配置或完整令牌，填入 MCP 客户端。完整令牌只在创建时显示一次。
4. 让客户端列出设备，确认能看到本机及已连接设备。
5. 如果需要操作本机，再启用自动化。

默认地址对应的服务配置如下；不同 MCP 客户端外层配置格式可能不同：

```json
{
  "url": "http://127.0.0.1:32100/mcp",
  "headers": {
    "Authorization": "Bearer <YOUR_MCP_TOKEN>"
  }
}
```

界面生成的直接令牌形式也受支持。优先复制界面给出的完整配置，避免遗漏请求头或使用错误地址。

设备列表调用示例：

```json
{
  "name": "devices.list",
  "arguments": { "target": "local" }
}
```

每个工具都需要明确的 `target`：本机用 `local`，远程设备用设备列表返回的 ID。不要把显示名称当作设备 ID。

## 操作远程设备 {#remote-devices}

1. 两台 Weblink 设备进入同一房间并完成[配对](device-trust.md)。
2. 在目标 Windows 桌面端开启自动化；仅查看诊断信息时不需要这个开关，目标也可以是浏览器。
3. 在 MCP 客户端列出设备，把目标设备 ID 用作工具的 `target`。
4. 目标端根据设备权限允许操作，或显示需要批准的请求。

远程目标不需要另外开放 HTTP MCP 服务。你连接的入口会通过现有设备连接转发，目标仍独立决定允许哪些操作。

需要输入操作时，先发现可共享的显示器来源并申请控制，再调用输入工具。可用工具及参数以客户端返回的工具列表为准；窗口共享不能替代可控制的显示器。

## 配置权限 {#permissions}

在目标设备的成员详情或**设置 → 客户端与房间**中配置自动化权限：

| 权限组     | 涉及操作                             |
| ---------- | ------------------------------------ |
| 读取与诊断 | 设备与流状态、截图、读取桌面界面内容 |
| 共享与控制 | 屏幕共享、流配置、键鼠输入、界面操作 |
| 终端与命令 | Shell 执行、输出读取和命令任务管理   |

每组支持询问、始终允许和拒绝，默认询问。通知中的“本次会话允许”只适用于当前连接；保存始终允许或拒绝则持续作用于该设备的对应权限组。

本机 MCP 令牌授权接入客户端，不会配对远程设备，也不能绕过目标端权限。有效令牌在本机自动化开启时可使用本机系统工具，不会为每个本机调用再弹远程设备审批。

## 管理令牌与监听地址 {#configuration}

为不同客户端分别创建令牌，便于识别最近使用情况和单独撤销。可编辑名称、有效期或撤销令牌；关闭 MCP 后仍可管理令牌。

过期或撤销会使相关调用失效。延长已过期令牌只允许后续新调用，不会恢复之前的任务。

“MCP 服务”设置可更改监听主机和端口，默认 `127.0.0.1:32100`。修改保存后，在下一次启用 MCP 时生效；按界面提示关闭再开启，并同步更新客户端 URL。

局域网客户端需要可达的监听接口和防火墙端口。使用连接地址列表中的具体 IP，不要把 `0.0.0.0` 或 `::` 当作访问地址。此接口提供 HTTP，不支持任意域名别名或内置 TLS；默认回环地址只供本机访问。

## 在浏览器中使用 WebMCP {#browser}

浏览器支持 WebMCP 时，在自动化设置中启用 MCP，再使用浏览器内的客户端调用工具。

浏览器不会启动 HTTP MCP 监听器，也不签发本地令牌。它可以查看本机诊断，或通过本地 WebMCP 客户端操作已连接且授权的桌面设备；浏览器本身不执行系统输入或 Shell 命令。

## 停止与撤销 {#stop}

- 关闭自动化：停止本机操作系统自动化、输入和命令任务；诊断和 MCP 转发仍可使用。
- 关闭 MCP：停止 HTTP 入口或浏览器工具注册，不等于关闭目标端已开启的自动化能力。
- 撤销令牌：取消该接入客户端的授权与相关任务。
- 拒绝远程设备权限：阻止对应设备或权限组继续访问。

需要立即停止主机输入时，使用[主机紧急停止快捷键](remote-control.md#permissions)。
