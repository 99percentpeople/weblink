# 设备配对与权限

配对用于确认当前连接的是已认识的设备，权限决定该设备可以访问哪些功能。显示名称、房间密码和 MCP 令牌各有用途，不能互相代替。

## 首次连接与以后重连 {#pairing}

第一次连接时，设备完成身份验证并保存配对记录，通常无需手动操作。之后重连会再次验证身份，再应用已保存的权限。

配对记录属于当前浏览器或桌面配置，不随账号自动同步。清除站点数据、使用新配置或换电脑后，另一端可能需要重新确认身份。不要只凭名称相同就认为是原来的设备。

## 查看与调整设备权限 {#permissions}

从成员详情打开权限，或前往**设置 → 客户端与房间**选择设备。权限按设备保存在本机，两端分别决定允许对方做什么。

| 权限         | 控制的功能                         | 初次配对后的默认行为     |
| ------------ | ---------------------------------- | ------------------------ |
| 接收内容     | 接收该设备的应用内容，如消息和文件 | 允许                     |
| 提供文件列表 | 对方浏览你主动共享的文件           | 允许；不自动共享全部文件 |
| 共享屏幕     | 向该设备提供屏幕内容               | 允许；不会自动开始采集   |
| 远程控制     | 对方操作本机显示器                 | 询问                     |
| 自动化权限组 | 读取与诊断、共享与控制、终端与命令 | 分组询问                 |

远程控制和自动化可按设备选择**询问、始终允许、拒绝**。自动化还要求目标端具备对应能力；操作系统工具需要开启自动化。详见 [MCP 与自动化](automation.md#permissions)。

## 处理权限请求 {#requests}

收到请求时，查看请求设备和操作内容，再选择允许或拒绝。自动化请求支持本次会话允许；始终允许或始终拒绝会保存对应设备、对应权限组的策略。

系统通知用于提醒或打开当前审批，单纯点击通知不会授予权限。请求过期、取消或连接中断后，旧通知不能继续批准；由对方重新发起请求即可。

## 身份变化与重新配对 {#repair}

出现身份不匹配或不受信任提示时，应用会停止受保护的内容访问和操作。先确认对方是否清除了数据、换了配置，或者确实换了设备。

1. 两端保持在线，打开该设备的权限页。
2. 一端请求重新配对。
3. 另一端确认当前设备可信后，在通知或权限页接受。
4. 等待两端保存完成，再检查权限并重试操作。

配对请求约 60 秒后过期，可在确认双方在线后重新发起。接受重新配对表示信任当前连接的设备并替换原身份判断，不是自动证明它就是旧设备。修复后重新检查需要保留的允许规则。

## 撤销与断开 {#revoke}

不再允许某台设备使用功能时，在设备权限中关闭对应开关或选择拒绝。正在共享或受控时，也可以从状态控件停止；紧急停止方式见[远程桌面](remote-control.md#permissions)。

普通断开会结束实时访问，但通常保留已保存的权限。下次连接仍需验证身份。身份校验失败后，仅重连或改成相同名称不会恢复授权，应先完成明确的配对修复。

## 接下来想了解什么？ {#troubleshooting}

- **想开始控制已经授权的电脑**：按[远程桌面连接步骤](remote-control.md#connect)继续操作。
- **想限制 AI 工具可以执行的操作**：继续配置[自动化权限](automation.md#permissions)。
- **想理解配对与恢复背后的身份验证**：深入了解[设备身份与授权](../architecture/device-trust.md)。
- **设备已配对，但内容仍无法传输**：继续检查 [WebRTC 连接](faq.md#peer-connection)。
