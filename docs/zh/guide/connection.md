# 连接设置与测速

先使用站点默认配置。需要接入自建服务、调整网络路径或测量两台设备之间的连接时，再按本篇操作。

## 先确定要修改哪项配置 {#before-you-start}

| 配置                 | 控制什么                 | 什么时候需要                 |
| -------------------- | ------------------------ | ---------------------------- |
| WebSocket 信令服务器 | 房间发现与建立连接       | 使用其他信令服务或自建后端   |
| STUN 服务器          | 发现可连接的网络地址     | 为当前网络配置地址发现服务   |
| TURN 服务器          | 无法直连时中继传输       | 为不能直接连接的网络提供中继 |
| 对端测速             | 已建立 WebRTC 连接的吞吐 | 设备连通后测量当前路径       |

信令服务可达，不保证对端连接一定可用。先确认两台设备能[加入房间并交换消息](rooms.md#join)。

切换服务前记下当前配置，并完成不希望被中断的传输或录像。点击头像打开**用户菜单**，即可进入**设置**。

## 选择信令服务器 {#signaling}

1. 获取服务的完整 WebSocket 地址，例如 `wss://signal.example.com`。
2. **每台设备**都打开**设置 → 连接 → WebSocket 信令服务器**。
3. 替换地址，确认没有格式错误提示；有效修改会自动保存。
4. 离开当前房间，再重新连接。新地址在下一次连接时生效，不会改掉已经建立的连接。
5. 两端使用相同房间 ID 和密码加入，发送消息和一个小文件，确认连接。

**成功的标志**：两端通过所选服务器找到彼此，并能交换内容。只修改一端的服务器，会让设备位于不同服务，即使房间 ID 相同也一样。

填写完整的 `ws://` 或 `wss://` 地址，不包含内嵌登录凭据、片段或 `room`/`pwd` 参数。HTTPS 网页连接远程服务需要 WSS；桌面端访问公网服务也应使用 WSS。`localhost` 和 `127.0.0.1` 指发起连接的设备，不代表另一台电脑。

恢复站点默认值时，点击**重置**，再退出并重新连接。现有网页或桌面端可以直接连接自己的信令服务，无需部署前端，组件选择见[自部署导读](../deployment/overview.md)。

## 添加 STUN 与 TURN 服务器 {#ice-servers}

打开**设置 → 连接**，使用服务提供方给出的地址与凭据配置。

1. 在 **STUN 服务器**或 **TURN 服务器**中输入一个条目，按 **Enter** 或点击**添加**。
2. 修改已有条目时，点击对应标签，编辑后保存；多条配置可以使用**批量编辑**，每行一项，再点击**保存**。
3. 在每台设备当前网络下，对配置列表运行**检查可用性**。
4. 修改条目后重新建立对端连接，再次交换消息与文件。

STUN 条目使用以下格式；实际使用时应选取已确认可达的服务：

```text
stun:stun.l.google.com:19302
```

TURN 条目以 `|` 分隔地址、用户名、密码和认证方式，示例中的值需要替换为自己的配置：

```text
turn:turn.example.com:3478|user|password|longterm
```

| 认证方式   | 填写内容                                                                         |
| ---------- | -------------------------------------------------------------------------------- |
| `longterm` | 服务提供方签发的 TURN 用户名与密码；临时凭据也使用此模式，到期前有效             |
| `hmac`     | 密码字段填写共享签名密钥，由客户端生成临时凭据；只用于可信任其持有该密钥的客户端 |

服务商 API 密钥不是 TURN 密码，不应填入这些字段或公开前端构建。站点后端提供 Cloudflare TURN 时，应用会自动获取临时凭据，普通用户无需填写服务商密钥。

**检查可用性**只检测当前设备能否使用列表中的服务。检查通过，不代表两台设备一定可以交换数据，也不证明当前连接实际走了 TURN；还应按下文验证新连接。UDP/TLS 地址示例和自建准备要求见 [STUN/TURN 导读](../deployment/overview.md#stun-and-turn)。

## 决定是否只通过中继连接 {#relay-only}

日常使用时，保持**设置 → 高级 → 仅使用中继服务器**关闭，让连接可以选择直连或中继。

需要测试或要求中继路径时：

1. 确认已手动配置或由后端提供可用的 TURN 服务。
2. 开启**仅使用中继服务器**，重新连接两台设备。
3. 打开目标设备的**客户端配置 → 会话信息**，检查**候选路径**是否为中继，并测试消息或文件。
4. 需要重新允许直连时，关闭该选项，再重新连接。

仅中继模式要求 TURN 凭据有效且服务可达。它不能修复缺失或不可用的中继，还可能阻止原本能直连的连接。

## 按需分享连接配置 {#share-settings}

房间邀请包含房间信息，但**不包含自定义 WebSocket URL**，需要另外告诉对方应选择哪个信令服务。

**设置 → 连接 → 分享服务器给其他人**可以将配置的 STUN/TURN 条目放入生成的邀请，包括 TURN 凭据。只有打算把这些条目交给接收者时再开启。关闭只影响之后生成的链接，已经复制出去的信息不会随之撤回。

## 测试当前设备连接 {#speed-test}

1. **两端**加入同一房间，等待连接与配对，并确认消息能到达。先完成或暂停文件传输、暂停通话，以减少干扰。
2. **发起端**打开目标成员的私聊，在会话标题栏选择**客户端配置**，进入**测速**。
3. 点击**开始测速**。
4. **另一端**在批准请求中选择**同意测速**，也可以通过**用户菜单 → 任务列表**处理请求。
5. 等待**本机 → 对端**与**对端 → 本机**完成，查看两个方向的结果；需要提前结束时点击**停止测速**。

**成功的标志**：测速完成，并得到两个方向的结果。每个方向最多发送 **10 秒或 64 MiB**，先达到任一条件就停止发送；双向合计最多 128 MiB 有效载荷，另有协议开销。当前路径经过中继时，也会消耗 TURN 流量。测速不会在文件库中创建文件。

关闭客户端详情或切换标签页不会停止正在运行的测速，可到**任务列表**查看或停止。离开房间或对端连接断开也会结束测速。

## 理解与比较结果 {#results}

结果是接收端确认的、当前 WebRTC 路径上的平均有效数据吞吐，不包含文件读取、压缩和磁盘写入；既不是宽带套餐速度，也不保证实际文件保存速度。

| 看到的情况                 | 如何理解                                     |
| -------------------------- | -------------------------------------------- |
| 两个方向速度不同           | 分别阅读两个方向，两端网络与处理负载可能不同 |
| 不到一秒就达到流量上限     | 重复测速比较，过短的样本可能不够稳定         |
| 实际传文件比测速慢         | 还需要考虑文件访问、压缩、存储写入和其他负载 |
| 会话信息中有浏览器带宽估计 | 将它视为估计值，不等同于测速页的实测结果     |

比较时让两台设备保持前台、使用相同网络，并减少其他传输或通话。修改 STUN/TURN 或仅中继设置后，先重新连接，再比较新路径。

## 接下来想了解什么？ {#troubleshooting}

- **想决定哪些服务由自己运行**：按[自部署导读](../deployment/overview.md)选择。
- **在中国大陆加入房间缓慢或失败**：按[信令可达性检查](faq.md#signaling-mainland)排查。
- **能看到成员，但消息、文件或媒体无法连接**：继续检查 [WebRTC 连接](faq.md#peer-connection)。
- **想理解设备发现与重连的过程**：阅读[信令与会话恢复](../architecture/signaling.md)。
