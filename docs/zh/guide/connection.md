# 连接设置与测速

### 修改前 {#before-you-start}

普通使用保留站点默认值即可。需要其他服务器或中继时，从头像的**用户菜单**打开**设置**。WebSocket 服务帮助设备发现彼此，数据连接是另一环节。

## 更换信令服务器 {#signaling}

1. **每台设备**打开**设置 → 连接 → WebSocket 信令服务器**，填写服务完整地址，例如 `wss://signal.example.com`。有效修改会自动保存。
2. 离开房间并重新连接以生效。两端使用相同服务器、房间 ID 和密码。
3. 发送消息确认新连接；**重置**可恢复站点默认值，在下一次连接使用。

重新连接会打断实时会话，先完成需要保留的传输与录像。现有网页或桌面端可以直接使用自己的信令服务。

::: details 地址要求与邀请链接

使用完整的 `ws://` 或 `wss://` 地址，不含内嵌凭据、片段或 `room`/`pwd` 参数。HTTPS 页面连接远程服务需要 WSS，桌面端访问公网也应使用 WSS。`localhost` 与 `127.0.0.1` 指发起连接的设备。

### 分享连接配置 {#share-settings}

邀请不包含自定义 WebSocket URL，需要另外告诉对方选择哪个服务器。

连接设置的**分享服务器给其他人**可以把 STUN/TURN 条目及凭据加入新生成的链接。只有打算分享这些信息时再开启，关闭不会撤回已复制的链接。
:::

## 按需配置 STUN 或 TURN {#ice-servers}

STUN 发现可连接的地址，TURN 在无法直连时中继数据。

在**设置 → 连接**的 **STUN 服务器**或 **TURN 服务器**中输入条目并按 **Enter**。点击已有标签可编辑；**批量编辑**时每行一项，再点击**保存**。

运行**检查可用性**，重新连接两台设备，再测试消息或文件。单个服务检查通过，还不能证明设备之间已经连通。

::: details 服务器条目格式与凭据

STUN 条目写法如下，实际使用时选择当前网络可达的服务：

```text
stun:stun.l.google.com:19302
```

TURN 示例中的地址、用户名和密码需要替换为自己的配置：

```text
turn:turn.example.com:3478|user|password|longterm
```

- `longterm`：填写服务方签发的用户名和密码，临时凭据也使用此方式，到期前有效。
- `hmac`：密码字段是用于生成临时凭据的共享签名密钥，只用于可信任其持有密钥的客户端。

服务商 API 密钥不是 TURN 密码。后端提供 Cloudflare TURN 时，客户端自动获取临时凭据。传输方式与部署选择见 [STUN/TURN 导读](../deployment/overview.md#stun-and-turn)。
:::

::: details 强制走中继，不允许直连

### 仅中继模式 {#relay-only}

先确认已配置或由后端提供可用的 TURN，再开启**设置 → 高级 → 仅使用中继服务器**并重连。在**客户端配置 → 会话信息 → 候选路径**中检查路径，并测试内容投递。

**没有可用 TURN 时，仅中继模式无法工作。**恢复允许直连时，关闭该选项并重新连接。
:::

## 测试当前连接 {#speed-test}

1. 两端连通后，打开目标成员私聊，选择**客户端配置 → 测速 → 开始测速**。
2. 对方在请求中或**用户菜单 → 任务列表**选择**同意测速**。
3. 等两个方向完成，或点击**停止测速**。结果反映这条连接，不是宽带套餐或磁盘保存速度。

**测速双向最多发送 128 MiB 有效载荷，另有协议开销**，走中继时也会产生 TURN 流量。先完成或暂停文件传输与通话。关闭对话框不会停止测速，可在**任务列表**查看或停止。

::: details 理解结果与比较网络

### 数字代表什么？ {#results}

每个方向最多发送 10 秒或 64 MiB，先达到任一条件即停止。结果是接收端确认的平均有效吞吐，不包含文件读取、压缩和写盘，也不会保存测试文件。

两个方向可以不同。过短的样本可重复测试；比较时保持前台、网络与负载条件相近。修改服务器或中继设置后，先重连再比较路径。

会话信息中的浏览器带宽估计不等于实测结果。离开房间或连接断开会结束正在运行的测速。
:::

## 接下来想了解什么？ {#troubleshooting}

- **想运行自己的服务**：从[自部署导读](../deployment/overview.md)开始。
- **加入缓慢或失败**：按[信令可达性检查](faq.md#signaling-mainland)排查。
- **能看到成员，但内容无法连接**：继续检查 [WebRTC 连接](faq.md#peer-connection)。
