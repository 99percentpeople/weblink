# 连接设置与测速

通常可以直接使用站点默认连接配置。需要连接自建服务、解决跨网络连接问题或判断当前链路速度时，再调整这一页中的设置。

## 选择信令服务器 {#signaling}

打开**设置 → 连接 → WebSocket 信令服务器**，填写浏览器或桌面端可以访问的地址，例如 `wss://signal.example.com`。有效修改会自动保存，重新加入房间后使用新地址；“重置”恢复站点提供的默认值。

同一房间的所有设备必须使用相同端点。HTTPS 网页和桌面安装版连接公网服务时应使用 WSS。其他设备不能使用你电脑上的 `localhost` 或 `127.0.0.1` 作为目标地址。

可以直接用现有网页或桌面端连接自己的信令服务，无需部署前端。先阅读[自部署导读](../deployment/overview.md)，选择需要的组件。

## 配置 STUN 与 TURN {#ice-servers}

STUN 帮助设备找到可连接的网络地址；TURN 在无法直连时中继数据。信令服务器可用，并不保证当前网络允许设备直连。

在连接设置中添加或编辑服务器条目，批量编辑时每行一个。STUN 示例：

```text
stun:stun.l.google.com:19302
```

已有 TURN 服务时，按自己的地址和凭据填写：

```text
turn:turn.example.com:3478|user|password|longterm
```

TURN 条目依次是地址、用户名、密码和认证方式，支持 `longterm` 与 `hmac`。用“检查可用性”检测当前网络是否能使用所配置的服务。

`longterm` 将填写的用户名与密码用于 TURN 认证，服务商签发的临时凭据也使用这种模式，到期后需要更换。`hmac` 模式下，密码字段填写共享签名密钥，由客户端生成临时凭据；仅用于你信任其持有该密钥的客户端，不要把服务商 API 密钥填进这些字段或公开前端构建配置。

UDP/TLS 地址示例、托管服务及自建 coturn 的准备要求，见 [STUN/TURN 部署导读](../deployment/overview.md#stun-and-turn)。

站点后端提供 Cloudflare TURN 时，前端会自动获取临时凭据，用户不需要在这里填写服务商密钥。自部署配置见[Server TURN 设置](../deployment/backend.md#turn)或 [Worker TURN 设置](../deployment/worker.md#turn)。

高级设置中的仅中继选项要求可用的 TURN。没有中继服务时开启它，会阻止原本可用的直连。修改网络设置后，重新建立连接再验证效果。

## 测试当前设备连接 {#speed-test}

1. 与目标设备加入同一房间，等待连接和配对完成。
2. 打开成员详情中的“测速”页并发起测试。
3. 对方批准后，依次测量上传与下载。
4. 查看结果；需要结束时使用停止操作。

测速会产生真实网络流量，双向合计最多发送 128 MiB 测试载荷，另有协议开销；如果当前连接经过 TURN，也会经过中继。它不会创建文件库中的测试文件。

关闭详情面板不会停止正在进行的测试；停止、离开房间或连接断开会结束测试。

## 如何理解结果 {#results}

结果反映当前 WebRTC 路径上的应用层吞吐，不等于宽带套餐速度或实际文件保存速度。磁盘写入、文件压缩、后台标签页、其他传输和设备负载都会影响体验。

对比测试时尽量保持相同网络、前台状态和负载。
