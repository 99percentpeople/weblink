# 远程桌面

使用手机或另一台电脑操作 Windows 电脑。下面分别说明**主机**（被控电脑）和**控制端**（你用来操作它的设备）需要做什么。

## 开始前准备 {#before-you-start}

| 设备   | 需要准备                                                                                    |
| ------ | ------------------------------------------------------------------------------------------- |
| 主机   | [Windows 桌面端](desktop.md)，保持运行并加入房间                                            |
| 控制端 | 手机浏览器、电脑浏览器或桌面端中的 Weblink                                                  |
| 两端   | 相同的 WebSocket URL、房间 ID 和密码；连接可用，且已完成[设备配对](device-trust.md#pairing) |

先互发一条聊天消息确认连接。第一次使用时，让主机旁有人负责批准请求。浏览器可以作为控制端，但不能接收远程鼠标、键盘输入来操作自身所在的电脑。

## 建立控制连接 {#connect}

### 主机：先共享需要操作的显示器 {#share-monitor}

1. 在底部会议控制栏点击**共享屏幕**。
2. 选择一个**显示器**并确认共享。需要让控制端听到系统声音时，在选择器提供音频选项的情况下同时开启。
3. 请控制端确认已经看到共享的桌面。

**窗口共享仅供查看**，远程输入需要选择显示器。共享显示器会让房间成员看到画面，但不会单凭共享就授予控制权。

### 控制端：申请操作权限 {#request-control}

1. 在会议区域选中主机共享的显示器，将其打开为主画面。
2. 点击悬浮按钮展开画面操作，选择**请求控制**。在小卡片上则使用对应卡片的操作按钮。
3. 等待主机批准；等待期间可点击**取消请求**撤回申请。

主机尚未共享显示器时，也可以从主机的成员卡片发起控制请求。这种请求会要求主机将**屏幕 1 及其音频共享给房间内所有成员**。需要先指定其他显示器时，按上面的主机步骤主动共享。

### 主机：批准后，两端一起确认结果 {#approve-and-check}

1. 阅读**允许远程控制？**提示，核对申请设备。
2. 本次使用选择**允许本次会话**，不允许则选择**拒绝**。更多批准选项中的**批准并加入白名单**会保存该设备的规则；已有允许规则可能让后续请求不再弹出批准提示。
3. 控制端确认出现**控制中**，主机确认出现**被控制中**。
4. 从控制端移动指针，并打开一个普通应用。电脑上打字前先**开启键盘控制**；手机上在画面操作中选择**打开键盘**。

**成功的会话应当既能看画面，也能发送输入。**共享的显示器用于映射指针位置，授权允许操作主机鼠标和键盘，不局限于某一个应用或显示器。点击系统通知本身只是打开请求，还需要选择批准操作才会授权。

## 鼠标、键盘与手机触摸 {#input}

| 你想做什么         | 操作方式                                                                         |
| ------------------ | -------------------------------------------------------------------------------- |
| 使用电脑键盘打字   | 在控制状态中**开启键盘控制**，键盘转发与指针捕获分别控制                         |
| 使用手机打字       | 在画面操作中选择**打开键盘**，选中远端桌面的文字输入框后使用手机键盘             |
| 使用手机移动和点击 | 使用触控板模式，单指移动、轻点点击；双指右键、滚动和缩放取决于触摸设置           |
| 返回控制端本机操作 | 按控制端的释放快捷键，默认为 **Ctrl+Alt+Shift+Q**；已批准的连接仍然保留          |
| 调整指针或触摸体验 | 在**设置 → 远程控制**调整本地指针/捕获模式、触摸速度、滚动方向、长按动作和采样率 |

失去焦点会释放当前输入；返回后根据需要通过控件恢复捕获或键盘转发。使用释放快捷键后，要重新开启键盘控制才能继续发送按键。

操作系统保留的快捷键和受保护界面不保证能远程操作。Windows 较高权限的窗口也可能拒绝来自普通权限应用的输入。

## 远程剪贴板与文件拖放 {#clipboard-and-files}

这两项功能**默认关闭**，并要求有效的远程控制授权。

- **在两端复制内容**：在**设置 → 传输**开启远程剪贴板同步。支持的文本、富文本、图片和文件类型取决于两端能力；可选择将剪贴板文件写入本机剪贴板或文件库，也可以关闭文件接收。
- **把本地文件复制到主机**：在同一设置区域开启远程文件拖放，然后把文件拖到远程画面中兼容的 Windows 应用上。文件夹会打包为 ZIP；目前不支持把文件从远程画面拖出到控制端的操作系统。

文件操作默认上限为 64 MiB，可调整为 1–512 MiB。只需要普通传文件时，无需建立控制会话，使用[聊天附件或共享文件](files.md)即可。

## 调整观看体验 {#viewing}

在画面操作中使用全屏或画中画；桌面端还可使用原生置顶窗口。

先使用自动编码。阅读文字时优先保证分辨率，观看运动画面时平衡帧率与码率。每次修改一个设置，连接无法支撑时降低帧率或分辨率。具体选项以及哪些修改需要重新共享，见[共享画质](media.md#quality)。

在流统计中检查连接和当前媒体链路，或运行[连接测速](connection.md#speed-test)。测速反映这两台设备之间的吞吐，不代表公网带宽。

## 结束会话或撤销权限 {#permissions}

| 你的目的               | 操作                                                            | 结果                                         |
| ---------------------- | --------------------------------------------------------------- | -------------------------------------------- |
| 暂时回到控制端本机操作 | 按 **Ctrl+Alt+Shift+Q**，修改过则使用自定义组合                 | 释放指针捕获并关闭键盘转发，保留已批准的连接 |
| 结束远程输入           | 在控制端画面操作或主机控制状态中点击**结束控制**                | 结束当前控制授权                             |
| 不再展示主机桌面       | 在主机对被控显示器点击**关闭画面**，或结束对应屏幕共享          | 停止该显示器的共享与控制                     |
| 在主机立即停止输入     | 按 **Ctrl+Alt+Shift+F10**，修改过则使用自定义组合               | 撤销远程输入，并停止相关自动化输入和命令     |
| 避免后续请求被自动批准 | 在**设置 → 客户端与房间**打开设备权限，将远程控制改为询问或拒绝 | 修改该设备已保存的规则                       |

结束控制后，检查屏幕是否仍在共享；不再需要展示时也要停止共享。离开房间会结束当前控制连接，但断开连接不会清除已保存的允许规则。

释放与紧急停止快捷键可在**设置 → 远程控制**中修改，以当前界面显示的组合为准。已保存规则与重新配对的说明见[设备权限](device-trust.md#permissions)。

## 接下来想了解什么？ {#unavailable}

- **想保存远程屏幕上的过程**：按[录制与保存](recording.md)操作。
- **想决定哪些设备无需再次询问就能控制主机**：检查[设备权限](device-trust.md#permissions)。
- **能看到成员，但无法完成连接**：按 [WebRTC 连接检查](faq.md#peer-connection)排查。
- **画面黑屏、卡顿，或没有声音**：分别查看[视频](faq.md#video)或[音频](faq.md#no-audio)排查步骤。
