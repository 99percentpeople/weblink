# 文件传输与共享

想把文件交给某个人或整个房间时，在聊天中发送；想让已连接设备自行浏览、选择文件时，使用共享文件列表。

## 传输前准备 {#before-you-start}

1. [加入同一房间](rooms.md#join)，确认聊天消息可以到达另一端。
2. **发送端**保留可读取的原文件及其存储位置。
3. **接收端**检查[新文件保存位置](storage.md#choose-storage)，需要目录授权时先允许访问。
4. 完成前保持两端在线。先传一个小文件，确认发送、接收和保存的整条路径可用。

## 发送并接收一个文件 {#send-and-receive}

### 发送端操作 {#send}

1. 打开房间群聊或目标成员的私聊，核对会话标题。
2. 选择**发送文件**、**发送图片或视频**或**发送文件夹**；也可以把文件拖入聊天，或使用**从文件列表选择**发送文件库中已有的文件。
3. 核对发送确认后继续。选择文件夹时，按提示将其打包为 ZIP。
4. 对方下载期间保持 Weblink 和原文件可用。房间附件可打开**查看详情**，分别查看每个接收者。

### 接收端操作 {#receive}

1. 打开对应会话，找到附件。
2. 尚未开始接收时，点击卡片上的传输操作，房间附件的操作名称为**点击传输**。
3. 在卡片或**用户菜单 → 任务列表**中查看进度，等待**保存 / 合并中**结束，任务显示**已完成**。
4. 预览或打开文件；需要额外保留副本时，使用[保存到设备或另存为](#save-and-preview)。

**成功的标志**：接收端已有完整文件，并能用合适的应用打开。附件卡片送达只代表文件信息已到达；群聊里某一位成员完成下载，也不代表所有成员都收到了文件。

出现**本地已有，已跳过传输**时，应用复用了可用的本地内容，无需再次下载。后来加入的设备不会自动收到旧附件信息。

## 自动接收房间中的小文件 {#automatic-downloads}

房间附件默认需要主动发起传输。希望自动接收新小附件时：

1. **接收端**从房间标题或房间会话菜单打开**房间信息与设置**，进入**房间设定**。
2. 将该房间的**允许自动下载文件**设为允许。
3. 在**设置 → 传输**中选择**自动下载文件大小上限**。
4. 请发送端新发一个未超过上限的文件，确认无需点击卡片就能完成传输。

大小上限由所有允许自动下载的房间共用。超过上限的文件仍可手动传输；开启后不会补下载历史附件。

传输设置中的**自动下载**是接收完成后保存文件的另一项选项，不能代替房间中自动开始接收文件的权限。

## 暂停、继续或停止任务 {#tasks}

打开**用户菜单 → 任务列表**，根据文件名和对端找到任务，使用当前状态提供的操作。

| 任务状态或目的         | 操作                                     |
| ---------------------- | ---------------------------------------- |
| 正在传输，希望暂停     | 点击**暂停**，保留原文件与已接收数据     |
| 已暂停或失败，需要继续 | 重新连接设备，再使用可用的继续或重试操作 |
| 不希望排队中的任务开始 | 从任务或附件操作中取消                   |
| 任务提供停止或取消操作 | 使用该操作停止任务，关闭面板不会停止它   |

断线后，房间附件需要回到原房间，确认发送者在线，并保持原文件与接收目录可访问。继续时会复用可恢复的已接收数据。

离开房间会中断当前连接。仍无法继续时，按[文件可用性检查](faq.md#file-unavailable)排查。

## 让别人浏览共享文件列表 {#shared-files}

### 提供文件的一端 {#share}

1. 打开**用户菜单 → 文件缓存**，这里就是本地文件库。
2. 导入想提供的文件，或选中列表中已有的完整文件，点击**共享**。
3. 在**设置 → 客户端与房间**选择接收设备，允许**提供文件列表**。

导入或接收文件不会自动共享；新发送的文件会自动共享，之后可选择**取消共享**。选择存储目录不会把其中所有文件自动开放给别人。

共享清单属于本机，**在不同房间共用**；已连接设备仍需有文件列表权限才能浏览，并不是每个房间都有独立清单。

### 接收文件的一端 {#browse-shared}

1. 打开**成员**，点击提供文件设备旁的**共享文件**。
2. 搜索或排序列表，选中文件点击**获取**；也可以多选后点击**获取选中项**。
3. 在**任务列表**跟踪下载，完成后从**文件缓存**打开文件。

**成功的标志**：接收端能看到选定的文件，并完成一次下载。共享列表下载不会额外生成聊天消息；取消共享也不会删除对方已经保存的副本。

## 接收文件保存在哪里？ {#storage}

浏览器默认保存到当前站点的浏览器存储，桌面端默认使用本地文件目录。**设置 → 传输 → 文件存储**决定新文件的位置。

更换默认位置不会移动旧文件、进行中的传输或录像。选择目录、恢复访问或寻找旧文件的步骤见[文件存储与管理](storage.md)。

## 预览并保存副本 {#save-and-preview}

从已完成的附件或**文件缓存**打开文件操作。

| 文件所在位置 | 操作                                         |
| ------------ | -------------------------------------------- |
| 浏览器存储   | **保存到设备**：导出副本                     |
| 本地目录     | **另存为**：在其他位置创建副本，保留原文件   |
| Windows 目录 | **打开位置**：在系统文件管理器中定位实际文件 |

桌面端也可以使用系统默认应用打开受支持的文件。应用内能否预览取决于文件类型与运行环境。

批量保存时，选中文件后使用可用的保存操作。批量**另存为**只需选择一次目标目录，同名冲突时选择覆盖、跳过或保留两份。取消会停止后续文件并保留已完成副本；关闭文件管理器不会取消后台保存。

## 接下来想了解什么？ {#troubleshooting}

- **想设置默认目录或释放存储空间**：按[文件存储与管理](storage.md)操作。
- **想在传大文件前测量当前连接**：运行[对端测速](connection.md#speed-test)。
- **想理解分块、续传与完整性校验**：阅读[文件传输协议](../architecture/file-transfer.md)。
- **附件不可用或保存失败**：查看[文件与存储常见问题](faq.md#files)。
