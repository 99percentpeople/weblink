# 视频统计与延迟口径

性能窗口提供同帧延迟、周期均值和连接探测。端到端延迟使用同一帧的采集与提交时间戳计算，浏览器视频元素与 Windows 原生 GPU 呈现统一以**提交合成**为终点。

## 查看统计 {#view}

在主画面的操作菜单开启**流统计**，可以在会议界面内拖动窗口，展开细项或复制统计。统计浮窗跟随主画面。

- 接收画面收起时显示帧率、接收码率，以及时间戳就绪时的端到端延迟。
- 本地画面收起时显示有数据的最慢接收端对应的**发送延迟**、本地帧率和总发送码率。浏览器逐帧测量到封包前，显示为**封包前延迟**。悬停查看接收端及统计范围，展开后按接收端区分。发送指标在发送方本机计算。
- 展开优先显示同帧的“接收延迟”和“呈现延迟”。RTT 是独立的连接参考。更细的缓冲、编解码、呈现等待和计数器保留在复制及诊断数据中。

### 时间点对照 {#pipeline-points}

| 变量  | 含义       | 说明                                                                                           |
| ----- | ---------- | ---------------------------------------------------------------------------------------------- |
| —     | 开始采集   | 设备或系统开始获取这一帧的图像。                                                               |
| **C** | 采集帧     | 本帧的采集时间戳。桌面端记录系统帧到达应用的时间；浏览器使用采集后端提供的 `captureTime`。     |
| **P** | 封包前回调 | 编码输出进入 RTP 封包前的回调，发送端在本机记录时间。                                          |
| **T** | 传输提交   | 这一帧的原始 RTP 标记末包交付传输层成功返回，桌面发送端记录时间。                              |
| **R** | 末包收齐   | 接收端收到这一帧的最后一个数据包。浏览器使用 `receiveTime`，桌面端取该帧所有包的最晚接收时间。 |
| **D** | 解码完成   | 解码器输出这一帧，桌面接收端记录其解码完成时间。                                               |
| **S** | 提交合成   | 这一帧交给合成器。浏览器使用 `presentationTime`，桌面端记录提交调用成功返回的时间。            |
| —     | 屏幕显示   | 系统完成合成，按屏幕刷新节奏扫描输出这一帧。                                                   |
| **X** | 预计显示   | 浏览器提供的 `expectedDisplayTime`，表示这一帧预计显示到屏幕的时刻，用于计算显示等待。         |

### 区间计算 {#pipeline-calculation}

**接收延迟 C → R**覆盖采集帧准备、编码、输出交付、封包、发送排队、网络传输和末包收齐。**呈现延迟 R → S**覆盖收齐后的组帧、缓冲、解码、纹理准备和提交合成。两段在 R 相接，相加得到同帧端到端延迟。

**编码处理位于 C → P 内**。“编码延迟”统计采样周期内，从编码处理开始到输出完成的每帧平均耗时；原生硬编包含输入格式转换和驱动处理。C → P 还覆盖编码前准备与等待、输出交付和回调调度。单独的编码延迟可在复制统计和诊断信息中查看。

图下方的**发送延迟 C → T**和**解码后延迟 D → S**分别标出发送端与接收端的逐帧分项，由桌面端记录。浏览器发送端记录 **C → P**，具体字段见[发送端逐帧计时](#sender-frames)。

S 之后进入系统合成、刷新和扫描显示阶段。浏览器用 X 表示预计显示时刻，**显示等待 S → X**描述从提交合成到该预计时刻的等待时间。

发送端在本机时钟上计算 C → P → T。接收端将 C 映射到本机时钟后，与 R、D、S、X 一起计算以下区间：

```text
endToEndMs = S − C
captureToReceiveMs = R − C
receiveToPresentMs = S − R
endToEndMs = captureToReceiveMs + receiveToPresentMs
decodeToPresentMs = S − D
displayWaitMs = X − S
```

各区间在同一帧的所需时间戳就绪、时间顺序有效后显示。界面提供数值和悬停说明，诊断字段记录来源及估算方式。周期均值用于观察阶段耗时变化，RTT 用于观察连接的网络往返时间。

## 同帧延迟 {#frame-latency}

| 指标名称   | 导出字段              | 起止区间                | 浏览器                                    | 桌面原生 GPU                                   |
| ---------- | --------------------- | ----------------------- | ----------------------------------------- | ---------------------------------------------- |
| 端到端     | `endToEndMs`          | C → S                   | `captureTime` → `presentationTime`        | WebRTC 映射后的采集时间 → 提交调用成功返回     |
| 接收延迟   | `captureToReceiveMs`  | C → R                   | 帧回调的 `receiveTime`                    | 该解码帧所有包的最晚接收时间                   |
| 呈现延迟   | `receiveToPresentMs`  | R → S                   | 包含剩余缓冲、解码、后处理与呈现调度      | 还包含 Rust 队列、纹理准备 / 上传、等待与提交  |
| 解码后延迟 | `decodeToPresentMs`   | D → S                   | —                                         | 该帧的 WebRTC 解码完成时间；是呈现延迟的子区间 |
| 显示等待   | `displayWaitMs`       | S → X                   | 浏览器估算                                | —                                              |
| 单帧解码   | `frameDecodeMs`       | 该帧的解码处理          | 浏览器 `processingDuration`，可含格式转换 | 解码周期均值见诊断                             |
| 呈现等待   | `presentationQueueMs` | 纹理发布就绪 → 开始提交 | —                                         | 是解码后延迟的子区间                           |
| 提交延迟   | `submitMs`            | 开始提交 → 调用返回     | —                                         | 是解码后延迟的子区间                           |

导出中的 `latencyEndpoint: "compositor-submit"` 标记统计终点。端到端与接收延迟通过跨端时钟映射计算，诊断中保留估算状态。本地预览提供帧率、呈现等待和提交耗时等本机统计。

同帧时间信息的有效期为 1.5 秒；隐藏、关闭、来源切换会重置采样。浏览器按帧的提交时间计算帧龄，桌面端在原生帧龄上加上读取后的经过时间。

## 发送端逐帧计时 {#sender-frames}

发送端按接收端分别统计同一帧的处理耗时，使用发送方本机时钟。C、P、T 对应前文的[采集帧、封包前回调和传输提交](#pipeline-points)。

| 平台   | 窗口主项   | 统计区间 |
| ------ | ---------- | -------- |
| 桌面端 | 发送延迟   | C → T    |
| 浏览器 | 封包前延迟 | C → P    |

**桌面发送延迟 = 采集到封包 + 封包与排队。**

| 分项       | 区间  | 包含处理                                                 |
| ---------- | ----- | -------------------------------------------------------- |
| 采集到封包 | C → P | 帧准备、编码前等待、编码、输出交付和回调调度             |
| 封包与排队 | P → T | RTP 封包和节奏控制排队，计时到原始末包交付传输层成功返回 |

逐帧样本有效期为 1.5 秒，窗口显示有效期内的样本，过期后留空等待更新。对比不同接收端或平台时，使用相同的 C → P 或 C → T 范围。导出字段、帧关联和采样频率见[发送端诊断](#sender-diagnostics)。

## 周期均值与包含关系 {#intervals}

WebRTC 计数器使用相邻有效快照的增量计算均值，并统一换算为毫秒。计数器建立基线后，在有新增样本的周期更新；计数器重置时重新建立基线。各均值按对应阶段的采样窗口和计数单位计算，用于定位阶段耗时。

| 指标     | 统计单位           | 起止范围                        | 包含关系                                             |
| -------- | ------------------ | ------------------------------- | ---------------------------------------------------- |
| 采编延迟 | 原生硬编的新捕获帧 | 捕获帧到达应用 → 编码输出       | 包含采集准备、编码等待和编码处理                     |
| 编码等待 | 编码帧             | 输入就绪 → 本轮编码处理开始     | 采编的子区间                                         |
| 编码延迟 | 编码帧             | 编码处理开始 → 输出             | 原生硬编从输入格式转换前开始计时，包含转换和驱动处理 |
| 发送队列 | **包数**           | RTP 封包器输出 → 交给 OS socket | 逐包发送排队的周期均值                               |
| 接收处理 | 解码帧             | **首包**到达 → 解码完成         | 包含组帧、接收缓冲、调度和解码                       |
| 缓冲     | 移出抖动缓冲的帧   | 首包进入缓冲 → 整帧移出         | 已包含在接收处理内，也与网络传输后续包的过程重叠     |
| 解码耗时 | 解码帧             | 送入解码器 → 解码完成           | 接收处理的子区间                                     |
| RTT      | 单次探测           | ICE/STUN 请求发出 → 响应到达    | 独立的连接往返时间                                   |

发送主项优先采用逐帧计时。旧式统计路径以采编均值加逐包发送队列均值，或编码均值加逐包发送队列均值估算发送处理耗时，使用 `sendLatencyBasis: "capture" / "encode"` 和 `sendLatencyState: "partial"` 标记。采编均值包含编码等待和编码处理。

窗口优先显示发送主项；采编、编码与发送排队保留在复制和诊断中，主项留空时展示可用细项。接收处理及其缓冲、解码子区间按包含关系说明。多接收端在相同统计范围内选择最慢值，各接收端行保留各自的逐帧完整区间、封包前区间或旧式估算。统计范围切换时，延迟曲线开始新的记录，帧率等历史继续保留。总码率为实际发送连接的码率之和。

## 统计范围 {#coverage}

接收延迟覆盖采集后的准备、编码、交付、RTP 封包、发送排队、OS 发送、网络传输和数据包收齐。呈现延迟覆盖末包收齐后的组帧、缓冲、解码到提交合成；原生的解码后延迟进一步记录解码完成后的帧交接、纹理准备、上传、排队和提交。

各平台按以下事件计时：

- 原生采集从应用收到 OS 捕获帧时开始，浏览器使用采集后端提供的时间戳。
- 原生呈现以提交调用成功返回为终点；后续依次进行 `wl_composition_commit`、GPU 完成、刷新和扫描输出。浏览器另提供预计显示时间。
- 编码组的 `delivery` 诊断统计向观看者和录制消费者交付输出的耗时。CPU 回读、驱动准备和输出等待按活动路径提供，资源持有时间及帧间隔用于观察资源占用和处理节奏。

## 时钟映射与估算 {#clocks}

接收端在本机单调时钟上计算同帧延迟。浏览器使用映射到接收方时钟的 `captureTime`；原生使用 WebRTC RTP/RTCP 捕获时间映射，再桥接到本机 `Instant`。接收与解码时间使用相同映射基准，桥接采用读取跨度在 2 ms 以内的时钟样本。

原生硬编以 WebRTC 单调时钟记录并提交采集时间戳。同步建立、字段就绪且时间顺序有效时，生成对应的延迟指标。网络上下行差异、时间戳精度和时钟映射共同影响估算结果。

原生静态重复帧使用重复输入的时间戳；采编均值使用新捕获帧。端到端描述每次媒体帧从采集到提交合成的交付耗时。

## 帧率、1% Low 与码率 {#rates}

呈现 FPS 统计合成提交，解码 FPS 统计解码输出。1% Low 使用最近十秒可见播放中已完成的帧间隔，取最慢 1% 间隔的平均值再求倒数。采样开始时初始值为 0，完成帧间隔后更新；播放器能力和估算状态通过界面及诊断字段说明。浏览器合并回调或有界采样时保留估算状态。

码率使用字节增量除以实际采样时长，目标码率和可用带宽描述传输预算。折线历史在采样间断处留白。复制与诊断保留计数器、历史、统计范围及原生细分数据，用于定位抖动和阶段耗时。

## 实现与标准 {#sources}

### 发送端诊断 {#sender-diagnostics}

复制与详细诊断保留 `sendFrame`、SSRC、RTP 时间戳和 `ageMs`。RTP 时间戳用于帧关联，耗时使用本机单调时钟，`ageMs` 表示样本帧龄。逐帧主项使用 `sendLatencyBasis: "frame"`，其数据来源和终点如下：

| 诊断字段              | 桌面端             | 浏览器                  |
| --------------------- | ------------------ | ----------------------- |
| `sendLatencyMs` 来源  | `captureToSendMs`  | `captureToPacketizerMs` |
| `sendLatencyEndpoint` | `transport-submit` | `packetizer-input`      |
| `sendLatencyState`    | `measured`         | `partial`               |

原始分项按同一帧的时间戳计算：

```text
captureToPacketizerMs = P − C
packetizerToSendMs = T − P
captureToSendMs = T − C
captureToSendMs = captureToPacketizerMs + packetizerToSendMs
```

原生按连接和 SSRC 关联帧。原始末包提交后生成一次完成样本并移除待匹配项，待匹配队列最多保留 512 项、十秒。浏览器复用编码 Worker，每 250 ms 至多发布一次计时快照，消息传递耗时计入帧龄。录制暂停时计时继续，连接关闭时释放观察者和 Worker。

### 代码与标准 {#source-references}

- 同帧计算：`apps/web/src/libs/domain/video-frame-latency.ts`、`video-presentation-stats.ts`。
- 发送逐帧计时：`apps/web/src/libs/domain/video-send-frame-stats.ts` 与 `rtp-encoded-media.worker.ts`；共享契约位于 `packages/platform/src/send-frame-stats.ts`，原生 SDK 按连接匹配编码帧与原始末包传输事件。
- 周期均值：`apps/web/src/libs/domain/video-stats.ts`。
- 原生帧时间与提交：`crates/desktop-capture/src/receive/`、`presentation/`；共享契约位于 `packages/platform/src/presentation-stats.ts`。
- [WebRTC Stats](https://www.w3.org/TR/webrtc-stats/) 定义首包到解码、抖动缓冲、编码及逐包发送队列。
- [视频帧回调规范](https://wicg.github.io/video-rvfc/) 定义末包接收、提交合成和预计显示时间。
- [WebRTC Encoded Transform](https://www.w3.org/TR/webrtc-encoded-transform/) 定义编码回调的采集时间元数据，用于浏览器 C → P 计时。

调整画质或编解码器时，结合[编码与 GPU 显示](codecs.md#quality)观察各阶段和总体耗时的变化。
